ONE ENGINE / TWO OPERATING MODES

Run one workflow. Or evaluate it as a grid.

A production workflow and an experiment use the same compiler, jobs, attempts, ledger, and policy controls. Fix the factors and the engine runs one cell. Vary them and it runs a controlled grid. Compare the cells, adapt one variable, and the grid becomes a campaign.

WORKFLOW COMPILER / OPERATING MODES

One execution engine,
from cell to campaign.

A fixed assignment produces one workflow cell. Factor levels produce a grid of cells. Both compile into the same jobs and attempts; only the grid adds cross-arm comparison and adaptation.

G × N × M = instrumented evidence surface
G

Grid breadth: the product of active factor levels, such as model × condition × policy × seed.

N

Workflow depth: linked sessions or stages whose accumulated effects must remain visible.

M

Measurement breadth: independent angles applied to each stage, from correctness to cost and recovery.

G×N×M

Adding a factor level multiplies cells; adding a stage or measurement expands every cell.

  1. 1 / SELECT OR VARYFixed factors produce one cell. Varied factors produce G cells without changing the workflow executor.
  2. 2 / EXECUTE AND RECORDEvery cell becomes jobs and attempts that emit append-only events to the same ledger.
  3. 3 / MEASURE AND CONTROLMeasurement rules produce information. Admissible control rules consume it inside the running workflow.
  4. 4 / COMPARE AND ADAPTGrids compare arms. Campaigns alter one factor and run the next evidence-acquisition pass.
FIELD MAP / EIGHT PLANES

Eight planes, one dependency direction.

The instrument is modular but not flat: the eight package planes form a dependency chain, and control consumes the information the lower planes produce. A plane's state is either instrumented (built and measured), proposed (designed but not run), or decided (a verdict binds it).

TWO MODES / ONE ENGINE

One engine, two operating modes.

A fixed factor assignment produces one cell; a factor cross-product produces G cells. Both converge on the same compile → jobs → attempts → ledger path; only the grid branches to compare and adapt.

AUTONOMY / PROPOSED NOT RUN

A bounded-autonomy envelope.

The human policy boundary sits outside; inside it, declared constraints bound execution and independent verification. Exits are accept, reject/rework, or halt/escalate. Typed checkpoints remain proposed capability, not a run state.

AUTHORITY / HUMAN CONTROL POINTS

Autonomy is bounded,
not human-free.

The agent may operate the workflow, but people define its objective, information requirements, policy, budget, and intervention conditions. Exceptions cross the boundary; routine work does not.

ECONOMIC INPUTS / MEASURED AND MODELED

Separate what is measured,
controlled, and modeled.

Observed cost, outcome, and narration fields come from 227 historical experiment worktrees. Retry rate is a workload input until the attempt ledger measures it directly — it now IS measured (the attempt ledger emits attempt_count, retry_reason, first_pass, and accepted). Modeling parameters (β, EPM) are calibrated to your codebase and provider-pricing horizon; EPM is the selection-time + budget-horizon risk factor, never a session lever. Separating observations, controls, and assumptions is the difference between deterministic budgeting and surprise overruns.

POLICY / PROPOSED CONTROL RULES

Turn observed patterns into
policy arms to test.

These are organized across three provenance tiers. Observed patterns are directly visible in the measurement corpus (227 historical single-session perturbation experiments + 1,067 multi-session story sessions). Derived metrics compute operational quantities from those observations. Modeled extensions project beyond what the experiment directly measures.

Selection and verification

Choose for resilience, explanation overhead, and working outcomes.

1
Grit (Ground-Truth Integrity). Default to models that maintain correctness when given degraded, contradictory, or incomplete instructions. If a model flails under perturbation — producing zero code despite high token output — it has low Grit. Don't use it for unsupervised work. The 10 perturbation operators measure Grit across three perturbation classes: specification corruption, objective mutation, and process perturbation.Concept: Grit (Ground-Truth Integrity) · Lever: C₀
2
The Explanation Tax. Rule 1 selects models that CAN code under degraded input. Rule 2 measures what their resilience COSTS — the flail rate (sessions producing zero code) and narration penalty (overhead on successful sessions). Measured: Claude 11% flail, 8% penalty. DeepSeek 8% flail, 0.0% penalty. For auditable work, the tax is insurance. For routine tasks, it's waste.Concept: Explanation Tax · Lever: ε
5
The First-Pass Rule. Price the accepted outcome, not the prompt. A cheaper model can lose its price advantage through failed verification, retries, and escalation. Derive first-pass quality from attempt number, acceptance, and an independent evaluator; then track it by task type, model, policy, and time window. Do not substitute a narrated report failure rate for an attempt-ledger measurement.Concept: Cost-Per-Accepted-Outcome / First-Pass · Lever: P, retry rate

Compounding economics

Model codebase, energy, and outcome effects before they become architecture.

3
The Snowball Rule. Your codebase grows with every session. Each new line of generated code increases the context window for every future session. This isn't additive – it's quadratic. The more you build, the more each subsequent build costs. Measured: story cost roughly doubles across the five-session arc ($0.16 → $0.34, a 2.13× Snowball). The β term compounds per-session — model the curve before you commit to an architecture. This is a one-way door.Concept: Snowball Effect (N²) · Lever: β, v · Formula: C(N,v) = C₀ × EPM(N) × [N + β·v·N(N−1)/2]
4
The EPM Horizon Rule. Energy costs are the inflation rate of AI compute. Local energy markets – not global averages – determine your long-term prices. A team in Texas (ERCOT grid) faces different EPM growth than one in Frankfurt (ENTSO-E) or Singapore. Find the year your geographic energy costs flip your model selection. Hedge before that point. EPM(t) = 1.00 + r(t−2024) where r depends on your region.Concept: EPM Horizon · Lever: EPM(t)
10
The Outcome Multiplier. The goal isn't to minimize cost – it's to maximize outcomes per dollar. Business Value Index = Total Successful Outcomes / Total AI + Human Cost. A 2× BVI means twice the work for the same cost. A 10× BVI unlocks new business models. ExtensionConcept: Business Value · Lever: BVI

Cache Strategy

Three-layer caching turns the provider economics in your favor. Each layer compounds on the one below.

Layer 1
Gateway Exact-Match. Return cached responses for identical prompts within TTL. Zero token cost. 80–95% savings on repeated prompts.
Layer 2
Provider Prefix Cache. Structure prompts so repeated prefixes hit the provider-side disk cache (DeepSeek, Anthropic). 50–90% savings on input tokens.
Layer 3
Semantic Cache. Match semantically similar prompts with a threshold (embedding cosine similarity ≥ 0.97). 20–60% savings on similar-but-not-identical prompts.
Critical rule: Static content before dynamic content — one dynamic field in the wrong position invalidates the prefix cache. Place system prompts, tool definitions, and static instructions first. Append user input last.
Two-Way Door
Cache Write vs Read. Cache writes preserve context but cost $3.75/Mtok (Anthropic). Cache reads retrieve context at $0.14/Mtok (DeepSeek). Measure your cache hit rate. If under 50%, switch to cache-read mode. If over 80%, cache-write pays for itself. Toggle per workstream.

Simulated Model Routing

Routing here isn't a vendor diagram — it's computed. compute_routing() (in src/instrument/routing.py) reads the experiment corpus, groups sessions by task, and recommends per task a default model (cheapest that clears the correctness threshold) or an escalation model (when a higher-correctness model leads by a meaningful margin). It then simulates single-model vs grit-routed strategies across the whole corpus.

Routing chain: request → task classifier → computed default model → verification gate → escalate-on-margin

Budget Enforcement

Hard caps prevent runaway costs. These tools enforce limits at the gateway layer.

tokencap
Token-based rate limiting per key, per model, per time window. tokencap --key sk-xxx --limit 1M --window 1h --model gpt-5.6
token-limiter
Enforce max tokens per request. Reject before the provider sees it. token-limiter --model gpt-5.6 --max-input 128000 --max-output 16384
agentbudget
Per-agent cost ceilings with automatic escalation to human review. agentbudget --agent coding-agent --daily-cap $5.00 --on-exceed escalate
