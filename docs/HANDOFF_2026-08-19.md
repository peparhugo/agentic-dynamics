## The data-integrity realization (the big one)

A workflow agent auditing the corpus discovered the pre-remediation results were flawed: the
*conditions did not do what they claimed*.

| Condition | Claimed | Reality |
|---|---|---|
| `early_degrade` | session-1 spec degraded (false premise) | **no-op** — mutation silently fell back to clean (P0-7) |
| `bad_seed` | seeded from a genuinely bad codebase | **not a bad seed** |
| single-task summary | meaningful taxonomy | stale `manifold`/`semantic` labels + cross-matched baselines + fabricated 100% pass rate |

**The boundary (per-dimension, not per-cell):**

| Dimension | Old (pre-fix) cells | New (re-runs + perturbed) |
|---|---|---|
| Cost (tokens, $, cache) | ✅ valid — they really ran | ✅ valid |
| Code quality | ✅ valid — they really produced code | ✅ valid |
| **Perturbation** (degrade/flail/recovery/narration) | ❌ no-op | ✅ the only trustable source |

So the canonical corpus is a **large clean baseline + a small real degraded arm** — not the fake
three-condition grid it was. The only trustable perturbation data is: **80 instrumented
`early_degrade` re-runs + `task_manager_*` (7 models) + `process_perturbation_resample_*`
(pro/fable-5/sol)**.

## Bugs fixed this session

1. **`test_knowledge_stream.py` flushed the production KB stream (Redis 6380 DB 2)** per-test and
   was not `external`-marked — so every `pytest tests/ -m "not external"` (run by every workflow's
   test phase) wiped `kb:v1:changes`. Fix: `FINOPS_KB_DB` env override (test uses DB 15) + `external`
   marker.
2. **The 77 contaminated cells registered as `current`** — `feature_queue-steer-2`'s top-level
   `stories/` predates the remediation move, so the story-worktree source read them as plain
   upserts *before* the `contaminated` pass could tombstone them (the `delete` got deduped by
   `knowledge_id`). Fix: `derive_story_pass3` skips contaminated `story_id`s.
3. **`/api/matrix` returned 4.2 MB per 5s poll** (the full retained sample list, up to
   `EVENT_LOG_MAX=500` per cell × 221 cells) — the Control Room felt dead. Fix:
   `RETAINED_SAMPLES_MAX = 60` (aggregates still over the full window; full history on
   `/api/events/<cell_id>`). 4.2 → 2.2 MB. Also fixed `latest_cost` (`cell_costs[0]`, not `[-1]`).
4. **Chroma (chromadb Docker) hangs after ~500 upserts** — heartbeat goes `000` while mem is 2% /
   CPU 0.01%. It's a server-side wedge, not load. Workaround: `docker restart chromadb`, then
   resume the consumer *without* resetting the cursor (claim_pending picks up where it left off).

## Gotchas

- **Running a workflow's `test` phase (`pytest tests/ -m "not external"`) no longer flushes DB 2**,
  but any *explicit* `pytest tests/test_knowledge_stream.py` still uses DB 15 — never DB 2.
- The migration is **idempotent** via the `CHECKPOINT_KEY` hash — re-emitting skips already-known
  `knowledge_id`s. To force a clean re-emit, flush DB 2 first.
- The **Chroma wedge** recurs — if `kb_worker.py --group kb-chroma-v1` shows `retry` + heartbeat
  `000`, `docker restart chromadb` and resume (do not reset the cursor, or it re-hits the wedge).
- opus-5 is the most expensive Claude model and will blow the subscription cap on a big task — use
  it sparingly; DeepSeek is the default for heavy/batch work.
