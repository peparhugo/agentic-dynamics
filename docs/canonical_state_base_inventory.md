# Canonical-State Inventory — Store Map

Inventory phase of `experiments/specs/canonical_state_design.yaml`. Maps every store the
project currently writes or reads, so the design phase can decide what becomes canonical,
what becomes an index/view, and what gets a date spine + supersession. Forensic findings are
cited by number as they appear in the spec's `forensic_findings` block (1–6); see that file
for the full text.

Classification legend (per the spec's requirement):

| Tag | Meaning |
|---|---|
| **IMMUTABLE-SOURCE** | The record's body is written once and never rewritten in place; it is the thing other stores derive from. |
| **DERIVED-VIEW** | Regenerated wholesale (or incrementally) from one or more sources; safe to delete and rebuild. |
| **INDEX** | A lookup/search structure over a source, keyed for retrieval speed, not itself the source of truth. |
| **GRAPH** | A relationship/lineage structure — could carry supersession edges but currently doesn't. |
| **TRANSIENT** | Lives in Redis or memory; bounded, evictable, or destructively consumed (BRPOP); not durable. |
| **SURFACE** | A human/agent-facing view (portal route, CLI) with no storage of its own beyond bookkeeping. |

## Summary by classification

- **IMMUTABLE-SOURCE** (5): story JSONs (#1), quarantined story JSONs (#2), review JSONs (#3), `opencode.db` (#4), KB artifacts (#5) — plus, once the supervisor runs in this checkout, `flags.jsonl` (#18).
- **DERIVED-VIEW** (6): `inventory.json` (#6), `sessions.parquet`/`stories.parquet` (#7), `_results_summary.json` (#8), `_trajectory_aggregate.json` (#9), `data_manifest.json` (#10, thin), `data.js` (#11).
- **INDEX** (2): Chroma (#13), `data_manifest.json` doubles as a thin index (#10).
- **GRAPH** (1): Neo4j (#12).
- **TRANSIENT** (7): KB Redis Streams plane (#14), story-job queue (#15), `monitor.py` (#16), `LivePublisher` pub/sub (#17), supervisor monitor pointer (#19), supervisor Redis hot path (#20), Control Room's own ephemeral bookkeeping (part of #21).
- **SURFACE** (1): `admin/server.py` / Control Room (#21) — confirmed to hold no canonical storage of its own.
- **Schema-only, unimplemented** (1): the conceptual ledger (#22) — declared in `LEDGER_FIELDS` but never persisted as a single per-attempt store.

No store currently combines a stable identity key, a full date spine (`observed_at`/`valid_from`/`valid_to`/`supersedes`), and canonical status in one place. The closest is the KB artifact layer (#5, via `KnowledgeRecord`), but its date-spine fields are dropped by both derived indexes (#12, #13) that sit downstream of it, and it does not yet cover `record_type`s outside `finding/code/report/policy` — story, review, ledger, and manifest records are not first-class KB citizens today.
