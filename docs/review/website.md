# Website review — structure + content

Phase 3 (website) of `repo_review_fable`. Scope: `firebase/public/` (8 pages + `data.js` +
`app.js` + `base.css`) and the two generators (`scripts/build_data.py`,
`scripts/generate_manifest.py`). Recommendations are split into **structural** (IA / rendering /
the `data.js` → UI seam) and **content** (stale numbers/claims) sections, each with a concrete
location. All `file:line` re-read at commit `1baff2a6f`.

---

## 1. How the site works today

- `data.js` is the **only** dynamic file (`firebase/CONTEXT.md:38`), regenerated by
  `build_data.py`. It carries two distinct corpora under one `window.DYNAMICS_DATA`:
  - `models` — the **story** pipeline (from `stories.parquet`, via `compute_story_models`,
    `build_data.py:868-958`), ids `deepseek-v4-flash`, `gpt-5.6-luna`, `deepseek-v4-pro`,
    `gpt-5.6-terra`, `claude-haiku-4-5`, `gpt-5.6-sol`, `claude-sonnet-5` (`data.js:38-248`).
  - `perturbation_models` — the **historical** single-session perturbation corpus
    (`compute_model_data`, `build_data.py:180-335`), ids `gpt-5-nano` … `anthropic/claude-fable-5`
    (`data.js:285-963`).
- `app.js` injects values into any element with `[data-stat]` / `[data-stat-fmt]` via a
  hand-written `statMap` (`app.js:38-63`), and fills `tr[data-anal-model]` rows from
  `D.analysis.models` (`app.js:89-108`).
- The other 7 HTML pages are hand-authored static prose that is **not** regenerated, and several
  embed large inline `<script>` blocks of hard-coded model/chart data.

The tension that drives every finding below: `build_data.py` switched `D.models` from the
perturbation corpus to the story corpus (`build_data.py:981-988`), but `app.js` and large parts of
the static HTML were written against the *perturbation* shape and were never re-pointed.

## 2. Structural recommendations (IA / rendering / the data.js → UI seam)

### S1 — Split `evidence.html` into two pages (current story evidence vs. perturbation archive)

- **Location:** `firebase/public/evidence.html` — 1,739 lines / 155 KB, the largest page. It
  mixes **two different corpora**: the current story pipeline (top, "Verification frontier",
  `evidence.html:106-209`) and the historical perturbation archive (bottom, "Open the perturbation
  archive", `evidence.html:297` onward), joined only by a "return to current evidence ↑" bridge
  (`evidence.html:292-302`). It also embeds **11 inline `<script>` blocks** (`evidence.html:249,
  545, 596, 640, 669, 699, 729, 759, 790, 962, 966, 1582, 1631`) carrying hand-written chart data.
- **Recommendation:** split into `evidence.html` (story pipeline — the live, regenerated data) and
  `evidence/perturbation-archive.html` (the frozen historical corpus, clearly stamped
  "historical, single-session, superseded by the story instrument"). Move the inline chart data
  out of `<script>` into `data.js` (see S2). This is the highest-leverage structural change: it
  removes the single biggest source of stale-content drift and makes the "which corpus does this
  number belong to" question answerable by URL instead of by scrolling past a prose disclaimer.

### S2 — Remove the hard-coded fallback/data arrays; make `data.js` the single source of truth

- **Location:**
  - `firebase/public/framework.html:919` — the calculator's fallback `models` array is hard-coded
    and **stale** (`{n:'Claude Fable 5',c:1.0847,p:0.99}` and `{n:'DeepSeek v4 Pro',c:0.0158}`),
    used whenever `window.DYNAMICS_DATA.calculator` is absent.
  - `firebase/public/evidence.html:552, 606, 679, 709, 733, 762, 1100-1478` — inline `<script>`
    model arrays (session counts, entropy, coupling, drift, grit, color maps) that duplicate and
    contradict `data.js`.
- **Recommendation:** delete the fallbacks and the inline arrays; `build_data.py` should emit a
  `perturbation` sub-object that the archive page reads. A page with no data should render
  "data not generated yet — run `scripts/build_data.py`", not silently show a 2025-vintage
  fallback. This kills the two-source-of-truth problem that produced the `fable-5`/`sonnet-5`
  split (see C1).

### S3 — Fix the `data.js` → UI seam: `statMap` is wired to the wrong corpus and `findModel` is ambiguous

- **Location:** `firebase/public/app.js:28-63`. `findModel` does substring matching
  (`ms[mi].id.indexOf(idPart) >= 0`) over `D.models` — which is now the **story** corpus ordered
  by `avg_cost` (`data.js:38-248`). Consequences:
  - `findModel(D,'deepseek')` → `"deepseek/deepseek-v4-flash"` (first hit, `data.js:38`), so
    `deepseek_cost_per` reports **Flash's** cost, not Pro's.
  - `findModel(D,'claude')` → `"anthropic/claude-haiku-4-5"` (`data.js:178`), so `claude_cost_per`,
    `claude_narration`, `claude_penalty` report **Haiku**, not Sonnet 5.
  - `findModel(D,'gpt-5.6')` → `"openai/gpt-5.6-luna"` (`data.js:73`), so `gpt56_cost_per` reports
    Luna.
  - `narration_rate` / `avg_narration_penalty` are `None` in the story models
    (`build_data.py:950-951` — deliberately "not measured for the story corpus"), so
    `claude_narration`/`deepseek_narration`/`claude_penalty`/`deepseek_penalty` render as
    `"0%"` via `(m.narration_rate || 0)`.
- **Concrete regression (visible):** `glossary.html:45` hard-codes "Claude: 11% flail, 8.0%
  penalty. DeepSeek: 8% flail, 0.0% penalty [M]", but `app.js` overwrites the spans with `"0%"` for
  all four. `databricks.html:102` hard-codes "$0.02 vs $1.08 — 69×", but the spans are overwritten
  with Flash/Haiku costs, so the "69×" sentence and the injected numbers disagree.
- **Recommendation:** key `statMap` entries by an **explicit model id** (or by provider with a
  declared default), and add a `cost_per`/`flail` block to the story models sourced from the
  perturbation corpus where they are actually measured. Never resolve by `indexOf`. Have
  `compute_story_models` emit `flail_rate`/`narration_rate` as `null` (not `0`) and make `app.js`
  render `null` as an em-dash instead of `0%`.

### S4 — Slim and version the generated `data.js`

- **Location:** `firebase/public/data.js` (183 KB, 6,868 lines) is emitted with
  `json.dumps(clean_data, indent=2)` (`build_data.py:1160`). The `indent=2` roughly doubles the
  bytes for no reader benefit, and the `_provenance` maps are duplicated inline per model
  (`build_data.py:314-332`).
- **Recommendation:** emit `indent=None` (or `separators=(',',':')`); add a `schema_version` field
  to `_meta` (alongside `generated_at`, `data.js` `_meta` currently has neither version nor a
  note); keep the pretty-printed variant only as a `data.pretty.json` artifact for humans. This
  also makes the dual-host deploy (`firebase/CONTEXT.md:43-47`) cheaper and drift-detectable.

### S5 — Hoist the "cost captured" denominator into every cost display

- **Location:** the parquet already records which cells have a captured cost —
  `compute_story_models` computes `cost_cells` and `avg(total_cost) FILTER (WHERE cost_captured)`
  (`build_data.py:900-901`, `:933`) — but the UI shows a bare `$X/session` with no "n of N".
  `evidence.html:142` is the only place this caveat surfaces, in prose.
- **Recommendation:** render cost averages as `$4.58 (n=23/31)` — i.e. thread `cost_cells` /
  `cells` into the table rows and the model cards. This is the single change that makes the
  subscription-vs-metered distinction legible instead of buried in a footnote.

### S6 — Shared header/nav is duplicated across 8 files (lower priority)

- **Location:** each of the 8 HTML pages re-declares the same nav/theme bootstrap; `app.js` then
  synthesizes a floating ToC client-side (`app.js:112-167`) from headings. This is acceptable
  under the no-bundler constraint (`firebase/CONTEXT.md`), but the duplication is why C1/C3 drift
  (a rename or a corpus count must be edited in 5+ places). A one-time `<script>`/SSI-free
  `nav.js` that injects the shared nav would be a small, constraint-compatible win.

## 3. Content corrections (stale numbers / claims)

### C1 — `fable-5` → `sonnet-5` labeling is split, not migrated

- **Location:** the historical perturbation archive in `evidence.html` still says **"Claude
  Fable 5"** throughout (`evidence.html:349, 371, 428, 445, 469, 481, 552, 591, 679, 709, 733, 762,
  852, 871, 896, 932, 1100, 1112, 1138, 1406, 1478`), while the story-pipeline pages say
  **"Claude Sonnet 5"** (`framework.html:832, 870, 882, 890`, `story.html:91, 123, 141, 181`,
  `index.html:152, 180`, `evidence.html:106-209`). `data.js` carries **both**:
  `anthropic/claude-sonnet-5` (`data.js:248`) and `anthropic/claude-fable-5` (`data.js:963`).
- **Root cause in the generator:** `MODEL_DISPLAY_ORDER` still lists `"anthropic/claude-fable-5"`
  (`build_data.py:43`), and `_short_model_label` still maps `"claude-fable-5" → "Claude Fable 5"`
  (`build_data.py:728`) alongside `"claude-sonnet-5" → "Claude Sonnet 5"` (`:726`).
- **Recommendation:** decide the fact and make it one source. If `claude-fable-5` is the *same*
  model under a renamed alias (per the commit "Fix claude-fable-5 model resolution … not aliased
  to sonnet-5"), then the perturbation corpus's model id should be normalized to `claude-sonnet-5`
  in `MODEL_DISPLAY_ORDER`/`_short_model_label` and `evidence.html` globally. If it is a genuinely
  *distinct, older* model, keep "Fable 5" **only** inside the clearly-stamped historical archive
  (S1) and add one sentence saying "the perturbation archive used Claude Fable 5; the story corpus
  used Claude Sonnet 5." Either way, the current silent coexistence of two names for what readers
  assume is one model is the site's worst credibility problem.

### C2 — DeepSeek pricing is stale; peak/off-peak is undocumented

- **Location:** `story.html:123` claims "Claude Sonnet 5's tokens cost 11.5× more per unit
  (**$10.00 vs $0.87** per 1M output tokens)". The DeepSeek output rate was rebased to
  **$1.98/M (off-peak), 2× at peak** (`src/instrument/efficiency.py:40-45`), so "$0.87" is the
  pre-rebase price and "11.5×" is wrong (current off-peak gap is ≈5.1×). The
  peak/off-peak 2× swing (01:00–04:00 & 06:00–10:00 UTC, `efficiency.py:44`) appears **nowhere** on
  the site.
- **Location:** `framework.html:832` (Sonnet pricing table `$2.00 / $0.20 / $10.00`) is correct,
  but `framework.html:882` ("Sonnet vs DeepSeek gap 33× ($4.58 vs $0.14)") mixes a per-session
  average with a per-token rate and inherits the stale DeepSeek basis.
- **Recommendation:** add a "pricing snapshot" block (provider → input/output/cache rates, with
  peak/off-peak note for DeepSeek) to `framework.html`'s provider playbook, regenerate the
  multiplier claims from `efficiency.PROVIDER_PRICING`, and fix `story.html:123` to `$1.98` (or
  `$0.87–$3.96` showing the off-peak/peak range).

### C3 — Corpus shrinkage is not reflected in the static prose

- **Location:** the generator now reports **772 story sessions / 156 stories (141 unique) /
  344 game reports / $219.51** (`data.js` summary, lines ~5-15), but the static HTML still
  claims the pre-shrink numbers:
  - `framework.html:6` meta: "1,097 story sessions and 227 perturbation experiments" (1,097 is
    stale).
  - `framework.html:784`: "227 single-session perturbation experiments + **1,097** multi-session
    story sessions".
  - `methodology.html:60`: "249 sessions" (neither 227 nor 772 — an orphaned number).
  - `evidence.html:292`: "the **221-story** corpus" vs `data.js` `stories_total: 156`.
  - `generate_manifest.py:241-244` `known_limitations` still says "116 of 227 sessions use
    heuristic correctness" and "DeepSeek 119, Claude 44, GPT variants 6-18 each" — these are the
    perturbation-corpus counts and are not marked as historical.
  - `accelerator.html:182, 278`, `databricks.html:6, 59, 87, 134, 191` all repeat "227 controlled
    experiments" as if it were the current corpus.
- **Recommendation:** introduce a single canonical count block — `data.js` `summary` should carry
  a `corpus` object with `{perturbation_sessions: 227, story_sessions: <live>, stories: <live>,
  generated_at}` — and replace every hard-coded "227 / 1,097 / 249 / 221" with a `data-stat`
  binding to it. Until then, at minimum prefix every historical figure with "historical"
  (the archive sections already do; the framework/accelerator/databricks pages do not).

### C4 — `game_reports: 344` vs the "224 game reports" claim

- **Location:** `evidence.html:292` says the perturbation precursor produced "224 game reports";
  `data.js` `summary.game_reports` is now **344** (the count of `.md` files in `reports/` per
  `build_data.py:135-139`). The 344 conflates perturbation reports with story-era reports. If the
  two corpora are to stay distinct (S1), the "reports" stat must be split per corpus rather than
  one global count.

## 4. Provenance model for the new cost regimes

The current tags (`[M]` measured, `[C]` computed, `[H]` heuristic, `[P]` policy, `[X]` external —
`firebase/CONTEXT.md:38`, `data.js` `_meta.provenance_note`) describe **how a number was produced**,
but not **which pricing regime the dollar figure reflects**. With the DeepSeek peak/off-peak
rebase and the Claude subscription-vs-metered split, a bare `[M]` on a cost figure is now
misleading. Concrete proposal:

1. **Add a cost-basis dimension, not a new tag letter.** Keep `[M]/[C]/[H]/[X]` for derivation
   method, and add a parallel `cost_basis` field with values
   `metered-api` | `metered-api-peak` | `metered-api-off-peak` | `subscription-unmetered` |
   `excluded`. The data already exists to fill it: `compute_story_models` computes `cost_cells`
   and filters `WHERE cost_captured` (`build_data.py:900-901, :933`); the parquet `cost_captured`
   column is the subscription-vs-metered discriminator.
2. **Never show a cost that mixes bases without a denominator.** Every cost average should render
   as `$4.58 (n=23/31 metered)` (S5). `evidence.html:142` is the correct precedent — promote it
   from footnote to table column.
3. **Tag the DeepSeek energy/pricing figures with the off-peak basis.** `efficiency.PROVIDER_PRICING`
   is off-peak with a documented 2× peak (`efficiency.py:44`); the site should render
   `$1.98/M (off-peak) · $3.96/M (peak)` rather than a single number, and `external_sources` in
   `data.js` (`build_data.py:1129-1137`) should carry the peak/off-peak window alongside the rate.
4. **Drop the `[M]` label on subscription-cli flail/cost claims** in `glossary.html:45`: those are
   `[M]` only for the metered subset; for the subscription cells they are either `[H]` (imputed) or
   `N/A`. The current `[M]` over-claims what was actually metered.

## 5. Priority ordering

| # | Change | Type | Effort | Impact |
|---|---|---|---|---|
| 1 | S3 — rewire `statMap`/`findModel` to explicit ids; render `null` as "—" | structural | low | high (fixes visible wrong numbers) |
| 2 | C1 — resolve fable-5/sonnet-5 in `MODEL_DISPLAY_ORDER` + `_short_model_label` + `evidence.html` | content | medium | high (credibility) |
| 3 | C2 — regenerate DeepSeek pricing claims + add peak/off-peak block | content | low | high |
| 4 | S1 + S2 — split `evidence.html`; delete hard-coded arrays/fallbacks | structural | high | high (drift) |
| 5 | C3/C4 — canonical corpus counts via `data-stat`; mark historical figures | content | medium | medium-high |
| 6 | S4 + S5 + S6 — slim `data.js`, surface `cost_cells`, shared nav | structural | low-medium | medium |

The single underlying fix is **one source of truth**: `data.js` should own every number and every
model label, and the static pages should only ever *bind* to it. The stale-content items (C1–C4)
are symptoms of the site's structure — the hand-authored fallbacks and inline chart data — having
diverged from the generator.
