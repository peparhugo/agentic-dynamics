# Retrieval Decisions - 2026-09-01

**Status: ACCEPTED.** This record ratifies the D1, D2, and D3 decisions reconstructed in
`2026-09-01_retrieval_agenda.md`. It is a policy and design decision record. It does not claim
that the pattern projection or the live activation gate has already been implemented.

## 1. Decision Summary

| Decision | Ruling | Consequence |
|---|---|---|
| D1 - agent access | **B: agents may retrieve patterns, never raw facts** | Agents receive compressed, uncertainty-carrying, citable experience. Raw facts remain addressable control inputs only. |
| D2 - pattern projection | **Yes: expose I9 patterns as retrieval-facing knowledge records carrying `PatternPayload`** | The projection is a read-only view of a reducer-minted pattern fact, not a second fact-store row or an LLM summary. |
| D3 - cross-repository isolation | **Accept boundary-only isolation for now** | `repository_id` and cell scoping remain the boundary. The missing explicit ACL machinery is an accepted risk with a multi-domain escalation trigger. |

## 2. Audit Basis

The ruling follows the surviving record rather than the lost session notes:

- The agenda records the matrix recommendation as D1 Option B and D2's proposed
  `source_type="pattern"` knowledge-record shape (`docs/architecture/current/2026-09-01_retrieval_agenda.md:62-83`).
- `PatternPayload` is already a frozen typed payload containing the claim, population, conditions,
  support, uncertainty, validity window, and source experiment
  (`src/agentic_dynamics/control/facts.py:222-272`). The `pattern/v1` reducer is the deterministic
  producer, so the approved projection has a measured source rather than an LLM-authored source.
- The current knowledge vocabulary registers `fact` but not `pattern`
  (`src/agentic_dynamics/knowledge/knowledge.py:121-160`). The agenda audit found no
  retrieval-facing pattern projection and no pattern candidate surface in `retrieve()`
  (`docs/architecture/current/2026-09-01_retrieval_agenda.md:121-128`). D2 is therefore an
  approved next implementation, not an assertion about the current tree.
- The existing retrieval path has dense and lexical ranked legs, RRF fusion, bounded graph
  expansion, and named fallback modes. `RetrievalAttempt` is recorded before construction, while
  the augmentation seam is read-only and failure-tolerant
  (`src/agentic_dynamics/knowledge/retrieval.py:1-20,849-872`,
  `src/agentic_dynamics/knowledge/augment.py:1-19,119-125`).
- Slice 3 is historical operational evidence that both stores were available, not proof of
  meaningful rank overlap: its query reported `dense-only: 1`, `lexical-only: 8`, and
  `fused(both legs): 0` (`docs/fleet/06_slice3_neo4j_rrf_log.md:70-84`). The activation phase must
  measure leg contribution and fallback distribution again instead of treating the historical
  `fallback_mode="full"` as sufficient product proof.
- Slice 4's deterministic guard result and live-service checks are also historical evidence. The
  agenda correctly keeps current index health, stream catch-up, and one accepted augmented phase
  as explicit activation criteria (`docs/architecture/current/2026-09-01_retrieval_agenda.md:133-147,168-182`).

The audit found no reason to reject the matrix recommendation. It did find a reason to keep the
implementation and activation claims separate: the typed fact payload exists, but the retrieval
projection does not.

## 3. D1 - Agents Retrieve Patterns, Never Raw Facts

**Decision: Option B.** An agent session may receive a pattern when RAG is enabled, but it may not
retrieve raw fact rows, including attempt-level rows or individual predicate values. A pattern is
the permitted transfer object because it is experience compressed with its uncertainty attached;
a raw fact is control truth whose use must remain address-based and contract-bounded.

This preserves the intended asymmetry:

- Agents read what the system learned: narrative knowledge records and, after D2 is implemented,
  reducer-minted patterns.
- Controllers consume what the system has measured: raw facts selected by declared
  `requires_facts` contracts.
- No prompt, candidate, evidence card, or constructor input may use the fact-store row as a
  substitute for the pattern projection.

Option A would preserve the strict status quo but leave measured experience unavailable to agent
sessions. Option C would collapse the two-channel rule and put stale or unsorted control truth in a
narrative prompt. Neither is accepted.

## 4. D2 - Retrieval-Facing Pattern Projection

**Decision: Yes.** Implement a `source_type="pattern"` knowledge record whose structured body
carries the canonical `PatternPayload`. The record is a read-only retrieval view of one pattern
fact. It is not a duplicate canonical fact and is not a prose summary generated by an LLM.

The implementation contract is:

- The pattern reducer is the sole minting authority. Support and uncertainty must be derived from
  real measured inputs; an LLM may propose an idea only as an uncitable advisory artifact.
- The projection is deterministic, content-addressed, scoped, and idempotent. Re-emitting an
  unchanged pattern is a byte-identical no-op, and its identity is derived from the pattern fact's
  identity rather than creating a second semantic fact.
- The projection retains the `PatternPayload`, the source experiment reference, repository scope,
  cell scope, and enough lineage to cite the underlying evidence.
- Supersession of the underlying pattern fact supersedes the projection. A projection may not
  outlive its source fact.
- Raw `fact` records remain absent from both retrieval indexes. The projection is the only path by
  which an I9 pattern becomes agent-visible.

### Candidate and Evidence Surfaces

The projection joins the candidate pool as a third **candidate surface** alongside ordinary
knowledge records. It does not create a third ranked transport leg or replace the existing
dense-plus-lexical two-leg RRF. Pattern candidates are therefore subject to the existing
deduplication, scoring, selection, citation, and fallback instrumentation, with the projection
surface explicitly identifiable in the candidate/evidence representation.

`retrieve()` and `build_evidence_cards()` must preserve the following boundaries when the next
implementation phase lands:

- A requested `repository_id` remains a hard pre-filter, with `cell_scope`/`acl_scope` applied in
  the same way as for ordinary knowledge records. Empty candidate scope remains legacy/unknown;
  it is not reinterpreted as global.
- Pattern support and uncertainty remain visible through the candidate and citation path. Equal
  relevance may use uncertainty as a documented pattern-specific ranking signal, but that signal
  must remain distinguishable from measured support and from the [H] retrieval-weight constants.
- Projection-off behavior remains byte-identical to today's retrieval behavior. A corpus with no
  projection must not gain an implicit fact path, and a fact row must never appear as a candidate.
- Evidence cards remain deterministic and citable. They must not fabricate support or uncertainty,
  and they must preserve the distinction between a reducer-minted derived pattern and an advisory
  narrative proposal.

## 5. Two-Channel and C5 Consequences

The two-channel rule is **unchanged for facts**. D1 does not authorize fact retrieval, and D2 does
not move patterns out of the fact plane. The projection is a separate read-only knowledge surface
whose content is derived from an already-authorized pattern fact.

The projection's epistemic status is **DERIVED, evidence class `[C]`**, when it is minted by the
deterministic reducer from real evidence. It is not `ADVISORY` merely because an agent can retrieve
it. Consequently:

- A valid pattern projection is citable as a derived knowledge record, with its source experiment
  and lineage attached.
- `ADVISORY` remains structurally uncitable under C5. Reviews, supervisor judgments, and LLM
  pattern proposals do not become citable by being placed near a pattern candidate.
- A pattern with missing, fabricated, or unverified support cannot be promoted to the `[C]`
  projection. It remains absent or advisory according to the producing contract.
- Controllers still consume canonical facts through declared addresses and compiler-validated
  requirements, never by searching the pattern projection.

## 6. D3 - Boundary-Only Isolation Accepted

**Decision: accept the repository boundary today and record the risk.** `repository_id`, private
defaults, and the existing cell-scope rules are the current isolation mechanism. No new cross-repo
ACL machinery is required before the system hosts more than one domain in a shared store.

This is an explicit accepted limitation, not a claim that repository separation is a complete ACL
implementation. The risk is that a copied or mis-scoped record could cross the boundary because
the machinery does not independently enforce a cross-repository visibility policy. The escalation
trigger is any second domain in the same retrieval or registry store, or any shared-facing surface
that combines domains. Before that trigger, the projection must still use the existing
`repository_id` and cell-scope pre-filters; D3 does not weaken those checks.

## 7. Deferred Activation Gate

This decision record approves the direction but does not mark retrieval activated. The subsequent
projection and activation phases must record all of the following:

1. A deterministic projection test showing patterns and ordinary knowledge records can coexist in
   the candidate pool, while raw facts remain absent and projection-off behavior is unchanged.
2. An uncertainty-aware ranking test that preserves support, uncertainty, source experiment, and
   citation data without treating an advisory proposal as derived evidence.
3. A retrieval census over real queries reporting dense-only, lexical-only, and both-leg
   contributions, the `fallback_mode` distribution, and the active `WEIGHTS_VERSION`.
4. A live index-health and stream-catch-up check for the Neo4j full-text index and `kb-neo4j-v1`.
5. One workflow phase with `rag_augment` enabled, recording retrieval and constructor outcomes and
   either accepting the augmented prompt or recording a named non-blocking fallback.

Until those measurements exist, the historical Slice 3 product-gate claim remains historical and
the augment seam remains an opt-in capability rather than a newly measured product.

## LOG

**PASS.** The audit found no reason to depart from the matrix recommendation. D1 is ratified as
Option B: agents may retrieve compressed, uncertainty-carrying, citable patterns and never raw
facts. D2 is ratified: I9 patterns receive a deterministic, scoped, idempotent retrieval-facing
knowledge-record projection carrying `PatternPayload`; the projection joins the candidate pool as a
third candidate surface while the underlying RRF remains two-legged. The two-channel rule is
unchanged for facts. C5 remains in force: reducer-minted patterns are citable DERIVED `[C]`
records, while `ADVISORY` remains uncitable. D3 accepts boundary-only isolation and records the
cross-domain ACL risk. Projection implementation and measured RRF/augment activation remain the
next phases, not claims of this record.
