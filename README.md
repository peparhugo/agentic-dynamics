# WebSocket Notification Server

An asyncio notification server built directly on the `websockets` library.

## Run

```bash
python3 -m pip install -r requirements.txt
python3 app.py --host 127.0.0.1 --port 8765
```

Connect a WebSocket client to `ws://127.0.0.1:8765`. On connection, the server
sends a `system` message whose payload contains the assigned `client_id`.

Every client message must use this envelope:

```json
{"type":"broadcast","payload":{"text":"hello"},"timestamp":"2026-08-13T12:00:00Z"}
```

- `broadcast` sends the payload to every connected client, including its sender.
- `direct` sends to the client named by `payload.client_id`; the delivered payload
  excludes `client_id` and includes the sender's `sender_id`.
- `system` is reserved for connection notices and errors generated by the server.
- The server replaces client timestamps with its own UTC timestamp.

Messages may include a non-empty `channel` field. Channel messages are delivered
only to clients subscribed to that channel. Messages without `channel` retain the
original behavior.

Subscribe or unsubscribe at any time with an empty payload:

```json
{"type":"subscribe","channel":"alerts","payload":{},"timestamp":"2026-08-13T12:00:00Z"}
```

```json
{"type":"unsubscribe","channel":"alerts","payload":{},"timestamp":"2026-08-13T12:00:00Z"}
```

A client may subscribe to multiple channels. Subscriptions are removed when the
client disconnects.

`GET /health` returns `{"connected_clients": N}`.

`GET /channels` returns active channels and their subscriber counts. `GET
/channels/{name}/subscribers` returns the channel name and its subscriber IDs;
an inactive channel has an empty subscriber list.
