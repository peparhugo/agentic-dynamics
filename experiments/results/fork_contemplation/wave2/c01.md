## Entry claim

**The controller's five findings are reproducible by a differential harness, and that harness is cheaper than the review it replaced.** — Stated to be attacked: I will design the harness concretely, show exactly three of the five are recoverable differentially, and show the other two are *structurally* outside any differential against the runtime.

## Two lenses (kept in conflict until the end)

**Lens A — differential metrology.** The only trustworthy statement about a controller that mirrors an authority is a diff against that authority's own output. Under this lens a "test" that asserts our formula against a fixture we authored is a tautology, and the harness is worth exactly its *kill rate* on re-injected bugs. Discriminating test: re-inject each historical bug; the harness must go red. If it does not, delete the test.

**Lens B — specification-first safety engineering.** The most dangerous failures in this arc had **no authority output to diff**: "a policy cap must not masquerade as native compaction" and "corrupt state must degrade, not crash" are *contracts*, not observables. Under this lens the right-hand side of those checks is a human-stated property, and a purely differential harness is blind to them by construction.

They disagree on the conclusion: A says "if it isn't a diff, it's prose"; B says "the review's highest-value findings are precisely the non-differential ones." Both are right about their own domain — that split is the result.

## What I add beyond wave-1 c17 (Q-B)

c17 named the standing differential interrogator and asked that its recall be scored against the five. What it did **not** do, and what I add: (1) an explicit **oracle taxonomy** per finding, proving 2/5 have no runtime oracle — this falsifies c17's own thesis ("the only durable output … can be written as such a diff"); (2) the **mutation-kill scoring** that makes "recall" measurable rather than asserted; (3) the **capture/CI-vs-host split** required because CI has no `opencode` binary; (4) the two worthless-pass modes. c17 supplied the question; this supplies the detector and its bound.

## The executable artifact

### Layout, integration, commands

```
scripts/capacity_differential.py            # oracle capture + live diff driver (host)
tests/test_capacity_differential.py          # the differential suite (deterministic)
tests/fixtures/capacity_oracle/
    manifest.json                            # runtime_version, binary_sha256, config sha256s, captured_at

    reference_expr.json                      # extracted constants + expression (binary-sha-pinned)
```

- **CI job:** the existing `test-shard` lane runs the *pinned-capture* tests (`pytest tests/test_capacity_differential.py -q -p no:cacheprovider`). Do **not** create a new required check — promoting one is the controller's P0.
- **Host standing check:** `python3 scripts/capacity_differential.py --oracle live --json`, folded into the activation checklist ("verify the running services use it") because CI has neither the binary nor auth.
- **Refresh rule:** `--capture` regenerates the pinned files; if `manifest.runtime_version` ≠ the installed binary's version, the suite **fails loudly**, never skips (the reviewed session's seven socket-dependent tests proved skip-passes are real).

### Oracle classes

```
O1 LIVE       opencode models <p> --verbose under a config variant (host only)
O2 PIN        version+binary-sha-pinned capture of O1 + extracted constants (CI)
O3 TRANSCRIBE a minimal transcription of the runtime's overflow expression and its
              run-loop guard `he.summary !== true` (used only where no output exists)
O4 CONTRACT   no authority output: a human-stated property held by mutation/metamorphic/
              robustness checks
```

### The reference transcription (deliberately tiny, independent of production)

```python
# Transcribed from the installed binary (sha pinned in reference_expr.json).
# DO NOT "improve" this by hand: if the runtime changes, refresh the capture.
def ref_measure(tokens: dict) -> int | None:
    """opencode's overflow measure: `tokens.total || input + output + cache.read + cache.write`.
    The deliberate absence of `reasoning` here is finding F3: adding it made 955K read 975K."""
    total = tokens.get("total")
    if isinstance(total, (int, float)) and total > 0:
        return int(total)
    cache = tokens.get("cache") or {}
    vals = [tokens.get("input") or 0, tokens.get("output") or 0,
            cache.get("read") or 0, cache.get("write") or 0]
    return sum(int(v) for v in vals) if any(v > 0 for v in vals) else None

def ref_should_compact(seq) -> bool:
    """The runtime run-loop's single decision point, extracted as a guard (finding F1):
       last_assistant.summary is not True  AND  measure >= usable.
    A completed summary makes the runtime SKIP the check and continue; therefore a verdict
    that blocks on the stale pre-compaction reading is a false negative."""
    last = next((m for m in reversed(seq) if m["role"] == "assistant"), None)
    if last is None or last.get("summary") is True:
        return False
    return ref_measure(last.get("tokens")) is not None and \
           ref_measure(last["tokens"]) >= ref_usable(last["limit"])
```

### Scoring

```
recall_R   = findings whose re-injected mutation dies / 5          → gate 5/5
holdout_H  = mutants OUTSIDE the five that die / 5                  → gate 5/5
fp_F       = failures on clean tree + benign variants (unknown
             provider → UNJUDGED; compaction.auto=false → CLOSE)   → gate 0
pass iff R == 1 ∧ H == 1 ∧ F == 0 and the oracle was actually consulted
cost       live path ≈ 2 × runtime CLI (~2 s) per run; CI path = pinned capture, no network
```

"Consulted" is load-bearing: a case that would pass with the oracle absent is not allowed to skip green (see below). The success metric is **mutants killed per run**, not tests written — per KB `7948b8ace287e881`, an arm that doesn't move an accepted outcome is dead weight.

### The two ways it passes while worthless

1. **Self-referential or absent oracle.** The right-hand side is the production port (or a fixture authored from the same model), so both sides move together and the diff is vacuous; the degenerate case is *skip-on-absent-binary*, which reports green while testing nothing (exactly the seven unrun socket tests). Guard: the reference lives in the test and is binary-sha-pinned; the host profile **fails** when O1 is unavailable; the capture must be refreshed on version mismatch.
2. **Known-bug overfit.** The cases are the five historical reproductions, so the harness has no power against the *next* divergence — a straight replay of the regressions I already wrote. Guard: property-based generators (seeded config permutations, boundary ±1-token, a summary carrying `error`, two project config files) plus hold-out mutants; and the benign-variant FP set so it cannot win by flagging everything.

## Can it recover the five? (the bound)

- **F2, F3 — yes, genuinely differential**, against the runtime's own output (O1/O2) and its extracted expression (O3). Cheap, and independent of the fixture author.
- **F1 — only model-vs-model.** No runtime output exposes the compaction decision; on this host the live oracle is *absent* (no completed compactions existed to sample), so F1 is recoverable against the transcribed run-loop guard, or against a live trace only if the harness is allowed to *induce* a compaction (a real session driven to the boundary — bounded dollars, not free). One of the five is therefore weaker than the other two.
- **F4, F5 — no.** No authority output exists to diff. The harness can hold the line once a human states the property; it cannot discover that the property should exist.

**What only human attention can do:** (a) name the contract where there is no authority — "a policy cap is not an engine", "corrupt state degrades"; (b) *imagine the input classes* (the controller thought of `OPENCODE_CONFIG` precedence, partial-field overrides, trailing commas; generators only permute what they are told is possible); (c) price the false-positive cost and decide the gate trade. **Bound:** one human pass per *new oracle class or new failure semantics*, not per regression; thereafter recurrence of the named classes is bounded to zero at milliseconds per run. The harness is recurrence-insurance, not a review replacement — c17's "everything durable is a diff" is exactly wrong for F4/F5.

## Falsifier for the entry claim

Revert the config merge order in production, then run **only** the CI pinned-capture path with no runtime binary present. If the harness stays green, F2 — the most "differential" of the five — is not recoverable without the live authority, and the claim that the harness reproduces the finding is false (true recoverable count ≤ 2); if it goes red, the capture design recovers F2 in CI and the claim holds for F1–F3.
