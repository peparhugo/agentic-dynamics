## Entry claim

**Cross-lineage agreement on behaviorally-oracle-scored items carries positive independent signal only when it exceeds the within-lineage agreement floor (ICS > 0); therefore the cheapest *informative* fan-out is two lineages × blind disjoint evidence × a pre-registered divergence matrix, scored by lineage-corrected agreement — more arms or more prose lenses only raise the floor, not the signal.**

(Falsifiable: measure ICS ≤ 0 on oracle items with genuinely disjoint evidence ⇒ lineage distance is not the binding constraint and the decorrelation must come from somewhere else.)

---

## The two lenses I route through

**Lens 1 — Cluster-randomized experiment design / intra-class correlation.** The problem is set up wrong if the unit is "an answer." The unit is a *lineage cluster*; answers within a lineage are repeated measures, not replicates. This lens gives the honest discount: the design effect `1 + (m−1)ρ` and the effective sample size `N_eff`, where ρ is estimated from same-lineage arms. It converts "6 of 7 agreed" (looks like evidence) into "1.3 effective independent witnesses" (the truth).

**Lens 2 — Differential/metamorphic software testing with mutation-calibrated detectors.** This lens supplies the only cheap ground truth: an *executable* oracle plus prior-traps. Its central discipline is calibration — a detector's value is its measured power against known-correlated and known-independent populations, not its elegance. It also supplies the key adversarial move: an oracle that is a **behavior** (run the authority), not a **document** (which lives in the shared prior).

---

## What I add beyond wave-1 c17

c17's Q-B builds a *differential interrogator for the capacity boundary* — i.e., an oracle for the **system**. I add the **meta-oracle for the fan-out itself**: a scoring rule that (a) estimates the shared-prior floor from same-lineage replicates, (b) discounts effective witnesses, and (c) pre-registers divergence so agreement is scored against a prediction rather than discovered after the fact. c17 asks "can the machine reproduce the human's oracle?"; that question is only answerable once we can distinguish *agreement that tracks truth* from *agreement that tracks a shared prior* — which is exactly what this protocol measures. I do not re-argue c17's design; I make its validation scoreable.

## Protocol: Correlation-Discounted Confirmation (CDC v1)

### 1. Arms — which models, which questions

**Which models.** Do not hard-code names; resolve a *lineage table* at run time from the installed authority so the arm set cannot silently collapse to one prior:

```jsonc
// experiments/fanout_convergence/arms.json  (generated, committed with the prereg)
{
  "resolution_cmd": "opencode models <provider> --verbose",  // the authority for lineage membership
  "arms": [
    {"id": "D1", "model": "deepseek/deepseek-v4-flash",                          "lineage": "deepseek", "role": "probe-cheap"},
    {"id": "D2", "model": "deepseek/deepseek-v4-pro",                            "lineage": "deepseek", "role": "floor-replicate"},
    {"id": "O1", "model": "openai/gpt-6-astra",                                  "lineage": "openai",   "role": "cross-lineage"}
  ],
  "rule": ">=2 lineages required; same-lineage arms exist ONLY to estimate the floor and are never counted as independent witnesses",
  "fallback": "one lineage available -> emit 'confirmation_unavailable' (never report agreement as evidence)"
}
```

**Which questions — a typed bank, not open prompts.** Every item carries a machine-checkable answer class; only Class O has an oracle, and that is the only class where "independent confirmation" is a meaningful phrase:

- **O (oracle):** answer computable by an executable authority. E.g. the usable-context boundary for a given config, or the verdict for a given usage sequence. Correct = match the authority's *behavior*.
- **P (prior-trap):** an O item engineered so the common prior disagrees with the authority (e.g. the documented constant vs the runtime's merged behaviour; a config whose naive reading differs from the runtime's precedence/merge). Unanimous wrong agreement here is the shared-prior signature.
- **N (no-answer):** insufficient evidence; correct = `UNJUDGED`. Detects confabulation.
- **R (paraphrase pair):** the same O item in two surface forms; correct = identical answers. Measures prompt-sensitivity.
- **C (calibration anchors):** trivially easy O items; failure invalidates the run.

The oracle must be a **command**, never a paragraph: paragraphs are inside the prior, behaviors are not.

```bash
# The authority the arms are scored against — behavior, not documentation.
python3 scripts/fanout/oracles/capacity_boundary.py --config <fixture.jsonc> --json
#   -> {"effective_limit": 968000, "native_effective_limit": 968000, "policy_limit": null, ...}
```

### 2. Blind entry points

Three independent blinds, because "blind" that only hides the expected answer still leaks the framing:

1. **Evidence blind** — each arm gets a *different, disjoint* randomized slice of the artifact pool. This is the main decorrelator beyond lineage: shared context is the strongest correlation channel in a fork-of-a-fork.
2. **Answer blind** — no arm sees sibling answers; no arm sees the prereg; entry templates are neutral and never contain the words "fan-out", "contemplation", or the leading hypothesis.
3. **Analyst blind** — answers are stored keyed by `entry_id`; the `arm → model` map is sealed in `key.json` (hashed in the prereg) and opened only after every answer is frozen. This prevents halo scoring.

Add one **no-evidence probe arm** (same model as D1, question only, no slice). If no-evidence answers equal slice-fed answers item-by-item, the evidence did not move the model — a direct prior readout.

### 3. Pre-registered divergence predictions

Freeze, hash, and commit *before* any arm runs; the scorer and thresholds live in the same frozen file so they cannot be retrofitted:

```jsonc
// experiments/prereg/fanout_convergence/capacity_meta.json
{
  "protocol": "fanout-convergence/v1",
  "frozen_at_utc": "…",
  "question_bank_sha256": "…",
  "arms_sha256": "…",
  "predictions": [
    // oracle item where the prior and the authority AGREE -> expect cross-lineage agreement
    {"item_id": "cap-01", "class": "O", "predicted_modal": {"deepseek": "A", "openai": "A"},
     "predicted_divergence": false, "mechanism": "evidence"},
    // prior trap where the naive reading is wrong -> expect divergence, or unanimous-wrong
    {"item_id": "cap-07", "class": "P", "predicted_modal": {"deepseek": "B", "openai": "C"},
     "predicted_divergence": true, "mechanism": "prior"},
    // no-answer -> expect UNJUDGED
    {"item_id": "n-03", "class": "N", "predicted_modal": {"deepseek": "UNJUDGED", "openai": "UNJUDGED"},
     "predicted_divergence": false, "mechanism": "ill-posed"}
  ],
  "scorer": {"statistic": "ICS", "alpha": 0.05, "min_oracle_n": 12,
             "divergence_threshold": 0.25, "prereg_sha256": "<self-hash after write>"}
}
```

The informational events are: **confirmed divergence** (predicted to split, split) and **confirmed independent agreement** (predicted to agree, cross-lineage agree *and correct*). The failure event is **unpredicted unanimous agreement on a P item** — that is shared-prior repetition, named.

### 4. Scoring — independent confirmation vs shared-prior repetition

```python
# scripts/fanout/score_convergence.py  (skeleton; verbose by design)
"""Score a CDC v1 fan-out.

Design decisions, stated so they can be attacked:
  * Agreement is chance-corrected and CLUSTER-aware. Raw majority is never reported,
    because within-lineage arms are one unit of evidence, not m witnesses.
  * The null model is estimated from the SAME-LINEAGE replicate pair (A_within); we do
    not assume independence to test independence.
  * "Correct" exists only for Class O/P/C items (there is an executable oracle). Every
    headline number is reported on that subset, with the N/R classes as behavioural
    diagnostics, never as confirmation.
ASSUMPTIONS (flagged, not hidden):
  * Arms within a lineage share error correlation rho; we estimate it, we do not assume it.
  * The oracle is behaviour (a command), not a document (which the prior can contain).
"""
from __future__ import annotations
from itertools import combinations
import json, statistics

def agree(a, b):                      # typed exact match; None/UNJUDGED is a value, not missing
    return a == b

def icc_floor(per_item: dict[str, dict[str, str]], lineage: dict[str, str]) -> float:
    """A_within: mean pairwise agreement among SAME-lineage arms (the shared-prior floor)."""
    pairs = [(r1, r2) for r1, r2 in combinations(per_item, 2)
             if lineage[r1] == lineage[r2]]
    vals = [statistics.fmean(agree(per_item[r1][i], per_item[r2][i]) for i in per_item[r1])
            for r1, r2 in pairs] if pairs else []
    return statistics.fmean(vals) if vals else float("nan")

def cross_agreement(per_item, lineage):
    """A_cross: mean pairwise agreement across DIFFERENT lineages."""
    pairs = [(r1, r2) for r1, r2 in combinations(per_item, 2)
             if lineage[r1] != lineage[r2]]
    vals = [statistics.fmean(agree(per_item[r1][i], per_item[r2][i]) for i in per_item[r1])
            for r1, r2 in pairs]
    return statistics.fmean(vals)

def independent_confirmation_score(a_within: float, a_cross: float) -> float:
    """ICS = (A_cross - A_within) / (1 - A_within)  -- kappa-like, lineage as the cluster.

    ICS <= 0  -> cross-lineage agreement is no better than sharing a prior:
                 report 'shared-prior repetition', count ZERO independent witnesses.
    ICS  > 0  -> item-level signal survives lineage; the magnitude is the discount factor.
    """
    denom = 1.0 - a_within
    return float("nan") if denom <= 0 else (a_cross - a_within) / denom

def effective_witnesses(n_items: int, m_arms_per_lineage: int, rho: float) -> float:
    """Cluster design effect: N_eff = N / (1 + (m-1)*rho).  This number, not the arm count,
    is what a downstream reader is entitled to treat as independent."""
    return n_items / (1.0 + (m_arms_per_lineage - 1) * max(rho, 0.0))
```

The report is gated:

> Convergence may be called **evidence** iff `ICS > 0` with a permutation CI excluding 0 **and** `P(agree | all correct) > P(agree | not all correct)` on Class O — i.e. agreement separates truth from error. Otherwise the run returns **"agreement is prior, not confirmation"** with the P-item unanimity table as the receipt.

Additional diagnostics, all cheap and all text-only: predicted-vs-observed divergence confusion matrix; `P(agree|correct)` vs `P(agree|wrong)`; paraphrase instability per arm; no-evidence-probe gap; calibration-anchor floor.

### 5. Cost — why this is the *cheapest* informative design

Reuse the existing fork machinery (the KB's in-session fan-out: 17 phases, ~$0.14). The deltas are: an extra lineage per question, smaller prompts (blind slices are *smaller* than the full history), a CPU-only scorer, and one extra no-evidence probe. Approximate per-arm-question cost is dominated by context tokens; blind entries *reduce* it. For 3 arms × 20 items:

```bash
# Design: coverage budget and confirmation budget are SEPARATE ledgers.
scripts/fanout/build_prereg.py --bank questions/capacity.yaml --arms arms.json \
    --out experiments/prereg/fanout_convergence/capacity_meta.json
scripts/fanout/run_arms.py --prereg … --slices experiments/fanout_convergence/slices \
    --out experiments/results/fanout_convergence/<run_id>/answers.jsonl
python3 scripts/fanout/score_convergence.py --prereg … \
    --answers experiments/results/fanout_convergence/<run_id>/answers.jsonl \
    --oracle-cmd "python3 scripts/fanout/oracles/capacity_boundary.py" \
    --json | tee experiments/results/fanout_convergence/<run_id>/score.json
```

Do **not** buy confirmation by adding same-model samples; that buys floor, not signal. If coverage is the goal, buy it separately with one context-rich arm; never sum coverage votes into the confirmation tally.

## Conflicts kept visible

- **Arm count vs arm distance.** Counting arms *looks* rigorous and is the cheapest to run, but it is the exact move that manufactures false confidence under correlation. My design deliberately trades count for lineage distance and blind evidence; the counter-position (more arms ⇒ more coverage) is correct for *coverage*, wrong for *confirmation* — hence two separate budgets, and a hard rule that their votes are never combined.
- **Context-rich accuracy vs context-blind independence.** Disjoint evidence slices likely make arms *less accurate* (they lack the full history) while making their errors *less correlated*. These pull opposite ways; I resolve them by scoring **conditionally on correctness** and keeping a single context-rich arm for coverage. The unresolved residual: if blind slices drop accuracy so far that Class O has too few correct answers, the protocol returns `inconclusive` rather than lowering the bar.
- **Pre-registration vs discovery.** Freezing predictions protects against post-hoc storytelling but can over-constrain genuinely novel findings. I freeze only the *divergence matrix and the scorer*, not the question content; an explicitly labelled exploratory lane may surface new questions, but its answers are unscored and cannot upgrade a claim to "confirmed."
- **Executable oracle vs human review.** The protocol can show when the differential oracle suffices; it explicitly does **not** claim to replace the human review that caught what CI could not. The oracle's coverage is bounded by the mutations we can author, so "no detector can find X" remains a live possibility, not a settled one.

## Executable artifact (presented, not run — analysis only)

```python
# tests/test_fanout_score.py
"""Calibrate the CDC v1 scorer against known independent and known correlated populations.

This is the test that makes the entry claim falsifiable in CI: the scorer must ACCEPT
independent agreement and REFUSE correlated agreement on the same observed marginals.
"""
import random
from scripts.fanout.score_convergence import (
    cross_agreement, icc_floor, independent_confirmation_score, effective_witnesses,
)

LINEAGE = {"D1": "deepseek", "D2": "deepseek", "O1": "openai"}

def _population(n_items: int, *, accuracy: float, shared_error: bool, seed: int):
    """Build per-item answers.

    shared_error=False: each arm errs independently -> genuine cross-lineage confirmation.
    shared_error=True : D1/D2/O1 err on the SAME items with the SAME wrong answer -> a
                        shared prior masquerading as consensus.
    Marginals are held equal across the two worlds so the scorer cannot cheat on rate.
    """
    rng = random.Random(seed)
    truth = {f"i{k}": "A" for k in range(n_items)}
    hard = {f"i{k}" for k in range(n_items) if rng.random() > accuracy}  # items the prior gets wrong
    def ans(arm):
        out = {}
        for i in truth:
            if i in hard:
                out[i] = "Z" if shared_error else rng.choice(["Z", "Y"])   # wrong, but how?
            else:
                out[i] = "A"
        return out
    return {arm: ans(arm) for arm in LINEAGE}

def test_scorer_accepts_independent_confirmation():
    per_item = _population(40, accuracy=0.85, shared_error=False, seed=1)
    a_in, a_cross = icc_floor(per_item, LINEAGE), cross_agreement(per_item, LINEAGE)
    ics = independent_confirmation_score(a_in, a_cross)
    assert ics > 0.0, "independent agreement failed to clear the shared-prior floor"
    assert effective_witnesses(40, 2, rho=max(0.0, a_in)) < 40  # honest discount still applied

def test_scorer_refuses_shared_prior_consensus():
    per_item = _population(40, accuracy=0.85, shared_error=True, seed=1)
    a_in, a_cross = icc_floor(per_item, LINEAGE), cross_agreement(per_item, LINEAGE)
    ics = independent_confirmation_score(a_in, a_cross)
    assert ics <= 0.0, "unanimous shared error was mis-reported as independent confirmation"

def test_no_evidence_probe_reveals_prior_pull():
    """If a question-only arm reproduces the slice-fed answer, the evidence did not move it."""
    fed = {"i0": "A", "i1": "Z"}
    probe = {"i0": "A", "i1": "Z"}
    assert all(fed[i] == probe[i] for i in fed)  # -> flag 'prior-driven', not confirmation
```

## Falsifier

Run the protocol on ≥12 Class-O oracle items with *maximally disjoint* evidence slices across **three or more distinct lineages**: if `ICS ≤ 0` (cross-lineage agreement no better than the same-lineage floor) *and* the no-evidence probe reproduces the slice-fed answers item-for-item, then my entry claim is false — lineage distance is not the binding correlation channel, the correlation is carried by the shared prompt/repo frame, and the cheapest decorrelation is evidence isolation rather than more models. In that world the honest output is not "confirmed" but a named **shared-prior repetition** with the P-item unanimity table as its receipt.
