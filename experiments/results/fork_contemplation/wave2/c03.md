## Entry claim (one falsifiable sentence)

**Below the native usable boundary — for a fraction `f = context_tokens / native_effective_limit < 1` measured immediately before the *next* phase — `f` does not predict that phase's accepted-outcome rate once phase position is held fixed (|Δaccept| < 0.10 absolute); therefore an 80% advisory that only warns is safe.** This is the claim under test. It is deliberately narrow: it is a *conditional-independence* claim about prediction, not a claim that context is harmless forever — the native boundary still owns `f ≥ 1`.

---

## Two lenses, run separately (conflict kept visible)

I route through **potential-outcomes causal design** and **reliability/survival operations research**, because they disagree about whether the existing corpus can answer this question at all.

**Lens A — potential-outcomes / experimental design.**
`f` is not a dose you can assign. It is a deterministic, monotone function of the work already completed inside the session (tokens accumulate as phases pass). Any manipulation of `f` either drops content (compaction) or adds filler (context injection); both change the treatment bundle, not just the size. So the only identifiable policy estimand is **action-conditional**: at a fixed `f`, does `continue` differ from `compact_now` (or `close/handoff`)? Under this lens the existing data are structurally unusable for the causal question: high-`f` sessions are *survivors* of every prior gate, so conditioning on `f` conditions on a collider (common effect of task progress and loop state), and acceptance is produced by the same work that produced `f`.

**Lens B — reliability engineering / survival analysis.**
The advisory is a *monitoring* decision, not an intervention. A monitoring rule needs a predictive hazard, not a causal effect: `P(next phase fails | f, phase_index, spec)`. That quantity is estimable from `control.db.step_attempts` alone (exposure = cumulative `tokens` before attempt *k*, outcome = `state`), with no cross-store join, and the right threat model is **informative missingness** (is `tokens` null exactly when the attempt failed?), not endogeneity. Under this lens the existing corpus *is* usable, and the advisory can be calibrated today.

**Where they conflict, unresolved for now.** Lens A: do not use the existing data for any policy claim. Lens B: use it for the warning, not for the gate. I hold both and resolve only at the decision rule (below), explicitly labeled — I do not blend them into a single "context is fine" conclusion.

---

## What I add beyond wave-1 c17 (Q-A)

c17/Q-A proposed a dose–response over "controlled context fractions (20/50/80/95%)" with accepted-outcome rate, family depth, DLQ incidence, and cost. I do not repeat it. The precise additions are:

1. **The dose is not `f`; it is the action taken at `f`.** c17 frames `f` as the independent variable; because `f` cannot be assigned without changing content, the pre-registration must randomize the **action** (`continue` vs `compact_now`) inside `f`-strata. This changes the estimand from `E[accept | f]` to `τ(f) = P(accept | continue, f) − P(accept | compact_now, f)`.
2. **The named confounder**, which c17/Q-A did not name: work-progress endogeneity (plus the join-key gap and informative missingness). Delivered as a *counted* feasibility gate, not an assertion.
3. **A decision rule with numbers** (δ, α, cost/repeat guardrails, sequential stopping, and an explicit default under ambiguity), tied to the known false-positive cost.
4. **A feasibility pre-check as the executable artifact**, so the go/no-go on the existing data is itself reproducible before any analysis or spend.

### 1. Feasibility pre-check (the go/no-go) — `scripts/experiments/context_dose_response.py feasibility`

```python
#!/usr/bin/env python3
"""Feasibility pre-check for the context-fraction dose-response question.

WHY THIS FILE EXISTS.  The cheapest answer would come from data already on disk.  This
stage does NOT estimate the effect; it decides whether the on-disk data CAN, and names the
failing prerequisite.  The paid fork trial is gated behind this verdict, so the decision to
spend is itself evidence.

DESIGN DECISIONS (verbose rationale).
  * Exposure is read ONLY from session-budget/v2.  v1 lines carry the retired 200_000
    constant; mixing them would silently re-import the constant this arc deleted.
  * Lines with post_compaction=true are dropped: their context_tokens is, by the check's
    own definition, the STALE pre-compaction reading -- not a fraction.
  * Outcome is read from control.db, never from the fleet board: "launching"/"running" is
    not an outcome.
  * The join is COUNTED and its coverage reported.  If the only bridge is a time window,
    the check FAILS loudly rather than joining on proximity (the same fail-closed posture
    as the budget gate: a gate that cannot measure must not fabricate a result).
"""
from __future__ import annotations
import argparse, json, sqlite3
from pathlib import Path

# Power proxies, not significance.  Set so the first pre-registered trial batch could at
# least detect delta=0.10; chosen from the observed corpus so the threshold is falsifiable.
MIN_AIODIRECT_RUNS = 20
MIN_FAILED_ATTEMPTS_WITH_TOKENS = 30
MAX_TOKEN_MISSINGNESS_GAP = 0.20   # P(null | failed) - P(null | ok)

def load_v2_fractions(journal: Path) -> list[dict]:
    out = []
    for line in journal.read_text(encoding="utf-8").splitlines():
        if not line.strip():
            continue
        e = json.loads(line)
        if e.get("schema") != "session-budget/v2" or e.get("post_compaction"):
            continue
        cap = e.get("capacity") or {}
        limit = cap.get("native_effective_limit") or cap.get("effective_limit")
        if not limit:
            continue
        out.append({"session_id": e.get("session_id"), "ts": e.get("ts"),
                    "fraction": e["context_tokens"] / limit, "turns": e.get("turns")})
    return out

def feasibility(control_db: Path, journal: Path, fleet_jobs: Path) -> dict:
    con = sqlite3.connect(f"file:{control_db}?mode=ro", uri=True)
    samples = load_v2_fractions(journal)
    jobs = json.loads(fleet_jobs.read_text(encoding="utf-8"))  # job_id -> command dict

    # (1) exposure availability
    exposure = {"v2_samples": len(samples), "sessions": len({s["session_id"] for s in samples})}

    # (2) outcome availability + (4) informative missingness of the phase exposure
    miss = con.execute("""
        SELECT COALESCE(state,'?') AS s,
               AVG(CASE WHEN tokens IS NULL THEN 1.0 ELSE 0.0 END) AS null_rate,
               COUNT(*) AS n
        FROM step_attempts GROUP BY 1""").fetchall()
    missingness = {r[0]: {"null_rate": r[1], "n": r[2]} for r in miss}
    failed = missingness.get("failed", {}); ok = missingness.get("ok", {})
    gap = (failed.get("null_rate", 0) - ok.get("null_rate", 0)) if failed and ok else None

    # (3) join coverage: the ONLY honest bridge is the submit command's aio block.
    bridged = [j for j in jobs.values()
               if isinstance(j, dict) and (j.get("aio") or {}).get("native_session_id") and j.get("run_id")]
    by_session = {j["aio"]["native_session_id"] for j in bridged}
    with_f = [s for s in samples if s["session_id"] in by_session]
    join = {"submits_with_run_id": len(bridged), "distinct_sessions": len(by_session),
            "sessions_with_f_and_run": len(with_f)}

    # (5) phase collinearity: is f deterministic in phase index?  (identifiability)
    conf = con.execute("""
        WITH ordered AS (
          SELECT run_id, attempt_no,
                 SUM(COALESCE(tokens,0)) OVER (PARTITION BY run_id ORDER BY started_at
                                               ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING) AS cum
          FROM step_attempts)
        SELECT COUNT(*) FROM ordered WHERE cum > 0""").fetchone()[0]

    verdict = {
        "existing_data_sufficient": bool(
            join["sessions_with_f_and_run"] >= MIN_AIODIRECT_RUNS
            and (missingness.get("failed", {}).get("n", 0) >= MIN_FAILED_ATTEMPTS_WITH_TOKENS)
            and (gap is None or gap <= MAX_TOKEN_MISSINGNESS_GAP)),
        "exposure": exposure, "join": join, "missingness": missingness,
        "missingness_gap": gap, "cumulative_token_rows": conf,
        "named_failure": None,
    }
    if join["sessions_with_f_and_run"] < MIN_AIODIRECT_RUNS:
        verdict["named_failure"] = ("EXPOSURE_OUTCOME_JOIN_GAP: runs carry no session_id; "
                                    "only AIO-origin submits bridge via fleet:jobs.aio")
    elif gap is not None and gap > MAX_TOKEN_MISSINGNESS_GAP:
        verdict["named_failure"] = "INFORMATIVE_MISSINGNESS: tokens null mostly on failures"
    return verdict
```

## Decision rule (stated before data; keeps or removes the advisory)

With `τ_g = accept(continue) − accept(compact_now)` in group `g`, `δ = 0.10`, one-sided 95% bounds, Beta(1,1) posteriors, clustered by family:

- **KEEP the advisory** (status quo: warn at 0.8, act only at the native boundary) iff **every** group satisfies `LCB95(τ_g) ≥ −δ` **and** `cost_per_accepted(continue) ≤ 1.25 × cost_per_accepted(compact_now)` **and** `repeats(continue) ≤ repeats(compact_now) + 1`.
- **HARDEN the advisory** (block at 0.8 until compaction) iff **any** group has `UCB95(−τ_g) > δ` — i.e. continuing is worse by more than δ with 95% confidence.
- **Otherwise** run one more pre-registered batch (max two); if still ambiguous, **KEEP** the advisory.

Why default-keep on ambiguity, and why these numbers: the *false positive* is already measured (a valid session was refused at 172,491 tokens against 968,000 usable at `ses_f5add1095ffe1ZDEm4YJZJLbwy`); its cost is a stopped workstream. The *false negative* is bounded by `δ` and by the native boundary still firing at `f ≥ 1`. Asymmetric costs justify a status-quo prior — but only until the `near` group shows a confident loss.

## The confounder that makes the existing data unusable

**Work-progress endogeneity.** `f` is a monotone function of the phases already completed, and acceptance is produced by that same work; a high-`f` session is a survivor of every prior gate, so conditioning on `f` conditions on a collider and `E[accept | f]` cannot be read as an effect of `f`. *`f` is a mileage gauge, not a throttle.* Two secondary faults compound it: (i) the **exposure and outcome live in disjoint stores** — `runs` has no session id, so the only honest bridge is `fleet:jobs[aio.native_session_id] → run_id`, which covers AIO-origin submits only (unusable for the broader corpus); (ii) **informative missingness** if `step_attempts.tokens` is null precisely on failures. The endogeneity is structural and cannot be fixed by more data of the same kind; the join gap is an engineering fix worth landing regardless (record `run_id, native_session_id, f_at_start` on the run row so the next corpus is joinable).

---

## Falsifier for the entry claim

A single pre-registered result falsifies it: in the `near` group (`f ∈ [0.85, 1.00)`), across ≥3 paired forks of the same next phase, `continue`'s accepted-rate falls ≥0.10 absolute below `compact_now`'s with the one-sided 95% upper bound of the loss above 0.10 — then context fraction does predict below the native limit, the 80% advisory is not safe, and it must harden into a pre-compaction gate.
