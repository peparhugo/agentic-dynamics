## 1. Two expert lenses, kept divergent

I route through two lenses and refuse to reconcile them early, because their disagreement is the useful part of this question.

**Lens A — compiler / denotational semantics.** A rule *denotes* a predicate. Enforcement is a rejection inside a **total** function `P(state) → {pass, refuse}` evaluated at a boundary. This lens cares about decidability, totality, and fail-closed behavior: a rule whose predicate is over a *distribution* (quality, correctness, "the right thing") is not a predicate this compiler can lower; it is a different kind of object. **Lens B — assurance-case / test-oracle engineering.** The oracle problem says most interesting properties have no cheap oracle; enforcement is not the only legitimate control. A **monitor** (observation without refusal) is real assurance machinery with an owner and a detection metric. Lens B's verdict: **do not drop the non-compilable finding** — that is how the arc lost the service-reload signal (`restart` printed `DISPATCH`, never checked `ok`, wrote no board record; `c02`). My compiler therefore emits two labels and carries a `nearest_monitor` field in the (b) case — which Lens A reads as prose-with-a-stub and Lens B reads as a future check. ## 3. The compiler

```
C(F) -> ENFORCED { predicate, boundary, observable, decision_rule,
                   owner, location, command, refusal_path }
     |  PROSE_ONLY { label, reason, nearest_monitor }

Rationale for this exact signature: the prompt fixes owner/location/refusal; I add
boundary/observable/decision_rule because a check without a boundary where refusal
still prevents the harm is a post-mortem, and a check whose observable is a proxy
re-invites the arc's central failure (c17's "adjacent quantity").
```

Lowering steps, in order — each returns `PROSE_ONLY` on failure rather than guessing:

1. **Predicate extraction.** Rewrite `F` as `P(state) → bool`. If `P` is over outcomes, distributions, or human intent ("builds the right thing"), emit `PROSE_ONLY{reason: distributional/undecidable}`.
2. **Boundary.** Find `B` where the state is visible *and* refusal still prevents the harm (before a launch, before a merge, at CI, at an approval gate). No such `B` → `PROSE_ONLY{reason: no boundary}`.
3. **Observable.** Identify `O` carrying `P`; prefer the authority's own output (a diff) over a locally computed proxy. Not observable at `B` → `PROSE_ONLY{observation gap}` or, where the consumer topology allows it, the existing **defer-to-the-owner gate** semantics (the correct handling when a container cannot see the host DB).
4. **Decision rule + calibration.** A threshold must cite a measurement source. Uncalibrated → **advisory monitor** (this is why the 80% WARN is advisory: it has no dose–response calibration, only a hunch — `Q-A`).
5. **Totality / fail-closed.** `P` must be defined on *unavailable* states; unknown must refuse or defer, never pass. A predicate that silently passes on missing data is rejected.
6. **Ownership.** A **paging** owner (the role accountable for the check staying green — not the rule's author), a concrete path, the exact command, and the named refusal. No paging owner → `PROSE_ONLY`.

**Refusal vocabulary this project already has and the compiler reuses:** `test`/`lint`/`surfaces` check red under branch protection; `LaunchRequestError` before the compose call; `UNJUDGED`/`COMPACT` in the budget verdict; `fleet_jobs` DLQ; `awaiting_operator_approval`.
