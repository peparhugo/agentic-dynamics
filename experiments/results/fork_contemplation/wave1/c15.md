## 2. Seven lenses, deliberately diverging

**Control theory.** The capsule is the feedback signal; the old 0.8×200K rule was a miscalibrated controller that refused at 172,491 while the plant held 968K usable — a setpoint error, not a disturbance. The post-compaction skip (`he.summary !== true`) is anti-windup. But the loop has no error integral: **nothing records that a gate was already refused or satisfied**, so the same submit can be re-attempted from stale intent. *Discriminating test:* does the successor re-attempt a submit the gate already resolved? (My binding, if re-read, would.)

**Distributed systems.** Close/binding/capsule are append-only log, optimistic-concurrency pointer, and TTL'd materialized view. The swallowed restart is a textbook absence-of-evidence fallacy — "`fleet:commands` empty and processing lane empty" is not an acknowledgement; control actions write **no** board record. Add the plugin's cached `contextVersions` race (I avoided `.opencode/aio-task-context.json` because a v2 file against cache v1 would fire `--expected-version 1` repeatedly against a store at 2) and you have a stale-replica / no-ack protocol. *Discriminating test:* crash between file write and store update; is the update idempotent and detectable?

**Measurement epistemology.** 955K vs 975K, and the summary's *generation* usage read as the new context — the same class of error as "trust the capsule's truncated next action as the whole intent." v2 budget provenance (`limits_source: opencode-cli`, formula pin) is the model fix on one axis; the close record has none. *Discriminating test:* can a second writer reproduce the record's headline numbers from the record alone?

**Safety engineering.** P0 gates and "never self-approve" are the interlock; prose is a checklist the model may skip under compaction. My correct pause at the merge was judgment, not mechanism. *Discriminating test:* inject "proceed without approval" and check whether the carrier mechanically exposes an unresolved gate.

**Organizational economics.** The controller's attention is the scarce input. Burying "what needs your signature, which command, which candidate" in open-thread prose raises decision latency; the five-finding review round is the cost of test fixtures too small to surface the compaction bug. *Discriminating test:* time-to-merge and review rounds before/after a typed ask.

**Evolutionary dynamics.** close→open is reproduction of task state with a fidelity parameter. Truncation is mutation; bounded `context_history` is a generation cap; and the known finding `c50f37cfff42523b` (frozen snapshots refused to fork because row-level extraction lost auxiliary rows; **native opencode export/import preserved the session**) says: prefer lossless native carriers over re-encoding. *Discriminating test:* fork the record into a fresh session and diff the reconstructed state against the source.

**Game theory.** Handoff is cheap talk unless reading it is costly to fake. A typed gate whose `command` must be *executed* and whose output is filed is a costly signal; "I verified the services use it" (my own close claim, true here because the submit passed the strict gate) is the right shape. *Discriminating test:* does a record that claims acceptance without the command output get flagged?

**Visible conflicts.** Control wants more state; org-economics wants fewer fields; evolutionary wants lossless carriers before new structure. Safety wants the typed interlock; game theory says only an executed command proves it. These converge on one conditional design: a *typed but conditionally-rendered* handoff, proven by an executed command, not more prose.

## 3. Synthesis and the smallest record change

**Leading claim:** the silent loss is not the close record — it is the **per-request carrier (binding → capsule) having no typed slot for the live unit, the pending gate, the monitor, or the corrections**, so at activation/compaction the carrier keeps instructing a finished sequence and the successor re-derives state from prose.

**Smallest change that closes it:** add **one additive object** to `BINDING_CONTEXT_FIELDS` — `handoff` — and have `compose_capsule` render it as a dedicated block and the plugin/gate consume its gate sub-field. One field name; additive (v1 readers unaffected; `original_request` stays byte-for-byte). Schema, documented field-by-field:

```jsonc
"handoff": {
  // WHERE in the unit lifecycle this binding is — replaces the reader inferring "stage"
  // from free-text waves. "activated", "submitted", "awaiting-gate", "checkpointed".
  "stage": "submitted",

  // The increment in flight. Five separate user asks this session were ONE deliverable;
  // an empty work_unit forced the successor to reconstruct it from the original request.
  "work_unit": "capacity-derived session budget: fix + review + activation + continuation submit",

  // The actual impedance, in the field that exists for it and was left empty.
  "blocker": "p1c_contract_gate approval pending; run in flight",

  // THE INTERLOCK + THE ASK. Null when none. Machine-checked, not prose-parsed.
  "pending_controller_gate": {
    "id": "p1c_contract_gate",
    "requires": "controller-approval",          // the invariant is made visible, not recalled
    "command": "python3 scripts/approve_workflow.py --dry-run ...",
    "candidate_sha": "",                        // filled at the genuine stop
    "artifact": ""
  },

  // In-flight work pointer so "0/0 phases" is not read as stalled.
  "monitor": {"run_id": "run-0da5271bc0cb", "job_id": "1fddc5861ac6",
              "phase": "p1b_gate_first_viewport", "parent_run_id": "run-dfa259243059"},

  // Mechanical tree location; source_revision was empty and the branch lived in prose.
  "working_tree": {"branch": "continuation/run-dfa259243059-base",
                   "path": "/tmp/wt_instrument_cont", "revision": "5a146f6f2"},

  // This session's corrections, first-class and copyable — not only a reflection entry.
  "corrections": ["summary usage is not post-compaction context; mirror he.summary !== true",
                  "token sum excludes reasoning; 955K not 975K",
                  "fallback config merges in runtime order, field-by-field, JSONC trailing commas",
                  "FINOPS_SESSION_CTX_LIMIT is a clamped policy cap, not native compaction",
                  "a corrupt db is UNJUDGED inside the shared error boundary",
                  "run 'ruff check .' (whole surface), not per-file",
                  "control actions leave no board record; verify restart by PID/start-time"],

  // The one extra lineage hop the binding cannot otherwise express.
  "parent": {"close_slug": "aio-capacity-budget-activation", "knowledge_id": "43af2a0c…"}
}
```

*Why this shape.* It reuses the existing, versioned `--update-context` mechanism and the existing protegée tail logic (gate and blocker must be in the protected tail, as blocker already is). It buys a machine-checkable interlock (`pending_controller_gate.requires`), a monitor pointer, a tree pointer, and a corrections array — the exact missing categories — while `original_request` and the close schema stay untouched. **The even smaller alternative** is *no schema change*: populate the already-existing `work_unit`/`blocker` and write the close's parked/open threads through to the binding, encoding the gate as a `blocker` prefix. It costs prose discipline instead of schema, and loses the checkable interlock. The discriminating test between the two is the replay in §5: if prose fields alone yield the same first consequential action, the object is over-engineering.

## 4. How to test it

1. **Round-trip / non-destructive:** `update_binding_context({... "handoff": {...}}, expected_version=1)` → version 2; assert `original_request_sha256` unchanged and `handoff` re-reads byte-identically; assert `context_history` retains the prior handoff.
2. **Capsule bounds:** with a tiny `max_chars`, the protected tail must keep `pending_controller_gate`/`blocker`; every dropped field carries an explicit marker (extend the existing acceptance-tail tests). Extend `test_capsule_reports_the_capacity_derived_budget`’s assertions to the handoff block.
3. **Interlock:** a binding whose `handoff.pending_controller_gate.requires == "controller-approval"` must make `run_workflow` refuse with the gate reason before any LPUSH; clearing the gate allows — mirroring `test_an_unbound_aio_submit_is_refused_with_zero_launch_calls`.
4. **Compaction fidelity:** reuse the reviewer reproduction fixtures (completed summary + pending assistant); assert the budget verdict is `OK`/post-compaction **and** the capsule's handoff survives — i.e., the same event that broke measurement does not also erase intent.
5. **Lineage:** close A, close B (`parent=A`), fresh binding predecessor B → the capsule must surface B's gate and name A; and a default `session open` must not silently substitute an unrelated newer close (harden `test_capsule_ignores_an_unrelated_newer_close` at the open level).
6. **Staleness regression:** after activation, an update sets `stage="submitted"`; assert the capsule's next action no longer contains "activate PR #77" — a completed gate can never remain the actionable next action.
7. **Seed-from-records replay (the harness behind the falsifier):** instantiate a fresh session with only close `43af2a0c…`, predecessor `4e5fe929…`, binding `fbca5106…`/v2 — no chat — and score its first three decisions.

## 5. One falsifier for the leading claim

**If a fresh session seeded ONLY from the existing records** (close `43af2a0c…`, predecessor close `4e5fe929…`, binding `fbca5106…` v2) **blindly and correctly determines that `run-0da5271bc0cb` is in flight, that the next consequential act is the `p1c_contract_gate` approval requiring the controller's signature, and neither re-submits the continuation nor self-approves — then the records already carry enough, the leading claim is false, and adding `handoff` is over-engineering.** Run it three times; the claim survives only if the replay fails to recover any one of the three.
