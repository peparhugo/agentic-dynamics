## Seven lenses (divergence first)

**Control theory.** The budget check is a supervisory controller: setpoint = operative limit, measurement = context samples, actuation = verdict. The old fixed 200K setpoint on a 1M plant is a scaled reference; the post-compaction bug is a **state-estimator fault** — feeding the actuator's own action (the summary call) back as plant state, a classic way loops mis-close. The reviewer's *"returning COMPACT does not initiate compaction"* is control-theoretic, not pedantic: COMPACT is an open-loop actuation claim that only the runtime can execute. *Discriminating test:* inject ≥usable with `compaction.auto=false`; the verdict must be CLOSE (no phantom actuator).

**Distributed systems.** The submit path is durable (BLMOVE claim lane + `_recover_processing`), but the `restart` control action was **at-most-once with silent loss**: claimed, queue emptied, no compose call, no board record. "Queue empty" is not an acknowledgement. The binding slot is content-addressed and flock-serialized, while the capsule reads a cached predecessor (30s TTL) — a benign staleness window for continuity, not for gating. Known finding `6ef9bf9b` (goals ride argv; newlines refused; untracked specs never reach clones) shows the transport is an argv/commit protocol with sharp edges. *Discriminating test:* give control actions a cheap terminal receipt; assert the consumer checks the broker's `{ok, returncode}` for non-submit actions.

**Measurement epistemology.** "Verified capacity" is a claim about a procedure, not a number. The reasoning-inclusion bug (955K native vs 975K local) is **construct-validity** failure — summing tokens the runtime's comparator ignores. The summary bug is map-replacing-territory. The repair is provenance: `limits_source: opencode-cli`, `model_source: session.model`, `formula: opencode@1.18.15`. Known finding `7948b8ac` (no instruction arm improved accepted outcomes; baseline cost-minimal; 95.5–97.9% cache) warns that changing the agent's *stated* policy may not change measured behavior — so the budget check must be judged on verdicts and run outcomes, not rule text. *Discriminating test:* replay a session token series through both the local resolver and the runtime comparator; assert equality on every sample.

**Safety engineering.** Defense in depth is real: plugin early check (convenience) → consumer validation → **strict broker** (interlock); `UNJUDGED` never permission is fail-closed. But a **false trip is a safety cost too**: 172,491 was a spurious trip that halted a legitimate build, and the post-compaction case was worse — a spurious trip exactly at the boundary the mechanism exists to cross. The advisory/alarm vs CLOSE/trip separation is correct architecture with initially miscalibrated trip points. *Discriminating test:* false-trip/false-clear rates on a labeled state corpus (the operator's six bullets are a start; n=1 per bullet).

**Organizational economics.** The AIO is an agent on an admission lease (reserve 0.6 / hard cap 1.0 / campaign 20); the controller holds permanence. The P0/P1 split is a **credible commitment**: my inability to merge makes the controller's signature a real cost, not theater. The swallowed restart is the standard monitoring gap — control actions leave no board record, so the principal must trust a log line. *Discriminating test:* add a terminal receipt for control actions and measure whether agent restart reliability rises while oversight cost falls.

**Evolutionary dynamics.** Policy variants are selected by the operator's preference, not an internal fitness function. `c50f37cf` (seed → four isolated branches, 47%→90% cache, $0.004735; frozen snapshots refuse to fork) frames fork **fidelity** as the heredity bottleneck; `7948b8ac` says most instruction mutations are neutral or worse. So the capacity change should be judged by **retention of the same task lineage** (resume of `run-dfa259243059`) rather than a fresh experiment. *Discriminating test:* fork the same session state with/without the summary-skip patch and compare boundary verdicts — the patch must be deterministically selected.

**Game theory.** The binding gate + `task_revision=2` is a mechanism against identity spoofing: the tool reads the binding from `ctx.sessionID`, never a model-supplied arg, and the backend re-resolves. The instruction *"do not construct another broker client"* is mechanism preference — route through the auditable durable path. The p1c operator approval is a screening device against self-dealing. *Discriminating test:* stale `task_revision` must refuse — already covered by `test_a_stale_task_revision_is_refused_and_the_current_one_passes`.

## Visible conflicts and their discriminating tests

- **Control/safety (tighten feedback, add trips) vs organizational economics (monitoring and false trips cost).** Test: false-trip rate + added transaction cost of an ack.
- **Measurement epistemology (`7948b8ac`: instruction changes may be inert) vs evolutionary selection (better variants win).** Test: hold policy fixed and measure behavior, versus vary policy and measure outcomes.
- **Distributed systems (capsule staleness is acceptable continuity) vs safety (a stale verdict must never gate).** Test: capsule TTL path must not feed the gate; the gate measures live.
- **My leading claim vs the policy-first story.** The accepted policy made a *same-session* submit legal; the predecessor close record shows a fresh-session route already existed. So the policy was enabling, not causal — unless the gate now tracks the runtime.

## Synthesis

Across the three moments, the load-bearing variable is **agreement with the mechanism being supervised**: the runtime's own resolution (moment 1), the runtime's own token comparator (moment 3), and a policy whose trip points no longer fire below the plant's real capacity (moment 2). The numeric capacity (968K) fixed the *specific* false trip; the provenance and behavioral mirroring fixed the *class* of false trips. The evidence for each numeric choice was weak at the time; the evidence for the equivalence was available but uncollected (the CLI output, the `he.summary` guard) or untested (realistic summary usage). `7948b8ac` is the sobering control: a changed rule can be inert unless the mechanism enforces it — which is why the gate, not the rule text, is the instrument.
