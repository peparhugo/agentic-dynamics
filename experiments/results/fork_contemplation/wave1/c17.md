# Cross-Fan-Out Synthesis — the AIO capacity-budget arc, read as one corpus

*Analysis only. No files, commands, or code. I am the last sibling; my evidence is the sixteen contemplations plus the working history they all cite.*

**Leading claim, stated up front so the closing falsifier has a referent.**
Every failure in this arc — and most of the remedies the fan-out proposes — is the substitution of a cheap *adjacent quantity* for the authority's own output. The repairs that held were the ones that replaced the local quantity with a diff against the authority; therefore the only durable output a deliberation like this can have is whatever can be written as such a diff (an executable oracle), not as prose.

I route through seven lenses, keep their conflicts visible, then reconcile.

## 1. Seven lenses, each with its own take, grounding, and discriminating test

### Lens 1 — Control theory: the observer must be the plant's own output
**Take.** The budget check was a controller running a model of the plant, not the plant. `DEFAULT_CTX_BUDGET = 200_000` against a resolved 968,000 usable (deepseek-v4-flash) is a mis-scaled setpoint; `_measure` reading a compaction summary's generation usage as the new context is an observer aliasing the actuator's effort for the state. The runtime's own loop carries the guard I should have mirrored from the start: `he.summary !== true` before `isOverflow`. The `FINOPS_SESSION_CTX_LIMIT=100K` → `COMPACT` finding is actuator dishonesty: the policy layer commanded native compaction, which only fires at its own threshold (fixed to a clamped policy `CLOSE`).
**Conflict (kept visible).** Control theory disagrees with itself here. c11 argues the loop runs *too fast* (per turn, while the plant's time constant is a session) and manufactures churn; c05 argues the authoritative observer is *slow* (~2 s `opencode models` subprocess) and prefers slow-but-true feedback over fast-but-fictional. Gain scheduling vs. loop rate — unresolved in the set.
**Discriminating test.** Model-in-the-loop equality: drive the exact post-compaction message sequence and the 955K usage triple through both the local check and the runtime's `Dl`/`Is`; any verdict disagreement is a false model, not a tuning problem.

### Lens 2 — Distributed systems: split-brain resolvers and effects without receipts
**Take.** Two writers to "the limit" — our `_config_candidates`/`load_runtime_config` and opencode's loader — is split-brain; the reviewer's three reproductions (OPENCODE_CONFIG ordered before project; partial `output` override discarding inherited `context`; JSONC trailing commas dropped) are the second implementation losing to the first. Separately, the swallowed `fleet_manager.py restart --service workflow-runner` is a lost control message: claimed, queue and processing lane emptied, no compose call, PID `733477` unchanged — acceptance without propagation. The binding tuple (`native_session_id`, `fbca5106…`, `task_revision 2`) is the fencing token that *does* work; the restart had no equivalent.
**Conflict.** Pure single-authority maximises correctness and creates a single point of failure; the host/container defer split is the deliberate concession (the consumer defers, the broker measures strictly). c05 names this divergence; the set never resolves the acceptable residual risk.
**Discriminating test.** Partition test: stop the authority and require every replica to emit the *same named* downgrade (`UNJUDGED`, defer, `DOCKER_UNAVAILABLE`). Plus: every effectful control action must leave a durable terminal record; today `submit` does (`fleet:jobs[…] <- launching`), `restart`/`drain`/`scale` do not.

### Lens 3 — Measurement epistemology: construct validity, and fixtures as self-fulfilling oracles
**Take.** Three independent instrument errors: `reasoning` added to a sum the runtime never includes (955K native vs 975K local); the summary generation usage read as context; and the corruption initially hidden because `_append_compaction_summary` defaulted to `summary_tokens=15_000`, 65× below the 975K pre-compaction reading — c13's sharpest phrase: *"a no-change verdict from a small task inside my own test design."* The malformed JSONC fixture ("I had to decide which artifact was lying") is the same class one layer down. The one genuinely epistemic act added was provenance (`limits_source`, `formula_version`, `runtime_version`, `version_match`) — it makes each number attributable to an instrument rather than to a re-derivation.
**Conflict.** Fidelity ("measure the runtime's state") vs. relevance ("measure the predicate the operator cares about"). The review resolved in favour of fidelity; c13's B2 notes that resolution may be category-correct but still not the right construct for the original failure.
**Discriminating test.** Blind authority round-trip: capture a real session natively (`opencode` export/import, per `c50f37cfff42523b`) and require our numbers to match on the same sample — no hand-authored fixtures.

### Lens 4 — Safety engineering: false trips, fail-unsafe paths, and aligning holes
**Take.** The gate is an interlock hierarchy — advisory `WARN` < policy `CLOSE` < native `COMPACT` < hard `CLOSE`, with `UNJUDGED` fail-closed — but it false-tripped on a *healthy* state (post-compaction: 975K/`COMPACT` after a successful compaction), the exact pathology the policy change existed to remove. The corrupt-DB CLI crash was fail-unsafe repaired to fail-safe (`UNJUDGED`). The structural hole the set under-weights: branch protection requires the ten checks but `reviewDecision: ""` — the decisive oracle (the controller's five reproductions) was *voluntary human attention*, not a rail; and the running services read the local main checkout, so `merge` + restart is the real energy boundary (c12's Swiss-cheese).
**Conflict.** Adding reviews battles the scarce resource (Lens 5) and, per `7948b8ace287e881`, prose/interlocks-as-text have not changed accepted outcomes. The safety answer must be *automatic* fault detection, not more human inspection.
**Discriminating test.** Fault-injection campaign — corrupt DB, stale binding, broker down, resumed compaction, model switch, summary-as-context — counting *unsafe-pass* vs *safe-stop*, with the silent cases (neither) scored worst. The swallowed restart is the current exemplar of "neither."

### Lens 5 — Organizational economics: attention is the scarce input, and text is outcome-neutral
**Take.** The controller's manual review was the highest-yield oracle in the session (c08's ledger); a 1,451-insertion diff hid three authority divergences that ten green checks could not see (`bc87e60af` fixed lint only; the five findings landed *after* green). The efficient interface makes the human's single line be "does the oracle match the runtime?", which argues for an authority-provenance block at the top of the change — one line, not more prose. `7948b8ace287e881` is the hard constraint: no instruction arm improved accepted outcomes, baseline cost-minimal.
**Conflict (central, and the fan-out does not resolve it).** Sibling after sibling cites `7948b8ace287e881` and then proposes *more typed fields, more close-record sections, more rules* — i.e., more text. The distinction the set gestures at but never states is **instruction (prose, outcome-neutral) vs. mechanism (executable, boundary-enforced)**. This is the contradiction I exploit in synthesis.
**Discriminating test.** Measure findings-per-review as a function of an executable authority block (an oracle the reviewer can *run*) vs. a prose block. Prediction from `7948b8ace287e881`: the prose block moves nothing; the runnable block changes the review's cost per finding.

### Lens 6 — Evolutionary dynamics: a local optimum that went stale, with no supersession marker
**Take.** 200K/80 was adaptive for a 200K-context world and became maladaptive; the system has no fitness signal on the thing that matters (terminal outcomes), so this is drift, not adaptation. Worse, stale constraints propagate: the predecessor close `control-room-instrument-cont-submit` still frames the submit against "a fresh session crosses the 160k WARN threshold in one deep-reading turn" — a threshold *this* session retired — with no supersession mark (c15). `version_match` is recorded in provenance but never acted on.
**Conflict.** Against c11's frame attack: evolution needs selection pressure; if accepted-outcome rate is flat (and `7948b8ace287e881` suggests instruction variation doesn't move it), the system is not evolving, it is accumulating artifacts.
**Discriminating test.** Inject a superseding rule and measure whether successors obey the retired copy. They did — the capsule rendered the *new* budget while the close prose still asserted the old threshold; successor behavior followed the executable surface, not the prose. That is evidence for the synthesis.

### Lens 7 — Game theory / mechanism design: principal–agent, and payoffs measured at the wrong gate
**Take.** The AIO's visible payoff is green gates and accepted submits ("Submission accepted by the durable path… A queued submit is NOT a running run"), not terminal run outcomes or attributed cost (`FINOPS_ADMISSION_COST_SOURCE=estimated` reservations, not realizations — c06's cost-without-attribution; contrast `c50f37cfff42523b`'s $0.004735 at four decimals). This rewards proxy success. The same-spec chain (`run-f344c4b99162` → `run-f52d829af58e` → `run-1c341d58af27` cancelled → `run-b787b0d16d6c` → `run-dfa259243059` → now `run-0da5271bc0cb`) plus 34 `fleet_jobs` DLQ entries is a population with no recurrence detector: the arc ends by resubmitting the failed parent, and no instrument can say "attempt N of a failing family."
**Conflict.** With Lens 5: redefining the payoff to terminal outcomes requires more observation (attention), the scarce resource — so the mechanism must be automatic.
**Discriminating test.** Re-base the agent's payoff on terminal run state + realized cost and measure behavior change in submission/continuation choices. If nothing changes, the gate-transition payoff is not the causal driver and c06's thesis weakens.

## 2. Reading the sixteen together: patterns, agreements, contradictions, blind spots

**Patterns / agreements (weak evidence: one model, correlated samples).**
There is near-unanimous convergence on four propositions: (i) consume the authority rather than re-derive it (c02, c03, c04, c05, c08, c10, c12, c14, c16); (ii) the compaction/worktree fixture masked the failure (c01, c07, c09, c13, c15); (iii) acceptance ≠ effect / queue-empty ≠ dispatch (c02, c03, c06, c07, c10, c12, c14); (iv) the human review was the decisive oracle (c07, c08, c09, c11, c12). The convergence is *not* independent confirmation — all sixteen share the same base model and priors, so agreement is weak evidence. Only c11's frame attack notices this.

**Contradictions.**
1. **Prose vs. mechanism** (the big one): nearly all siblings cite `7948b8ace287e881` (instructions don't improve outcomes) and then prescribe new fields, sections, provenance blocks, and typed records — more text. Nobody states the discriminator that would resolve it.
2. **Loop rate**: run the check every turn (current) vs. sample at the plant's time constant (c11); slow-authoritative vs. fast-fictional observers (c05).
3. **Single authority vs. resilience**: consume opencode exclusively (c04, c14) vs. the deliberate host/container defer split (c05, c12) — the accepted residual risk is never quantified.
4. **Was the policy change right?** The operator's directive is treated as ground truth in most siblings; c11 and c13-B2 challenge whether capacity is the right construct at all, since the original 25-hour failure was *compliance/looping*, not overflow.

**Redundancy.** The seven-lens frame is repeated verbatim in all sixteen and collapses to three lenses in practice (control, distributed systems, measurement epistemology). Evolutionary dynamics and game theory are named but rarely deployed substantively (c05, c11, and this synthesis are the exceptions); safety and organizational economics appear in roughly half.

**Blind spots the fan-out as a whole did not see.**
1. **The arc's final act was never verified to an effect.** Every sibling treats the receipt (`1fddc5861ac6` → `run-0da5271bc0cb` running, `p1b_gate_first_viewport` leased) as the outcome. The set's own thesis — "a queued submit is not a running run" — applies one level up: no sibling verified `p1c_contract_gate`'s checkpoint stop or `p6g_acceptance`; the packet showed `phases 0/0` and `step_attempts=0` across 240 s at epoch 772, which reads as *stalled* to a successor that doesn't know the ledger is written at run end (c15 names this, but only as a carrier flaw).
2. **The fan-out's own cost/benefit.** Only c09 (economics) and c11 (frame attack) consider it; no sibling applies `7948b8ace287e881` to the practice itself. The prompt has to ask me to score it.
3. **The voluntary review.** Only c12 notices `reviewDecision: ""` — that the oracle which found five bugs was an unpinned human act, not a rail.
4. **No effect-receipt requirement generalised.** The swallowed restart is diagnosed by several lenses, but none converts it into the leading structural fix (durable terminal receipts for *all* effectful acts), which is the one mechanism that directly matches "acceptance ≠ effect."
5. **Quality vs. capability.** The set conflates "will it fit?" with "is it any good?"; the construct that failed originally (a session that kept accepting work and looping, ~698K context, zero compactions) is not obviously bounded by a context ceiling. B2 (c13) raises this; the set does not resolve it.

**Question quality.** Well-posed: "where did effort compound and what would have stopped it" (the seed question) and "smallest changes, largest trajectory effect" (c05) — both yield executable candidates. Redundant: the repeated "what could go wrong" lens surveys. Missing: the quality construct; the mechanical detector; the fan-out's own epistemic validity; who reviews the reviewer.

## 3. The two strongest new questions for the next wave

### Q-A — Is the capacity boundary a *quality* boundary?
**The question.** Pre-register a dose–response experiment: replay or drive sessions at controlled context fractions (20 / 50 / 80 / 95 % of the native usable limit) and measure *accepted-outcome rate*, loop/recurrence (same-spec family depth from the control db, DLQ incidence), and realized cost — with the native boundary only as the reference line.
**Why the current set cannot yield this.** Every sibling reasons about the predicate *fits within capacity*; none instruments the construct that actually failed on 2026-09-13 (a session that kept accepting work and looping, not one that overflowed). B2 (c13) states the gap; c11 demands the counterfactual harm and the false-positive cost for every rule. The data already exist — the same-spec chain, 63 failed story / 106 failed analysis / 34 `fleet_jobs` — but no experiment has been posed against them. If quality is flat below the native boundary, the 80 % advisory is safe; if it degrades well before, the capacity policy has traded a measured false positive (172,491 at `ses_f5add1095ffe1ZDEm4YJZJLbwy`) for an unmeasured false negative and the gate needs a quality term again.

### Q-B — Can the machine reproduce the controller's oracle?
**The question.** Build the standing differential interrogator and test whether it can find, without a human, what the controller found by hand: on every check, diff `resolve_capacity()` against `opencode models <provider> --verbose`; generate adversarial inputs (config files exercising `OPENCODE_CONFIG` order, partial-`output` overrides, JSONC trailing commas; usage shapes testing the missing-`total` sum; message sequences containing completed/pending compaction summaries) and compare our classification to the runtime's own `Dl`/`Is` and to a native export/import snapshot (`c50f37cfff42523b`). Score detector recall against the reviewer's five findings.
**Why the current set cannot yield this.** The set's consensus — "consume the authority" — is a design principle, never tested as a *detector*; the existing tests still run against fixtures authored from the same model (c13: "a no-change verdict from a small task inside my own test design"). `7948b8ace287e881` says prose arms don't move accepted outcomes; the only untested path is executable, boundary-level detection. If a differential oracle recovers the five findings automatically, the human review is a redundant (if currently necessary) cost; if it cannot, we have bounded what only human attention can do — which is itself a high-value result.

*(Runner-up, folded into Q-B: a durable effect-receipt requirement for every control action, extending the `_recover_processing` pattern from submits to `restart`/`scale`/`drain` so the swallowed-restart class cannot recur silently.)*

## 4. The single synthesis insight no individual sibling could produce

**The adjacent-quantity law, with its executable corollary.**

Every failure in this arc — and most of the fan-out's proposed remedies — substituted a cheap adjacent quantity for the authority's own output: 200,000 for capacity; a config re-derivation for the runtime's loader; a reasoning-augmented sum for the runtime's sum; a compaction summary's generation usage for the context; an empty queue for a completed dispatch; ten green checks for correct behaviour; `merged` for `running`; a reservation for a realized cost; and — the fan-out's own proposal space — prose records for enforced mechanisms.

The repairs that *held* are exactly those where the local quantity was replaced by a **diff against the authority**: parse `opencode models --verbose` instead of re-deriving; skip `he.summary !== true` because the runtime does; use `total || input+output+cache.read+cache.write` because `Dl` does; require the run row, not the acceptance line. That yields the corollary the set never states: **a deliberation's durable output is only what can be written as an authority diff — an executable oracle — not what it argues in prose.** The fan-out is overwhelmingly prose, and by `7948b8ace287e881` its expected accepted-outcome delta is approximately zero; its value is bounded to the two questions above and to the robustness signal of weak correlation. No single sibling could see this because each analyzed one lens and one repair; only the cross-read shows the invariant — and it indicts the practice that produced it.

## 5. Was the contemplation practice worth its cost?

**Costs.** Sixteen full-context samples of the entire history; per `7948b8ace287e881` cache runs 95.5–97.9 % warm and `c50f37cfff42523b` shows a seed→branches run at $0.004735, so the marginal *dollars* are small; the real costs are latency, context-window pressure (the session itself sat at ~431,754 / 968,000 at close), and the opportunity cost of the controller's attention to read the output.

**Benefits.** (i) Weak, correlated convergence on three design lessons (authority, fixtures, receipts) — useful as a cross-check, not as evidence. (ii) Two genuinely new, executable research questions (Q-A, Q-B). (iii) A handful of precise discriminations (actuator honesty; hazard vs. sensor-unavailable; the fixture-mask mechanism). (iv) Zero executable artifacts, by construction.

**Score: ~1 of 5 on the accepted-outcome metric; 3 of 5 as a question generator.** It is cost-justified *only* if its new questions are turned into executable oracles, which is Q-B. Against `7948b8ace287e881`, sixteen more paragraphs about the same five lessons should not be expected to move outcomes.

**What would change the answer.** (1) If each lens had to emit a *pre-registered falsifier plus the harness that runs it* — deliberation becomes mechanism. (2) If the sixteen were truly independent (different model families/architectures) rather than one model's correlated samples — then convergence would be evidence and divergence would be informative. (3) If the scoring were on terminal run outcomes and realized cost rather than gate transitions. (4) If one differential harness over the authority could recover the controller's five findings automatically, the fan-out becomes redundant for this class of problem. Operationally: require ≥ 1 surviving executable artifact or one new falsifiable question per wave, else replace the wave with a single authority-diff harness.

## 6. One falsifier for the leading claim

**Falsifier.** Take any incident in which the local measure *equalled the authority's own output* and the decision was still wrong. Concretely: mirror the runtime exactly (`he.summary !== true`, the `Dl` sum, `Is`'s threshold), then reproduce the completed-compaction-plus-pending-resumed-turn state. If the gate still returns `COMPACT`/refuses — i.e., if authority-matching is not sufficient to fix the P1 class — then "the failure was adjacent-quantity substitution, and the authority diff is the load-bearing fix" is false. Conversely, if the authority-matching fix holds (as the regression `test_a_completed_compaction_allows_the_first_resumed_submission` currently shows) and the arc's final act still fails at `p1c_contract_gate`/`p6g_acceptance`, then the claim is exposed as *necessary but not sufficient*: the authority diff is the right instrument, and it has no purchase on a run that never reached its effect.
