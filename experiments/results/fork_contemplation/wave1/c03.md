# Contemplation — the feedback loops that governed this work

**Scope note (verbose mode).** Analysis only; no files touched, no commands run. Every claim below is anchored to a named moment in the working history or to a named KB finding. I route first across seven lenses (divergence preserved), then synthesize. The format deliberately keeps the *conflicts* visible, because the useful signal in this material is where the loops disagreed with each other.

## Lens 1 — Control theory

**Take.** The AIO session is a setpoint-tracking system. The operator's directive was the setpoint ("use the active model's real capacity"), the AIO's behavior was the plant, the budget check was the inner controller, and the controller's review was the outer supervisory loop. The original inner controller had a **mis-scaled sensor**, not a mis-tuned gain: `DEFAULT_CTX_BUDGET = 200_000` and `DEFAULT_TURN_BUDGET = 80` in `scripts/session_budget.py` against a plant whose real ceiling (`deepseek/deepseek-v4-flash`, effective 968,000) is ~5× larger. The result was a steady-state error: 172,491 read as a violation (`ses_f5add1095ffe…` WARN, and the Control Room submit refused) while the runtime would have allowed it.

**Damping.** Making the 80% warning *advisory* removed a relay-like nonlinearity. A hard WARN at 0.8× a wrong threshold produces chattering near the threshold — work/stop/work/stop — which is exactly the pathology the operator's item 3 names. Turning turns into telemetry removed a second relay (the 80-message trip).

**Amplifying / oscillation.** The `summary`-as-context sensor had *positive* feedback in the pathological region: a successful compaction *raised* the measured context (the summary generation call carries the old conversation's usage), which demanded more compaction (block), which could not lower the reading — a compressor stall. The controller's reproduction (975K/COMPACT after a successful compaction) is that stall, and the fix (`he.summary !== true`, mirroring the runtime's own guard) is the anti-windup.

**Discriminating test.** Step response: inject a post-compaction state and measure whether the inner loop settles to OK or chatters on COMPACT. It now settles (`test_a_completed_compaction_allows_the_first_resumed_submission`).

## Lens 2 — Distributed systems

**Take.** There were **two authorities** on one fact (the usable limit): a local Python re-derivation and the opencode runtime — no consensus protocol, i.e. split-brain. The controller stated the principle exactly: "sharing one Python helper does not establish one authority if that helper disagrees with OpenCode." The fix is single-writer: consume `opencode models <provider> --verbose` first, keep the catalog+config reader only as a declared fallback.

The same failure family recurs in dispatch. The first `fleet_manager restart --service workflow-runner` was **acknowledged without effect**: the queue drained and the processing lane emptied, but no `docker compose` line appeared and the PID was unchanged. Acceptance ≠ propagation. The re-issue through the documented broker seam produced the effect ack (`Restarting infrastructure_workflow-runner_1 ... done`, PID 883849). KB `6ef9bf9b6ef3b53a` is the same shape one level down: goals ride argv (newlines refused) and **untracked specs never reach run clones** — a submit can be "accepted" while the run cannot see its spec. And the native tool's own receipt says it plainly: "A queued submit is NOT a running run — verify the run row exists."

**Discriminating test.** Partition test: fail/slow the runtime CLI and check whether the fallback *converges* to the same limit or silently diverges. The tests now cover failing and garbage CLI output falling back to the fixture catalog.

## Lens 3 — Measurement epistemology

**Take.** The budget number is a proxy for an unobservable (will the next model call fit?). Construct validity failed on **three independent axes simultaneously** — the *limit* (config precedence/merge/JSONC), the *accounting* (`reasoning` illegally added to the missing-`total` sum: 955K native vs 975K local), and the *state* (the summary's generation usage read as the new context). Each was internally consistent; the local model was coherent and wrong.

This is precisely KB `c50f37cfff42523b`: row-level extraction of frozen sessions **lost auxiliary rows** and refused to fork, while the native `opencode export/import` round-trip preserved the session. Fidelity came from the native path, not from a hand-rolled reconstruction. My config reader was the row-level extraction; `opencode models --verbose` is the round-trip.

**Discriminating test.** Inter-method agreement: compare the check's token count and threshold to the runtime's own overflow decision on identical sessions. Disagreement means the construct is invalid, regardless of how green the tests are.

## Lens 4 — Safety engineering

**Take.** The gate is a safety interlock with asymmetric failures. **False block** stalls the principal's goal (cheap, visible, and *named* — it is precisely why this task existed). **False allow** lets context overrun (the 698K / 25-hour incident). The "never fabricated OK" rule is fail-safe design, and I preserved it: `UNJUDGED` still blocks; the post-compaction `OK` is a **named, bounded exception** (like the initial-session exception), not a default.

The exit-3 control envelope was a **fail-open**: `read_control_packet` matched on `schema == "control-status/v1"` alone, so the CLI's no-database error envelope rendered as an *observed* empty packet (`epoch None, active 0`) — empty passed for missing. That is the safety violation the contract itself forbids; the fix requires the full body (`control_epoch` present, no `error`).

**Discriminating test.** Fault injection across the boundary: corrupt DB, missing catalog, pending-only usage, runtime CLI down, unbound/nonexistent session. Every one must yield a named non-OK (or the defined exception) — never OK. `test_a_corrupt_database_is_unjudged_and_the_cli_still_emits_json` closes the crash-to-fail-open path.

## Lens 5 — Organizational economics

**Take.** Principal (operator) delegates to agent (AIO); verification is costly, so the principal *samples* (review) while the agent self-reports via tests. The agency problem is visible: my full green suite was **cheaper and more self-interested** than the controller's independent reproduction, and the latter found five defects — including the P1 — that my suite had encoded as correct. The marginal verification value sat entirely with the principal.

The cost asymmetry is explicit in the operator's framing: "Dollar budgets, admission leases and controller approval gates retain their existing rules" — the context budget is a *liveness* instrument, the dollar budget a *spend* instrument, and they must not be conflated. The policy override `FINOPS_SESSION_CTX_LIMIT` initially conflated them: I let a local cap emit `COMPACT`, a claim about a native mechanism that does not exist at that cap. The correction to a clamped **policy CLOSE** restores the distinction (a policy cap is not a native trigger).

**Discriminating test.** Cost-of-verification: remove the principal's review and price the expected loss. Here it is the entire 8-hour continuation: the P1 would have shipped and the resumed submit would have been refused — the exact outcome the task was chartered to remove.

## Lens 6 — Evolutionary dynamics

**Take.** Variation (my designs) → selection (CI, review, the live submit) → retention (merged commits `9ae173419`, `d2aef3be3`, `4c3c6cdf0`, then `c8acc4d8c`). The fitness function was **partly private**: my tests selected for my model of the runtime, i.e. selection toward a local optimum. The operator's review supplied an exogenous pressure that the private landscape could not generate.

KB `7948b8ace287e881` is the selection result that matters here: across the prompt-branch pilot, **no instruction arm improved accepted outcomes; baseline was cost-minimal**. Translation for this session: my rewrite of `agent_config/agents/aio-control.md` rule 6 is **exhortation**, a weak selection axis. The mechanism — the shared resolver, the gate matrix, the runtime CLI — is the strong axis. This is the sharpest warning in the material: do not mistake the regenerated surfaces (exhortation) for the delivery (mechanism).

**Discriminating test.** Vary instruction vs mechanism and measure accepted outcomes. The KB already ran it: instruction variation did not move acceptance; mechanism differences did.

## Lens 7 — Game theory

**Take.** Cheap talk vs costly signals. The AIO's PR is cheap talk until CI and review make it costly; the operator's merge (`c8acc4d8c`) is the costly signal; the runtime's `models --verbose` output is a costly, hard-to-forge fact. The binding design is good mechanism design precisely because the backend **re-resolves** the claimed `binding_id` from the durable store instead of trusting the claim — and my attached `fbca5106…` at `task_revision 2` was re-resolved by the broker before the compose call, as the accepted receipt shows.

The swallowed restart was a cheap-signal failure: "queue emptied" is cheap talk about a restart. Only the compose log and the new PID were costly evidence. The submission's durability was similarly proven by a costly signal — `run-0da5271bc0cb` in the control DB *and* the `p1b_gate_first_viewport` sibling cell carrying its actual lease (`bud_afacee0f57e647b5`), not by the tool's "accepted" string.

**Discriminating test.** Signaling test: remove the independent reproduction and see whether cheap signals predict runtime behavior. They did not (green suite vs five real defects).

## Synthesis — the loop map

| Loop | Sign | Delay | Where it helped | Where it oscillated / failed |
|---|---|---|---|---|
| Operator steering (task → review → merge) | Corrective (negative), high gain | Hours | Produced the policy change; 5 targeted fixes; converged, no over-correction | Would stall if over-gained; the original directive arrived while code + docs disagreed |

| Cost/budget visibility (leases, context) | Negative, gated | Real-time to minutes | Admission lease armed the p1b cell (reserve 0.6 / cap 1.0); the 6-item verification oracle | Coarse provenance (`cost_source=estimated`); context proxy easily mistaken for cost |

The conflicts worth preserving: the **operator loop** is the detector that made the fixes happen, but it is low-frequency; the **runtime-authority loop** is the bias source and it fires on *every* verdict. The **self-test oracle** is the most dangerous loop in the set because it looks like verification while being self-confirmation. The **exhortation** channel (rule 6, docs) is the weakest, per KB `7948b8ace287e881`.

## The single loop that changes the most downstream behavior

**The local-budget ↔ runtime-compaction measurement loop.** Closing it to one authority — `opencode models --verbose` plus the runtime's own overflow expression and its `summary !== true` guard — is the highest-leverage move because it is the *sign* of the gate's output that routes every consequential AIO action (submit / continue / compact / close), and it fires on every turn. Left open, it is a bias integrator: the check accumulates a measure the runtime disagrees with and issues a terminal verdict with no error signal, which is why one summary message could refuse a valid submission (`975K/COMPACT`) and why a project-only `output` override could silently discard an inherited `context`. The operator's review *detected* this; it did not *cause* most of the downstream behavior — the inner loop's sign does.

## One falsifier for that leading claim

**Verdict-difference rate.** Replay the actual AIO session history through both gates: the open one (local re-derivation, as at the parent of `9ae173419`) and the closed one (runtime authority). Count the turns where the two produce **different decisions on a consequential action** (a submit allowed vs blocked, a close vs continue), and weight by whether a submit was actually pending. If that rate is effectively zero — i.e., the AIO never re-read inside the post-compaction window and every measured context stayed below the native boundary, so the open and closed loops would have allowed the same submission — then closing the measurement loop changed no downstream action, and the **operator-review loop** (whose single veto would have stopped `run-0da5271bc0cb` from ever being submitted) must be the dominant one instead. The claim stands only if the open loop demonstrably flips at least one real, consequential decision; the controller's 975K reproduction is the standing evidence that it does — but it is one point, and a difference-rate near zero over the full history would overturn "most downstream."
