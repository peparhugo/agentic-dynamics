**Reasoning for the shape of this answer.** The request asks for trajectory-changing, failure-class-eliminating changes, ranked by evidence strength, grounded in this session's moments. I deliberately separate *divergence* (independent expert lenses, each allowed to disagree) from *synthesis* (the ranked set), because the strongest lesson of the evidence is that early convergence on one model of the world is exactly what failed. ## 1. Seven lenses, independently

### Lens A — Control theory
**Take.** The budget gate was a controller with a wrong plant model: it regulated a 200,000-token setpoint while the plant (deepseek-v4-flash, resolved by opencode 1.18.15) had a 968,000-token usable range. At 172,491 tokens it tripped "WARN" and refused the Control Room submit (`control-room-instrument-cont-submit`). The correction is adaptive control: read the plant's actual limits each sample and lower the trip to a genuine interlock.
**Moment.** The review's "override" finding is a control-inversion bug: `FINOPS_SESSION_CTX_LIMIT=100K` returned `COMPACT`, i.e. it commanded an actuator (native compaction) that only fires at the native threshold. Commanding an actuator you do not own is the classic inversion; the fix (clamp to native, policy `CLOSE`) restores actuator authority.
**Divergence.** A controller that adapts its setpoint from a slow subprocess (the 2s `opencode models` probe) trades stability for accuracy; the fixed constant was stable but wrong. Control theory prefers slow-but-authoritative feedback over fast-but-fictional feedback.
**Discriminating test.** Step response to a model switch (1M → 200K → 160K) must change the verdict within one sample — `test_switching_to_a_smaller_model_updates_the_limit`.

### Lens B — Distributed systems
**Take.** Capsule, CLI, and broker are three replicas of one predicate; the review proved they could diverge. A corrupt database made the backend return `UNJUDGED` while the CLI crashed (finding 5), and the config reader resolved a different precedence than the opencode replica (finding 2). The controller's sentence — *"sharing one Python helper does not establish one authority if that helper disagrees with OpenCode"* — is a consistency-model claim: the helper was a stale replica of the runtime's state machine.
**Moment.** The restart that vanished is the same disease in the control plane: `fleet_manager restart --service workflow-runner` was claimed (queue emptied, processing lane empty) yet no compose record, no journal line, unchanged PID. The control plane had an unobserved write path; "queue empty" is an availability illusion.
**Divergence.** Pure single-authority (always shell to the runtime) maximizes correctness but creates a new single point of failure; the two-tier host/container split is the deliberate concession.
**Discriminating test.** Kill the authority and assert every replica emits the same *named* downgrade — the existing defer/strict test pair is the seed of this.

### Lens C — Measurement epistemology
**Take.** The compaction bug is a construct-validity failure, not a coding slip. The summary message's `tokens` measure the *summary-generation call over the old conversation*; my check read that number as the *new context*. The measurement was real and measured the wrong construct. The controller's reproduction (975K/COMPACT after a successful compaction + pending resumed turn) is the experiment that disconfirmed my construct; the runtime's own run loop (`he.summary !== true`) was the authority I should have consulted before designing.
**Moment.** The 955K-vs-975K divergence is instrument miscalibration: I added `reasoning` to a sum the runtime never includes.
**Divergence.** "Measure the runtime's state" wants fidelity; "measure what the operator cares about" wants the session's *effective* predicate. The review resolved it in favor of fidelity — correctly, because the predicate acts on the runtime.
**Discriminating test.** A fixture with realistic summary magnitude and a pending resumed turn; my original small-summary fixture had no power to detect the bug (the reviewer said so explicitly).

### Lens D — Safety engineering
**Take.** The old policy conflated an alarm with a trip. The change demotes the 80% warning to an alarm, keeps `COMPACT`/`CLOSE`/`UNJUDGED` as interlocks, and adds a hard-limit backstop. This is the standard alarm/interlock separation.
**Moment.** `UNJUDGED` must never be permission, and a fallback read must be *visibly degraded* — otherwise the catalog fallback becomes a de-facto interlock bypass. The corrupt-DB fix (structured `UNJUDGED` in both CLI and gate) and the policy-cap `CLOSE` are fail-closed choices.
**Divergence.** De-sensitizing WARN is real risk: if the 80% alarm was load-bearing containment, removing the trip increases exposure. The compensating control is native `COMPACT` plus the hard `CLOSE`.
**Discriminating test.** Compaction disabled + over-capacity must `CLOSE`; a policy cap must `CLOSE`, never falsely `COMPACT`.

### Lens E — Organizational economics
**Take.** The controller's independent reproduction produced five real defects; my twenty-plus tests produced none of them. Verification is a principal–agent problem: the author's tests encode the author's misunderstanding. The project already practices separation of powers at the launch boundary (the plugin's *"convenience only"* early check versus the backend gate; the close record's *never self-approve*). That separation is missing at the **semantic-fidelity** boundary.
**Moment.** The pilot finding `7948b8ace287e881` is an economic result: no instruction arm improved accepted outcomes, baseline cost-minimal. Marginal returns to instruction/prompt spend are near zero; returns accrue to verification and enforcement.
**Divergence.** Reproduction is expensive and can bottleneck; the pilot says instruction spend is nearly free but inert. The evidence favors buying verification.
**Discriminating test.** Measure defects caught per review-hour versus per author-test-hour on the next semantics-bearing change.

### Lens F — Evolutionary dynamics
**Take.** The fleet selects on reproducibility and cache: Docker forks went 47% cold → 90% warm at $0.004735 (`c50f37cfff42523b`). Traits that don't cross the boundary don't replicate. `6ef9bf9b6ef3b53a` (untracked specs never reach run clones; goals ride argv, newlines refused) means untracked behavior is invisible to selection — the six untracked `control_room_*.yaml` currently in the main checkout are precisely a phenotype that cannot replicate.
**Moment.** The native session export/import result in `c50f...` (a native round-trip preserves sessions where hand-rolled row extraction lost auxiliary rows) is the same lesson as the capacity port: use the host's own serialization to reproduce.
**Divergence.** Evolution also selects cheap compliance over expensive enforcement, so the interlock must live in the replicating path (the backend), not the convenience layer.
**Discriminating test.** Materialize untracked inputs and verify the run clone reproduces the exact digest; if not, the run is non-heritable.

### Lens G — Game theory
**Take.** An agent optimizing for "task complete" is incentivized to satisfy the letter of a check and to claim delivery before the authority agrees. The `FINOPS_SESSION_CTX_LIMIT` behavior was cheap talk: a signal (COMPACT) not backed by the actuator. The submit boundary has a commons problem — each run benefits from reading host-local state, but the class loses reproducibility; a manifest makes defection detectable.
**Moment.** The plugin's early refusal is the cheap signal; the broker's strict re-validation is the costly, credible commitment. The close record's *never self-approve* is a commitment device working as intended.
**Divergence.** Manifest enforcement raises friction (some legitimate host-local reads); a rubber-stamp manifest restores defection.
**Discriminating test.** Can a submit referencing a missing/untracked input pass the gate? If yes, the equilibrium is defection.

## 3. The smallest ranked set

**1. Authority-consumption contract with degraded verdicts (system + measurement).**  
*Mechanism:* every derived fact (model limits, context, packet state) must be resolved from the runtime's own artifact; when it cannot be, the verdict is a distinct degraded state (`UNJUDGED` or `authority: fallback`), never the same token as an authoritative verdict; plus a fidelity test that re-extracts the installed runtime's constants and fails on drift. *Evidence:* the five review reproductions; the `he.summary !== true` discovery; `c50f...`'s native-export result; *"one helper ≠ one authority."* *Cost:* subprocess/parse brittleness, a schema/consumer sweep. *Failure mode if wrong:* refusal storms when the runtime is flaky, and teams route around a brittle extractor. *Makes a class impossible:* silent divergence between our model and the runtime's.

**2. Content-addressed input manifest at every execution boundary (system).**  
*Mechanism:* every submit/fork carries hashes of all inputs (tracked and untracked), materializes them into the run root, and refuses otherwise. *Evidence:* `6ef9bf9b6ef3b53a` (untracked specs never reach clones; argv cannot carry newlines); the six untracked control-room specs in main today; `c50f...`'s row-extraction loss. *Cost:* hashing/materialization and cache invalidation. *Failure mode if wrong:* legitimate host-local reads break, or the manifest becomes a rubber stamp. *Makes a class impossible:* non-heritable runs and resumes that diff the wrong base.

**3. One canonical local CI entrypoint wired to the push boundary (process).**  
*Mechanism:* `make ci-local` runs the **exact** CI commands (whole-surface `ruff check .`, surfaces check, fast path, targeted), enforced by a pre-push hook. *Evidence:* `bc87e60af` — per-file ruff missed the `F401` in `core/__init__.py` that `ruff check .` caught in 14s. *Cost:* minutes per push, hook maintenance. *Failure mode if wrong:* `--no-verify` bypass or environment drift makes it theater. *Makes a class impossible:* "green locally, red in CI."

**4. Durable records for control actions (system + measurement).**  
*Mechanism:* scale/drain/restart emit a terminal board record carrying the broker's argv and return code; no silent control writes. *Evidence:* the swallowed `fleet_manager restart` (queue empty, processing empty, PID unchanged, journal silent); the successful seam call logged by compose. *Cost:* one write path. *Failure mode if wrong:* board noise, or the record write shares the failure and stays silent. *Makes a class impossible:* phantom operations and "queue-empty-as-success."

**5. Independent reproduction gate for semantics-bearing changes (process).**  
*Mechanism:* any change encoding a foreign system's behavior requires a second party's reproduction against the installed artifact before merge; the author cannot self-certify. *Evidence:* five controller findings versus zero from my tests; the low-power fixture the reviewer identified. *Cost:* latency plus a capable reviewer. *Failure mode if wrong:* bottleneck or rubber stamp; environment mismatch. *Makes a class impossible:* tests that encode the author's misunderstanding.

**Explicitly not proposed:** instruction/prompt arms. The pilot (`7948b8ace287e881`) already showed no instruction arm improved accepted outcomes, so prompt edits rank below boundary enforcement for trajectory change.

## 4. One falsifier for the leading claim

**Leading claim:** the dominant repeatable failure class here is divergence between a reimplemented model and the authority it models (runtime semantics, config precedence, input reachability); making the authority's own resolution the only admissible input — and making fallbacks visibly degraded — changes more trajectories than any prompt or speed change, because enforcement at the boundary makes the class impossible rather than making a task faster.

**Falsifier (single replay test):** replay all seven named incidents — the five review defects plus `6ef9bf9b6ef3b53a` and `c50f37cfff42523b` — against mechanisms (1) and (2). If **any one** incident survives both — i.e. it reproduces even with the runtime as sole authority and inputs content-addressed — then the root cause was not divergence/unreachability, the ranking above is wrong, and the dominant class lies elsewhere (most plausibly availability/friction or resource exhaustion).
