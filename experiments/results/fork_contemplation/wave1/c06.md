# Divergence first: seven lenses, each with its own verdict

**1. Control theory.** The budget check was an observer with a wrong process model: it commanded `CLOSE` at 172,491 while the plant’s native usable limit was 968,000 (policy constant vs. model capacity). The compaction case is textbook *aliasing*: the sensor read the actuator’s effort (the summary-generation call’s usage, 975K) instead of the resulting plant state, so it fired `COMPACT` after a successful compaction — the controller reproduced exactly this. Verdict: the missing thing is an *observer-agreement loop* (local estimate vs. the runtime’s own measurement, alarm on divergence). Discriminating test: inject a known 975K state plus a completed summary; assert local == native. We only ran that test after review, and it failed three times.

**2. Distributed systems.** Submission is at-least-once with no idempotency key; `run-0da5271bc0cb` resumes `run-dfa259243059`; the DLQ is a graveyard, not a detector. Worse, control actions leave no board record: the first `fleet_manager restart --service workflow-runner` was claimed, the queue drained, the processing lane emptied — and the container never restarted (I found this by PID/start-time). “Queue empty” was mistaken for “dispatch succeeded.” Verdict: missing exact-once/loop semantics plus control-action acknowledgment. Discriminating test: does `fleet:jobs` hold a record for every accepted control action? It does not — restart has none.

**3. Measurement epistemology.** The controller’s line is the thesis: *“sharing one Python helper does not establish one authority if that helper disagrees with OpenCode.”* The arc produced shadow measurements — my config reader vs. the runtime’s resolved CLI, reasoning-in-sum (975K) vs. the runtime’s sum (955K), summary cost vs. context, per-file ruff vs. whole-surface ruff. Verdict: the missing instrument is a *measurement contract* — every number must name its authoritative source and the observed divergence, and `UNJUDGED` is the honest absence. Discriminating test: measure the same state twice (local and native); any nonzero divergence makes the local number inadmissible.

**4. Safety engineering.** An interlock must be independent and proof-tested. The budget gate was a single, locally re-derived sensor (not independent), and the anti-repetition interlock is absent. The controller’s post-compaction reproduction *was* a proof test, and the layer failed it. Verdict: missing independent protection layer + proof-test interval; the raw material (`step_attempts.attempt_no`, `runs.family_id`) already exists and is unused as a safety input. Discriminating test: proof-test with the exact boundary state (post-compaction + pending turn) — now a regression, previously untested.

**5. Organizational economics.** Principal–agent: the controller measures acceptance, so the fleet optimizes acceptance. Cost is attributed as `estimated`; there is no P&L per accepted outcome. KB `7948b8ace287e881` says the marginal product of prompt work on acceptance was ~0 while cost was measured precisely — a fleet buying gate-passage at unpriced quality. Verdict: missing an attributed outcome P&L (accepted value vs. actual cost, by phase/family). Discriminating test: do `step_attempts.cost_usd` reconcile with the admission reservations at phase grain? In the arc, actuals never landed.

**6. Evolutionary dynamics.** Selection on “accepted” with no variation ledger means retries are indistinguishable from learning. KB `c50f37cfff42523b` (one seed → four isolated branches) was the arc’s only real variation instrument, and it was done in Docker, outside the production loop. Verdict: missing a *variation ledger* — the field-delta between consecutive attempts. Discriminating test: diff consecutive same-spec attempts (spec sha, candidate, model, prompt). If nothing materially changed, it is a loop, not an experiment.

**7. Game theory.** Where the metric is the target, the cheapest moves are: declare admission `estimated`; produce gate-satisfying evidence (the *same* agent family prepares the p6g acceptance package); pick the token measure that makes the verdict pass. The arc’s rule “never self-approve” exists, but no instrument enforces independence. Verdict: missing an adversarial-verification record (author vs. signer). Discriminating test: if author and signer share a principal/family, the evidence is inadmissible.

**Where the lenses conflict.** Control theory, distributed systems, and evolutionary dynamics all say *recurrence*; epistemology and safety say *authority-agreement / proof tests*; economics and game theory say *attribution and independence*. That is a real fork, and it resolves only on one question: which instrument, if present, would have prevented the arc’s most damaging event — the 25-hour session and the repeated same-spec failure chain, or the wrong-capacity refusal? The refusal was caught by a human reviewer within one round; the recurrence ran for six hours and is still running. The discriminating test is the next section’s falsifier.

# Synthesis: the single most consequential missing instrument

**The Attempt-Recurrence Interlock (ARI).** Not a new metric — a *detector over data the fleet already writes*. Here is the concrete spec, with the design reasoning inline.

```python
"""
ARI — the Attempt-Recurrence Interlock.

WHY THIS ONE: recurrence is the only quantity in the four-axis taxonomy that is measured
NOWHERE. Acceptance, cost, and verification are all instrumented at least partially (CI,
admission leases, spec digests). Recurrence is invisible: `runs.family_id` and
`step_attempts.attempt_no` are recorded but never consumed as a signal, and the arc's final
act — resubmitting run-dfa259243059 as run-0da5271bc0cb — happened with no instrument able to
say "attempt N of a failing family". A wrong quantity can be corrected by review; an absent
quantity cannot.
"""
```

**What it records — the `recurrence_receipt` (one per terminal attempt):**

```python
receipt = {
    # The key is CANONICAL, not free text: the goal string is deliberately excluded, or every
    # cosmetic rephrase resets the count (see gaming, below).
    "recurrence_key": {
        "spec_name":     spec_name,        # e.g. "control_room_instrument_build"
        "spec_sha256":   spec_digest,      # the digest the broker already validates (caf1eb6b…)
        "phase":         phase_id,         # attempt grain: step, not run
        "model":         model,            # deepseek/deepseek-v4-flash
        "failure_sig":   normalized(error),# normalized error class/message, not the stack text
    },
    "lineage": {                           # how this attempt is related to prior ones
        "family_id":   family_id,          # already in the `runs` schema — currently unused
        "parent_run_id": parent_run_id,    # e.g. run-dfa259243059
        "run_id":      run_id,
    },
    "ordinal": {                           # the actual counter
        "attempt":     attempt_no,         # 1-based within the rolling window
        "since_first_s": elapsed_seconds,
        "outcome_chain": ["failed", "cancelled", "failed", "failed"],  # cancellations COUNT
    },
    "delta_from_previous": {               # the variation ledger (lens 6): what changed?
        "spec_sha256_changed": bool,
        "candidate_sha_changed": bool,
        "model_changed": bool,
        "prompt_hash_changed": bool,       # if all False -> it is a loop, not an experiment
    },
    "interlock": "fresh" | "repeat" | "escalated",  # the signal the controller reads
}
```

**When it fires (trigger points) — and why there:**

```python
# 1. At SUBMIT ADMISSION, before the LPUSH. Rationale: recurrence must be visible BEFORE
#    money is reserved and a container exists (run-dfa259243059 → run-0da5271bc0cb was a
#    resubmit; the interlock should have required a named reason for attempt N).
# 2. At every TERMINAL TRANSITION the control db already records — run terminal state
#    (completed/failed/cancelled) and step_attempts terminal (the writer that bumps the
#    control epoch, e4). Rationale: zero new write path; the instrument is a pure consumer.
# 3. At APPROVAL-READY (p1c/p6g checkpoints). Rationale: the second approval gate is where a
#    recurring family should be escalated to the principal, not silently retried.
```

**From which source (authority):**

```python
sources = [
    "control.db:runs(run_id, spec_name, parent_run_id, family_id, candidate_sha, state, cost_usd)",
    "control.db:step_attempts(attempt_no, state, error, cost_usd)",   # attempt grain + real cost
    "fleet:jobs / fleet_jobs DLQ",                                    # transport-level attempts
    "the submit's spec_sha256",                                       # canonical identity, not goal text
]
# WHY THESE: they are the transition writer's own outputs, authoritative and already durable.
# No new sensor, no shadow re-derivation — the lesson of finding #2 (authority agreement).
```

**Failure mode — what gaming it invites, and the mitigations baked in:**

```python
gaming_vectors = {
    # THE OBVIOUS ONE: fragment the key so "attempt 4" reads as "attempt 1".
    "cosmetic_resubmission": "rephrase the goal / flip a comment to change the spec digest",
    # -> mitigation: exclude the goal string; key on spec digest + lineage + normalized failure;
    #    if the digest changed but the DELTA is semantically empty, mark "fresh-but-near-identical".
    "phase_fission": "split one failing phase into two to reset attempt_no",
    # -> mitigation: count at the RUN/family grain as well as the step grain.
    "lineage_laundering": "spawn a child session / new family_id to reset the counter",
    # -> mitigation: carry ancestry across session bindings (the AIO binding already has
    #    predecessor + family continuity).
    "cancel_before_terminal_failure": "cancel so the failure signature never lands",
    # -> mitigation: cancellations count as attempts (outcome_chain above).
    "weak_gate_acceptance": "declare success at the cheapest gate to close the family",
    # -> mitigation: the interlock reads the FINAL gate (p6g), not intermediate greens.
}
# The interlock's output is a REVIEW REQUIREMENT (a controller-signed waiver to exceed N),
# never an automatic retry. Gaming must be made expensive and ATTRIBUTED, not merely logged —
# otherwise the metric becomes the target (lens 7).
```

**The discriminating test versus the runner-up.** The runner-up is the acceptance-quality instrument (an attributed outcome P&L independent of the gate). Run the ARI key and threshold over the existing control db: if it flags the `f344c4b99162 → f52d829af58e → 1c341d58af27 → b787b0d16d6c → dfa259243059 → 0da5271bc0cb` chain (and the 63/106 DLQ clusters), recurrence is the missing instrument. If it flags nothing because those attempts are genuinely distinct experiments, then variation is real and the missing instrument is the independent quality measure. That single replay decides the fork.

**Falsifier for the leading claim.** Replay the ARI over the recorded history. If every consecutive same-spec attempt differs materially in `spec_sha256`, phase set, candidate sha, model, and failure signature — i.e., the interlock would have fired **zero** times and the six attempts are six distinct experiments — then my claim (“recurrence is the most consequential missing instrument”) is false, and the correct conclusion is that the fleet is not looping but failing to measure the quality of what it accepts; the missing instrument is then the attributed outcome-quality ledger, not the interlock.
