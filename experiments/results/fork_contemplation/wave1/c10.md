## Part 1 — Seven lenses, kept independent, conflicts left visible

### Lens 1: Control theory (setpoint vs plant capacity)
**Take.** The session budget was a fixed-setpoint controller whose plant had a much larger true capacity (200,000 setpoint; deepseek-v4-flash resolves to a 968,000-token usable boundary). The correction swapped in a measured setpoint (runtime-CLI-first resolution). But the controller's *actuator* is still asymmetric: returning `COMPACT` does not itself actuate compaction — the runtime actuates it, at its own threshold. The reviewer's finding #4 named exactly this: a `FINOPS_SESSION_CTX_LIMIT` of 100K "returned COMPACT even when native compaction starts at 968K." A controller that reports a setpoint it cannot actuate is describing, not controlling.
**Grounding moment.** `session_capacity.classify()` now emits a policy `CLOSE` rather than a false `COMPACT` when the cap is below native — the actuator distinction was made explicit in `9ae173419`.
**Discriminating test.** Step-response: inject context past the boundary and count *actual native compaction events* versus *verdicts*. If verdicts fire without compactions (or vice versa), the controller is not controlling the plant.

### Lens 2: Distributed systems (who is the authority?)
**Take.** The reviewer's architectural sentence — *"sharing one Python helper does not establish one authority if that helper disagrees with OpenCode"* — is a consensus problem. The original helper was a second implementation of the runtime's config load order, and it lost: `OPENCODE_CONFIG` precedence inverted, partial `output` overrides discarding inherited `context`, JSONC trailing commas silently dropped. The fix made the runtime CLI the leader (`opencode models <provider> --verbose`) and demoted the catalog reader to a documented follower. Separately, the swallowed `fleet_manager restart` — the command was claimed, the claim lane emptied, but compose never ran and control actions leave **no board record** — is a lost control message masquerading as delivery.
**Grounding moments.** `9ae173419` (authority) and the reload episode at 01:59–02:02 (a queue that is empty is not a dispatch that succeeded).
**Discriminating test.** Run the same submit through CLI, capsule, container gate, and strict host broker and diff the verdicts. The container's defer-to-host behavior is the one legitimate split; any other disagreement is a consistency bug.

### Lens 3: Measurement epistemology (the measure must match the measured system)
**Take.** Two reproducible measurement errors were live: the missing-`total` sum added `reasoning` (955K native vs 975K local), and the post-compaction state read the summary-generation call's usage as the new context (a quantity that no longer exists — the old conversation's size). The runtime's own loop skips `he.summary !== true`; therefore the observer had to skip it too. Measurement must be the *system's* definition, not an adjacent one.
**Grounding moments.** The reviewer's P1 post-compaction reproduction (975K/`COMPACT` after a successful compaction) and the P2 token-accounting divergence; fixed and regression-tested in `9ae173419`/`d2aef3be3`.
**Discriminating test.** Feed identical usage samples through runtime and helper; any non-zero delta on the same sample falsifies "we measure what the runtime measures."

### Lens 4: Safety engineering (fail-closed, and which failure is worse?)
**Take.** The budget gate is a safety interlock with two failure modes: *dangerous permission* (a fabricated `OK` when context is unmeasurable) and *liveness loss* (a false `CLOSE`/`WARN` refusal). The old policy optimized the wrong side: it produced a false refusal at 172,491 while the real capacity was 968K, and it would have closed the 25-hour/698K session only after context was already pathological. The correction keeps `UNJUDGED` non-permissive, adds a named post-compaction exception, and — importantly — fixed the corrupt-database crash (a safety hole where the CLI crashed but the gate returned `UNJUDGED`).
**Grounding moments.** `close:session_ingestion`'s pending-zero rule (Astra, 2026-09-14) and the reviewer's P2 corrupt-db finding.
**Discriminating test.** Fault injection: corrupt DB, pending-only samples, missing catalog, model with `context: 0`. Assert none yields `OK`.

### Lens 5: Organizational economics (operator attention is the scarce resource)
**Take.** Every premature close is a handoff; every handoff costs operator attention and re-orientation. The 7 promotables waiting in `safe_actions` are already a queue of attention. The old WARN created a perverse incentive documented in the close record itself: a fresh session "crosses the 160k WARN threshold in one deep-reading turn" — i.e., the policy punished the deep investigation the AIO exists to do. Advisory WARN removes that tax.
**Grounding moment.** The first capsule of this session carried `session budget: WARN (turns 37, context 185657)` while the same turn's work was entirely legitimate.
**Discriminating test.** Count operator touches per accepted outcome before/after; if advisory WARN reduces touches without raising violation rate, the policy buys attention at no safety cost.

### Lens 6: Evolutionary dynamics (the fleet is a population; cache is inheritance)
**Take.** The ladder is a population of forks under selection by acceptance and cost. The known finding `c50f37cfff42523b` (one seed → four isolated branches; cache 47% cold → 90% warm; $0.004735) is a fitness landscape result: warm lineage is cheap, cold fork is expensive, and the inherited-session state is the genome. Fixed 200K/80 was a local optimum the environment outgrew once contexts became 5× larger. The prompt-branch pilot (`7948b8ace287e881`) showed instruction mutations are nearly neutral (no arm improved accepted outcomes) — i.e., the population's fitness is dominated by *mechanism*, not *prompt*.
**Grounding moment.** The pilot's finding plus the correction's mechanism change.
**Discriminating test.** Fitness = accepted outcomes per dollar. Does the capacity+compaction genotype invade the fixed-policy niche at equal cache warmth?

### Lens 7: Game theory (the gate is a mechanism design problem)
**Take.** The AIO wants to proceed; the operator wants safety; the gate sets the equilibrium. A gate that refuses at an arbitrary 80% of an inherited constant creates an off-equilibrium incentive to avoid context (read less, investigate less). An advisory WARN plus a real boundary moves the equilibrium toward honest work with a genuine stop at capacity. The live submission is the mechanism working: the same submit that was refused pre-merge was *accepted* post-merge (`1fddc5861ac6`), and the run is real (`run-0da5271bc0cb`).
**Discriminating test.** Compare "deep-reading turns per task" and "refusals per accepted outcome" across the two mechanisms; a mechanism that suppresses investigation is dominated.

### Visible conflicts (do not reconcile them away)
1. **Control theory vs safety engineering.** Tighter margins are safer but cost handoffs; the trade is exactly the frontier the experiment must measure. Discriminating test: cost per accepted outcome *plotted against* violation rate (fabricated-OK + binding loss).
2. **Measurement epistemology vs distributed systems.** When the runtime is unavailable (containers), epistemology says "unmeasured → UNJUDGED"; distributed systems says "defer to the authority that owns the DB." The accepted resolution (container defers, strict broker measures) is a compromise, not a theorem. Discriminating test: the cross-surface verdict diff.
3. **Evolutionary dynamics vs organizational economics.** Evolution wants many cheap arms; economics says operator attention and dollars are capped. Discriminating test: marginal information per dollar at the interim look.

## Part 2 — The one controlled experiment

### Name
**CAP-BOUNDARY-1: does capacity-derived context management with native compaction improve continuation outcomes at equal cost?**

### Question (leading hypothesis H1)
For continuation-sensitive, checkpointed builds, does capacity-derived budgeting with native compaction at the true usable boundary (arm A1) raise the rate at which a resumed task reaches its declared acceptance oracle, versus the fixed 200K/80 close-and-handoff policy (A0), without raising cost per accepted outcome?
Secondary: is any effect caused by **native compaction continuity** or merely by the **larger capacity** (isolated by A2)?

### Task family
Two strata, one family — *checkpointed continuation builds*:
- **Stratum B (boundary stratum, high exposure, cheap).** Native-exported frozen session snapshots, forked and driven to the boundary, then asked to complete a fixed mechanical canary continuation. Rationale: this is where the mechanism is actually exercised; it is cheap enough to power, and it uses the round-trip that preserves sessions (the Docker row-level fork that "refused to fork" is explicitly **excluded** — known finding).
- **Stratum R (run stratum, confirmatory).** Full continuation runs of the anchor spec `control_room_instrument_build` (39 phases; checkpoints `p1c_contract_gate`, `p6g_acceptance`) plus 2–3 companion specs of comparable length, all resumed from real parents. Rationale: this is the actual deliverable class; it validates that any boundary-stratum effect survives contact with a full run.

### Arms (four cells; three core, one dose)
| Arm | Context limit | Compaction | Rationale |
|---|---|---|---|
| **A0** | fixed 200K / 80 turns (historical) | close at 0.8× | The incumbent policy; the baseline the pilot never tested mechanistically. |
| **A1** | capacity-derived (runtime-resolved) | native (auto) | The merged policy under test. |
| **A2** | capacity-derived | disabled (`compaction.auto=false`) | Mechanism isolation: separates *capacity* from *compaction continuity*. |
| **A3** (optional dose) | capacity-derived | native | Clamped policy cap at 50% of native — tests whether early compaction helps or harms; droppable if power is short. |

### Acceptance oracle (mechanical; pre-registered)
A trial is **ACCEPTED** iff **all** hold:
1. **Continuity:** the task binding is preserved across any compaction (same native session id; binding `task_revision` consistent), and the resumed run carries `--parent-run-id` to its declared parent (as `run-0da5271bc0cb` carries `run-dfa259243059`).
2. **Outcome:** the control-db run ends `completed` and the spec's acceptance phase passes (for the anchor, `p6g_acceptance` via the render gate's acceptance profile; for companions, the equivalent gate).
3. **Honesty (no fabricated OK):** no event where the gate returned `OK` and the runtime then crossed its native boundary without the gate predicting `COMPACT`; and no `UNJUDGED` from an *available* measurement.
4. **No false stop:** zero submissions refused by a policy gate where the native runtime would have allowed continuation.

Secondary measures: model cost per accepted outcome (ledger), operator touches per accepted outcome, actual compaction count, cache warmth at start.

### Sample size (with power reasoning)
- **Stage 1 (B):** 20 frozen sessions × 3 core arms = **60 trials**; fork cost ≈ $0.004735 (known finding), so ≈ $1–$5 of model spend. n=20/arm detects a 40%→70% (30 pp) shift at ≈80% power, α=0.05 (two-proportion).
- **Stage 2 (R):** **8 runs per core arm = 24 runs**, per-run `admission_required`, reserve 0.6 / hard cap 1.0, campaign budget 20 (mirrors the live run). Stage 2 is a **confirmatory replication gate**, not the discovery test — stated *a priori* so a null here does not get over-interpreted.
- Stage 1 has the power; Stage 2 has the validity. That split is deliberate: the last pilot's weakness was testing instructions with neither.

### Decision rule (pre-registered)
Adopt A1 operationally and retire A0 iff:
- Stage 1 acceptance-rate difference (A1 − A0) **≥ 20 pp with a 95% CI excluding 0**; **and**
- Stage 2 acceptance rate not worse than A0 by more than 5 pp, and cost/accepted-outcome ≤ A0; **and**
- zero fabricated-OK and zero continuity losses across all arms.
Corollaries fixed in advance:
- If A1 ≈ A2 > A0 → the driver is **capacity**, not compaction; prefer raising the limit and keep compaction at the runtime default.
- If A2 > A1 → compaction is hurting; keep capacity, disable compaction by default, investigate.
- If A3 > A1 → adopt a clamped early-compaction cap; else drop A3.
- If nothing separates A0/A1 → keep the merged policy as harmless (it removes a false refusal) but mark it **unproven**; do not roll back absent a harm signal.

### Budget
Total model spend **≤ $50**, one campaign lane, respecting the existing dollar-budget and lease rules unchanged: Stage 1 ≤ $5, Stage 2 ≤ $40, $5 contingency. Every Stage 2 run carries an admission lease with reserve 0.6 / hard cap 1.0 and campaign budget 20, exactly as the live continuation does.

### Stopping conditions
- **Harm (immediate):** any fabricated-OK, any binding/task-identity loss across compaction, any data corruption, or an interim acceptance regression >10 pp vs A0.
- **Futility (pre-registered interim at n=10/arm in Stage 1):** primary effect ≤ 0 or wrong direction → stop, declare uninformative/null.
- **Exposure:** if <50% of Stage 1 trials actually cross the boundary or compact, stop and redesign — the experiment cannot discriminate.
- **Resource/checkpoint:** budget cap reached; fleet occupancy means queue (never a different execution shape); a `checkpoint: true` phase stops for operator approval that is **never auto-approved**.

### What would make the result uninformative (explicit)
1. **No exposure** — tasks too short or too warm ever to reach the true boundary. The historical failure at 172,491 was a *threshold artifact*, not a capacity overrun; if the new arms never cross the real capacity, the experiment measures nothing.
2. **Transport confound** — using the frozen-row Docker fork that refused (known finding) instead of the native export/import round-trip; then the sample is the transport, not the policy.
3. **Helper ≠ runtime** — if the budget helper disagrees with OpenCode's accounting (the reviewer's 955K/975K and precedence findings), then "capacity-derived" is a mislabel and any null is about measurement, not mechanism.
4. **Cost confound** — cold cache (47%) vs warm (90%): cost comparisons require warmed, logged lineage (pilot cache 95.5–97.9%).
5. **Oracle saturation or floor** — all pass (no discrimination) or all fail for an unrelated reason (e.g., the `p1b_gate_first_viewport` re-run failing identically in both arms).
6. **Instruction leakage** — changing prompts alongside the mechanism, which the prompt-branch pilot already showed is neutral/confounded.
7. **Unregistered multiplicity** — scanning arms and the 7 promotables ad hoc until something looks significant.

### Why this beats the last pilot
The prompt-branch pilot varied **instructions** and found no accepted-outcome improvement — a mechanism-neutral result. This experiment varies a **mechanism** (budget resolution + compaction actuator), isolates capacity from compaction with A2, verifies exposure, and measures the live failure that motivated the change (the 172,491 false WARN refusal; the 25-hour/698K no-compaction path). It gets statistical power cheaply from the fork harness (`c50f37cfff42523b`) and validity from full runs, uses the native session round-trip rather than the refusing Docker fork, and pre-registers the oracle, decision rule, and harm/futility stops. And it honors the reviewer's core demand — *one authority* — so the label "capacity-derived" is actually true when the result is read.

### Falsifier for the leading claim
**H1 is falsified if** forked native sessions that cross the true boundary and compact natively show the same canary-continuation acceptance rate as those closed at the fixed threshold (difference ≤ 0 with a CI excluding the hypothesized ≥20 pp gain) — i.e., if compaction preserves the binding but does not improve task completion at equal cost, then "capacity-derived context management with native compaction improves continuation" is false, and the only honest remaining benefit is the removal of a false refusal.
