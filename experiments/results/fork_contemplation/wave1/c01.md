## 1. The reconstructed repair cycles

### R1 — The lint repair (repairing a verification gap)
- **Trigger:** CI `lint` red on the first push: `F401 .session_capacity imported but unused` at `src/agentic_dynamics/core/__init__.py:27`.
- **Compounding:** I had "verified" with per-file `ruff check <changed files>`, which cannot see the `__all__` rule; my earlier read of that file covered only the first 30 lines, so I never saw the list at line 32. The defect was created by an incomplete verification, then repaired by a push.
- **Cycle-one observable:** the exact CI command — `ruff check .` over the whole active surface — not a subset. The signal existed one command away before the push.
- **Smallest structural change:** a pre-handoff parity script that runs the CI linter over the whole tree (and the surfaces check), not per-file linting chosen by the author.

### R2 — The compaction boundary (repairing the repair; re-diagnosing the measurement class)
- **Trigger:** reviewer P1: "a successful compaction followed by a pending assistant message: the gate still reported 975K / COMPACT and refused submission."
- **Compounding:** the first `_measure` treated the compaction summary's `tokens` as the new context. The summary row is created zero-valued and then filled with the *summarization call's* usage — i.e. the old conversation's size (the runtime source creates `{output:0,input:0,reasoning:0,...}` then the call fills it). My own first regression test masked this because `_append_compaction_summary` defaulted to `summary_tokens=15_000`, 65× smaller than the 975K pre-compaction context; the reviewer's line — "the current fixture's small summary input hides this failure" — names the mask exactly. So I repaired the capacity policy, and the repair immediately needed a repair because the sensor read the wrong referent during a transient.
- **Cycle-one observable:** a replay using a realistic summary magnitude; or asserting the runtime's own guard. The runtime's loop literally carries `he.summary !== true` before `isOverflow`, which I had already extracted from the binary and still failed to mirror.
- **Smallest structural change:** reconstruct transient session state from runtime-shaped snapshots (pinned replay) rather than hand-authored fixtures — and treat any test fixture for runtime state as untrusted until captured from the runtime. This is the same lesson the project already recorded in `c50f37cfff42523b`: row-level extraction lost auxiliary rows, while a native opencode export/import preserved the session.

### R3 — The configuration authority (re-diagnosing the authority class)
- **Trigger:** reviewer P2: three reproduced divergences — `OPENCODE_CONFIG` ordered after project, partial `output` overrides discarding inherited `context`, JSONC trailing commas discarded.
- **Compounding:** I built a *second configuration system* (`load_runtime_config`, `_config_candidates`, `_strip_jsonc`) to feed capacity, when the runtime's own resolved metadata was one command away (`opencode models deepseek --verbose`, ~1.9s, which I had already run during recon). The controller's synthesis sentence is the whole lesson: "sharing one Python helper does not establish one authority if that helper disagrees with OpenCode."
- **Cycle-one observable:** a differential consistency check between my resolver and the runtime CLI across a config matrix, including the out-of-distribution cases (precedence, partial merge, trailing commas). The signal is one subprocess call.
- **Smallest structural change:** make the runtime's own resolution the single authority and gate every local derivation behind a parity oracle — no second loader can be merged without agreeing with the authority on a mutation matrix.

### R4 — The token arithmetic (same class as R3)
- **Trigger:** reviewer P2: "identical usage counted 955K natively versus 975K here."
- **Compounding:** I added `reasoning` to the missing-`total` sum. The runtime's expression (extracted as `Dl`) is `tokens.total || input + output + cache.read + cache.write` — no reasoning. I owned the exact source and still wrote a "plausible" approximation, then defended it with tests that used `total` and therefore never exercised the branch.
- **Cycle-one observable:** a unit case with `total` absent (the reviewer's exact 900K + 55K + 20K shape) and a parity assertion against the runtime expression.
- **Smallest structural change:** the same parity oracle, extended from *limits* to the *measure*: the local predicate must be textually traceable to the runtime expression, and the branch coverage must include the missing-`total` case.

### R5 — The override semantics (repairing the repair back toward the defect; re-litigating a settled decision)
- **Trigger:** reviewer P2: "Setting it to 100K makes 120K usage return COMPACT, even when native compaction starts at 968K… An oversized override can also exceed native usable capacity."
- **Compounding:** the operator had already ruled — "Changing only `--ctx-budget` or an environment variable is insufficient" — and yet my first design made `FINOPS_SESSION_CTX_LIMIT` the operative boundary and returned `COMPACT`, a verdict that claims the runtime will compact. It would not. This is the original early-stop hazard re-introduced through the fix, dressed as a verdict the runtime owns. In game-theoretic terms it is a commitment device repurposed against the gate's purpose.
- **Cycle-one observable:** one question asked of every verdict — *who acts next, and will they?* `COMPACT ⇒ the runtime will compact` is an invariant that the override case violates immediately.
- **Smallest structural change:** a verdict algebra keyed by *acting authority* (runtime compacts / operator cap / hard model limit) with enforced invariants, so a policy cap can never speak in the native verdict's voice.

### R6 — The corrupt database (a partial error boundary)
- **Trigger:** reviewer P2: the session lookup at `session_budget.py:179` sat outside the exception handler; the backend returned `UNJUDGED` but the JSON CLI crashed.
- **Compounding:** I had consciously built an error boundary and then placed exactly one read outside it — the boundary was a local patch, not a contract.
- **Cycle-one observable:** a fault-injection case (a non-SQLite file at the DB path) exercising the CLI and the gate.
- **Smallest structural change:** one guarded resolver for all external reads, with the CLI and gate able to emit only the structured state set — no read may bypass it.

### R7 — The swallowed control action (repairing an ops step)
- **Trigger:** `fleet_manager.py restart --service workflow-runner` emptied `fleet:commands`, left `fleet:commands:processing` empty, and did not restart the container (PID `733477`, start time unchanged).
- **Compounding:** control actions are fire-and-forget and leave no board record; I read "queue empty" as "dispatch succeeded." The re-issue through the documented seam (`BrokerClient().fleet_command(...)`) produced exactly the expected compose line (`Restarting infrastructure_workflow-runner_1 … done`) and PID `883849`.
- **Cycle-one observable:** verify the *effect* (PID/start-time) or require a terminal board record, never the queue state.
- **Smallest structural change:** every control-plane action gets an acknowledged terminal record (or a mandatory effect check), so the caller can distinguish "not yet" from "lost."

### R8 — Two efficiency cycles worth naming honestly

## 2. Divergence first: seven lenses

**Control theory.** The gate is a regulator whose setpoint was a constant on a variable-capacity plant (200K on a 1M model → false trip at 172,491), and whose observer served stale state during a transient (post-compaction), keeping the safety trip engaged after the plant had already reset. This is sensor-model mismatch, not gain tuning. *Discriminating test:* a step-response replay of a compaction — does the controller release as soon as the plant state is replaced, or does it demand a fresh sample?

**Distributed systems.** Two writers of one derived value, no single source of truth: my helper and OpenCode's resolved config. The catalog reader was a stale replica with no invalidation and no read-your-writes guarantee; the three config discrepancies are consistency violations. *Discriminating test:* a differential consistency check across config mutations. *Conflict:* the authority is a subprocess that can be absent or slow — so a strict single-authority rule must still define a degraded mode; the safe degradation is `UNJUDGED`, never a fabricated capacity.

**Measurement epistemology.** "Context size" has no direct observable; the runtime *defines* the proxy (`Dl`), so validity means matching its expression, not constructing a plausible one. The summary row is a wrong-referent measurement — its usage measures the summarization call over the old conversation — and the 15K fixture was an unrepresentative operationalization that hid the referent error. *Discriminating test:* construct validity against the runtime predicate on real snapshots, plus a referent assertion that a summary row is never consumed as context. *Conflict:* this requires emulation (there is no CLI for the token measure), which pulls against the distributed-systems preference for pure delegation.

**Safety engineering.** An interlock that trips spuriously ("cried wolf" at 172,491) invites evasion — the operator explicitly feared exactly that. My first fix then re-armed the spurious trip through the override (R5) and left an unguarded input (R6): the safety case lacked a fault-injection matrix. *Discriminating test:* absent/partial/corrupt/stale input matrix measured as false-trip vs true-trip. *Conflict:* safety wants fail-closed on unreadable input (`UNJUDGED` blocks), control theory wants to keep the plant moving; we deliberately chose the safety bias.

**Organizational economics.** The controller bore five findings' worth of verification labor; the producer captured the throughput. Classic principal-agent misalignment — and CI (`lint`) played the same role mechanically, catching what locally-scoped self-verification omitted. *Discriminating test:* track defect-detection stage and rework cost; a left shift shows findings caught pre-PR with zero review-round rework. *Conflict:* the principal cannot pre-specify every OOD case, so left-shifting only works with generated mutations, not fixed acceptance lists.

**Evolutionary dynamics.** The policy is a trait; the environment is the runtime. My first trait was fit to a *model* of the environment (my config reader, my token sum), so it was selected against by the first novel case. The survivor delegates to the environment's own machinery — a generalist, not a mimic. *Discriminating test:* an OOD mutation suite (three config cases + a realistic compaction snapshot) as the selection pressure the trait never saw. *Conflict:* external selection (review) is slow and costly; internalizing it as a harness accelerates selection but can overfit if the harness is hand-authored.

**Game theory.** The gate plays a repeated game with the AIO. A gate whose refusals are artifacts loses credibility and provokes workarounds; the override was a commitment device that could be turned against the gate. Credibility requires high precision (refusals ⇔ real incapacity) and legible reasons — which is precisely what the native-`COMPACT` vs policy-`CLOSE` split repairs. *Discriminating test:* refusal precision/recall on a labeled set of true-incapacity vs policy/artifact cases. *Conflict:* game theory wants fewer refusals to preserve compliance; safety wants refusals under uncertainty. The reconciliation is legibility plus the `WARN`-advisory split.

## 3. Synthesis (conflicts kept, then resolved)

Every lens points at the same generator from a different angle: **the gate behaved as a second implementation of the runtime.** Three re-derivation axes — configuration (R3), arithmetic (R4), transient state (R2) — and one re-litigation axis (the override, R5, against a settled operator decision). The conflicts resolve into one design rule:

> Consume the runtime's authority where it is queryable (limits, via `opencode models --verbose`); where it is not queryable, emulate its *exact expression or guard* and pin the emulation with a runtime-derived replay artifact; never emit a verdict that claims an actor will act when it will not; and make every external read pass one guarded boundary.

This is also what the project's own known findings already said in another key: `c50f37cfff42523b` — native export/import preserves session state where row-level extraction loses auxiliary rows; `7948b8ace287e881` — instruction arms did not improve accepted outcomes, so the lever is the mechanism, not more prose in `agent_config/agents/aio-control.md`; `6ef9bf9b6ef3b53a` — transport and tracking details (argv, tracked specs) are the real failure surface.

## 4. Ranking the structural changes by how early they would have fired

1. **Authority-first design rule + parity oracle for derived values** (design stage). Fires before code: no local value ships without agreeing with the runtime's own resolution on a mutation matrix. Removes R3 and R4, and would have skipped most of the second implementation pass.
2. **Native-state consumption + pinned replay for transients** (design/first test). Fires at the first test using a runtime-shaped snapshot. Removes R2 and the fixture-realism mask; grounded in `c50f37c`.
3. **Verdict algebra with role invariants** (design stage). Fires when the verdict set is defined — `COMPACT ⇒ runtime compacts`, a policy cap never speaks natively. Removes R5 and the R8 env re-litigation.
4. **One guarded resolver / error-boundary contract** (first implementation). Removes R6.
5. **Fixture-provenance invariant** (first test authoring). Removes the class that hid R2.
6. **Pre-handoff CI-parity script** (before push). Cheapest, most deterministic; removes R1, and should fold in the pre-existing-failure guard that R8 duplicated.
7. **Control-action acknowledgement / effect verification** (at first operation). Removes R7.

The trade-off is explicit: items 1–3 fire earliest and prevent the most rework but require design conviction up front; item 6 fires latest but is mechanically certain for its narrow class.

## 5. Leading claim, and one falsifier

**Leading claim.** The dominant compounding cycle in this fork was *authority divergence*: the gate re-implemented runtime semantics (a second config loader, a divergent token sum, a hand-rolled transient interpretation, a policy cap speaking in the native verdict's voice) instead of consuming the runtime's authority or pinning emulation to its exact guard. The smallest class-removing change is a producer-owned, pre-handoff conformance harness with two halves — *parity* where the runtime is queryable (limits via `opencode models --verbose`, across an OOD config matrix) and *pinned replay* where it is not (the runtime's own message-row invariants, e.g. "a completed compaction summary is never a context sample") — plus the verdict invariant that no signal may claim an action its actor will not take.

**One falsifier.** The claim is false if there exists a divergence class that neither half can see — specifically, runtime behavior with **no queryable surface and no persisted trace to replay**. The post-compaction case comes closest: OpenCode's overflow loop skips the summary and immediately forgets the transient, so the parity oracle over `opencode models` cannot see it, and the replay half only works because the summary row survives as a trace. If a real session compacted and resumed in a way where the runtime's decision depended on in-memory state never written to the database (as the `c50f37c` snapshot experience warns row-level extraction can lose), then neither parity nor replay would have caught the block, and the only class-removing change would be to stop comparing and instead **consume the runtime's native session representation directly** (the export/import lesson) rather than model it. A single observation — a compacted session where no runtime-visible artifact distinguishes the stale pre-compaction reading from the live context, and the correct verdict is simply to trust the runtime to proceed — would falsify the leading claim as stated and force the stronger structural fix: delegate the decision, do not emulate it.
