## 2. Seven lenses, divergence first

**1) Control theory.** The AIO is a controller whose internal model (a Python resolver) diverged from the plant (OpenCode). The 975K/COMPACT-after-compaction and 955K-vs-975K are steady-state errors; the review was an external observer injection. *Discriminating test:* open-loop replay of a recorded usage sample through plant and observer, asserting identical verdicts at the boundary. (The controller ran exactly this.)

**2) Distributed systems.** Two writers to "the limit" is split-brain; the review named it. Secondary: **code identity is not deployment** — long-lived broker/consumer processes cache code, so "merged" ≠ "running." *Discriminating test:* assert the loaded version through the live service. Here the live submit served as the behavioral version probe (pre-merge it refused; post-reload it was accepted).

**3) Measurement epistemology.** The compaction summary's `tokens` measures the *generation call over the old conversation*, not the new context — a **referent error**, not arithmetic. `UNJUDGED` and `usage_incomplete` are the honest states; a small-summary fixture *"hides this failure."* *Discriminating test:* exact-shape fixtures (pending-zero, completed summary, reasoning-only).

**4) Safety engineering.** An interlock must actuate the mechanism it names: *"Returning `COMPACT` does not initiate compaction"* is a lying interlock. A monitoring script that crashes on a corrupt DB is a hazard, not a gate. *Discriminating test:* fault-inject (corrupt DB, absent socket, hung runtime) into every gate and assert a **named** fail-closed state.

**5) Organizational economics.** Operator attention is the scarce resource; the agent's re-derivation is an unpriced externality pushed onto the reviewer. The fix is to *price* it: a merge request should carry its verification provenance, and **reviewer-findings-per-PR** is the KPI. *Discriminating test:* does consuming the authority measurably reduce findings?

**6) Evolutionary dynamics.** CI is the immune system; the operator is apex selection. A mutation that passes the immune system yet defeats the organism's purpose (the post-compaction block) survives unless the apex looks. *Discriminating test:* replay the last N operator findings as automated tests — every one that becomes machine-caught lowers the apex's marginal value.

**7) Game theory.** The P0 merge gate is a credible commitment; "hold the merge" made the AIO's cheap talk (green suite) costly; "native-tool-only" removed a side channel. *Discriminating test:* attempt to construct a defection (self-merge, workaround client) that improves local payoff — if it is blocked only by *permission config* and not by design, the constraint is fragile.

**Visible conflicts.**
- *Control theory vs. distributed systems:* improve the controller's model vs. **delete** the model and consume the authority. `c50f37cf` adjudicates: consumption wins where the binary exists; re-derivation survives only as a **documented degraded mode** (containers without the binary).
- *Organizational economics vs. safety engineering:* automate findings into tests vs. never automate purpose-level judgment. The P1 was a purpose failure ("continuity"), not an arithmetic one — so automate the *machine-checkable* class, surface the *preference* class.

## 3. Synthesis — the division-of-labor rule

**Docstring (the rule).** *A unit of work may be decided alone iff it is reversible **and** inside a pre-declared policy **and** verifiable against a single authority. If reversible but judgment-laden, or if the fact is unmeasurable, it must be surfaced with its unverified assumptions and fail closed where it gates. If irreversible, spends beyond the lease, signs an approval, or changes the policy itself, it must wait.*

```python
# Decision predicate, with rationale per clause.
#   1. reversible  -> a wrong call can be undone without asking; the cheap half of the spectrum.
#   2. pre-declared policy -> the operator already set the setpoint (they set 968K, not 200K).
#   3. single-authority-verifiable -> the check can consume the runtime (opencode CLI / DB),
#      never a second model of it. This clause exists because its absence produced BOTH
#      the config-overlay bugs and (by exact analogy) the c50f37cf row-loss.
def may_decide_alone(act) -> bool:
    return act.reversible and act.within_declared_policy and act.has_single_authority
```

**Decide alone.** Run the environment's *exact* rails before claiming green (`ruff check .`, not per-file); resolve limits and judgment by consuming the runtime; reload the gate services and report start times; submit a pre-authorized continuation once activation has landed; emit `UNJUDGED`/fail-closed states.

**Surface (act + publish evidence and the assumptions it could not verify).** Advisories (`WARN`); plant-model assumptions; **code-identity/reload status** ("broker PID 883363 @01:59:12; consumer 883849 @02:02:51"); control actions that leave **no board record** — the swallowed `fleet_manager restart` proved "queue empty ≠ dispatch succeeded," and the system should have emitted a dispatch receipt; cost trends; fixture-realism caveats.

**Wait for the human.** Merge/permanence; deploy; the `p1c`/`p6g` approvals; budget/admission changes; acceptance ratification; and **any change to the policy itself** (the operator was right to reserve "This is my explicit context-policy change").

**Interface contract (make human attention cheap):** every surfaced item ships (a) the decision requested, (b) the evidence rail and exact commands, (c) **the assumptions it could not verify**, (d) reversibility and cost-of-error, (e) blocking state. The operator's two best interventions were cheap precisely because the AIO had framed the choice; the expensive one (the review) reconstructed the AIO's unverified assumptions itself.

## 4. Leading claim and one falsifier

**Leading claim.** *The operator's marginal attention is most valuable at irreversible, purpose-level boundaries; the residual load here was dominated by plant-model divergences the system could have eliminated by consuming the runtime's authority and running the environment's exact selection rails. Therefore: consume authority, never re-derive it — and price your own verification before requesting attention.*

**Falsifier (one, concrete and measurable).** Take the next change prepared under this rule — limits and judgment consumed wholesale from the runtime CLI, the exact CI command run before the request, and fixture-realness tests that include a pending/zero **summary** shape — and run it through the same operator review. **If it still draws even one finding that was expressible as a failing test at request time, the claim is false:** the attention cost is not re-derivation but something else (unknowable runtime behavior, or operator preference), and the rule must shift from *"consume authority"* to *"negotiate acceptance criteria before implementing."*

*One residual honesty note against myself:* the operator's P1 was not just an arithmetic slip — it was a **purpose** failure (a gate that defeated the policy's reason to exist). That class is only partly mechanizable, which is exactly why the "surface" bucket stays real rather than collapsing into "decide alone." The falsifier above is designed to test whether *this* class is the true residual — and it can only be run by the next review, not argued away here.
