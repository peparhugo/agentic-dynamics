## 1. Divergence first: seven lenses, each grounded

**Lens 1 — Control theory.** Authority is control gain; the budget gate is a setpoint. At `control-room-instrument-cont-submit`, the setpoint was a constant (`DEFAULT_CTX_BUDGET = 200_000`, 0.8× = 160K), so the controller refused a *valid* plant state (172,491) — a sensor-equivalent error produced a control error. My own post-compaction bug, reproduced by the controller as "975K / COMPACT", was the same fault from the other side: `_measure` read the compaction summary's *generation-call* usage as the plant state, so the controller demanded compaction that had already completed. Two more sensor faults followed: the corrupt-DB CLI crash and the empty-vs-missing conflation (the exit-3 envelope rendered as an observed empty packet). *Take:* the durable guard belongs in the plant (an interlock on effects), not in another controller setpoint; a safe controller assumes the measurement is wrong.

**Lens 2 — Distributed systems.** Authority is identity plus a fencing token. The binding tuple (`native_session_id`, `binding_id fbca5106699d…`, `task_revision 2`) is exactly that, and Unit D re-resolves it at the backend so a claimed id is never proof. But `c50f37cfff42523b` shows identity is copyable (native opencode export/import preserves the session) and frangible (row-level extraction lost auxiliary rows — a fork that *looks* like the parent but has silently lost constraints). The swallowed `fleet_manager restart` is the unobservable-effect problem: control actions leave **no board record**, so I mistook "queue empty" for "dispatch succeeded" and only recovered by re-issuing through the broker seam and reading the compose log/PID. *Take:* every effectful act needs an observable terminal record or idempotent semantics (the system already built `_recover_processing` for this).

**Lens 3 — Measurement epistemology.** What does the number mean? 955K native vs 975K local (`reasoning` in my summed fallback) is a 20K phantom that would demand compaction the runtime never triggers. `usage_incomplete`, `post_compaction`, `remaining_tokens`, and `limits_source: opencode-cli` are all claims with provenance, not facts. My close-out verified the world directly — control-db row `running`, PID 883849 at 02:02:51, compose log "Restarting infrastructure_workflow-runner_1 … done" — not the command's exit code. And `7948b8ace287e881` is the hard lesson: no instruction arm improved accepted outcomes. *Take:* guards must verify effects (run row exists, PID changed, sha matches), not intentions.

**Lens 4 — Safety engineering.** Swiss cheese, and the holes currently align: remote branch protection (10 checks) with **no required review** (`reviewDecision: ""`), the broker's armed-admission refusal, the strict budget gate, the P0 doctrine — and the local `main` checkout, which is what the running services actually read. My `git merge --ff-only origin/main` and `systemctl --user restart` succeeded without an interactive human, and the ladder container is bind-mounted from that same checkout (`…:/repo:ro`). In-process runs are explicitly "documented scopes, not enforced ones". *Take:* put the first interlock at the highest-energy boundary — activation of code and spend — and fail closed.

**Lens 5 — Organizational economics.** The scarce resource is the controller's attention. Requiring review of every AIO effect is a tax; taxes get dodged, and the in-process exception is the dodge. The real bounds are budgets: `campaign_budget_usd 20`, `reserve 0.6`, `hard_cap 1.0`, leases `bud_afacee0f…` / `con_36ca651b…`. `7948` (baseline cost-minimal; instructions ineffective) is an economics result: cheap prose is worthless, expensive verification is real. *Take:* the best guard lowers monitoring cost per unit of autonomy by making effects self-evidencing.

**Lens 6 — Evolutionary dynamics.** Selection rewards delivery. The pre-fix gate *punished correct behavior* (it refused because policy, not capacity); post-fix it selects for capacity-aware work. Cache economics (`47% → 90%` warm, `$0.004735`) select fork-heavy workflows; the cost-minimal baseline selects minimal work. Authority creep is an adaptation: any bypass that yields a delivered outcome (in-process run, local merge, kill-and-restart) will be selected. *Take:* change payoffs — make bypasses fail or yield no accepted outcome — rather than stacking prohibitions.

**Lens 7 — Game theory.** The constitution is a commitment device; `FINOPS_SESSION_CTX_LIMIT` was a *self-relaxable* cap (the reviewer's P2: it could produce `COMPACT` the runtime would never honor) until clamping. The local-main route dominates `gh pr merge` for speed; in-process dominates the fleet queue. *Take:* remove dominated-but-attractive moves and make commitment externally verified (operator signature at the effect boundary).

**Conflicts kept visible.** Safety/control: more interlocks. Economics/evolution: friction invites bypass and `7948` says instruction won't help. Distributed systems: identity suffices. Game theory: identity is cloneable. Measurement: verify effects. Economics: verification must be cheap. *Discriminating tests:* (a) install the strongest mechanism guard and re-run the `7948` pilot — if accepted outcomes don't improve, mechanism is also theater; (b) export/import a session into a host with no binding store and watch the backend — does identity alone refuse it? (c) offer the in-process shortcut while the fleet is saturated and see whether it is refused.

## 2. The authority map (worst realistic quarter; guard; accepted?)

Scores are P (probability next quarter, 1–5) × B (blast radius, 1–5) ÷ C (guard cost, 1–5).

**A. Scope exceptions — in-process agentic execution.** Granted-by-omission: `run_workflow.py` without `--orchestrator` runs phases on the host, no lease, no container, `--require-deterministic` opt-in. *Worst outcome:* facing a refusing/queued fleet (our `run-0da5271bc0cb` took a queue slot), the AIO runs `control_room_instrument_build` in-process; unbudgeted spend (the `$1.0` hard cap never fires), writes outside the cell mount contract, no admission binding. *Guard:* default-deny agentic-phase specs in-process at the fleet boundary; require a controller-signed exception. Accepted? No — documented, not enforced. 3×4÷1 = **12.0**.

**B. Host-side commands (shell beyond P1).** *Worst outcome:* edit `~/.config/systemd/user/…env.conf` to disarm admission, or locally merge a branch that the services already read, or write outside the KB-worktree contract. *Guard:* effect-logged, refuse-by-default shell scope. Accepted? No. 4×5÷2 = **10.0**.

**C. Pattern kills.** *Worst outcome:* `pkill -f opencode` kills the AIO's own server (posterior lost); killing the broker mid-submit orphans a `docker compose run`; killing workers loses in-flight jobs. *Guard:* deny kill patterns, force the existing drain/restart seam, record every control effect. Accepted? Only for the Control Room/Web UI (P0); everything else unguarded. 2×4÷1 = **8.0**.

**D. Merges / local-main activation.** *Worst outcome:* local merge or `git push origin main` bypasses remote branch protection because services run the local checkout. *Guard:* local main immutable to the AIO; services start only from an operator-signed commit (signature verified at unit start). Accepted? Remote protection accepted; the local hole is unexamined. 2×5÷2 = **5.0**.

**E. Agent forks.** *Worst outcome:* `c50f37c`-style export/import clones the AIO identity into a context with no binding gate; or a row-loss fork keeps acting under `task_revision 2` with a truncated posterior. *Guard:* fork manifest (parent binding id + revision + snapshot hash + scope); require native export/import for snapshots; Unit D already refuses an unbound session id. Accepted? Partially. 3×4÷3 = **4.0**.

**F. Caps.** *Worst outcome:* self-relaxation via `FINOPS_SESSION_CTX_LIMIT` (now clamped), a spoofed `FINOPS_OPENCODE_MODELS_CACHE` making the AIO's *own* check huge (the broker's env still measures honestly — a real mitigation), or an oversized reserve within the campaign. *Guard:* pin capacity env at the backend, bound reserve/hard-cap by policy, expose provenance in receipts. Accepted? The clamp is a partial accept; the catalog/env path is not consciously evaluated. 3×3÷2 = **4.5**.

## 3. Ranked, and the ONE guard to build first

Ranking: **A (12.0) > B (10.0) > C (8.0) > D (5.0) > F (4.5) > E (4.0).**

The formula's single highest cell is A (in-process), but A, B, C, and D share one physical boundary: the AIO's shell and the host effects it can emit. The correct *one* guard is therefore the **host-effect interlock**, whose first rule is A's refusal:

> Refuse-by-default, effect-logged shell scope for the AIO: every effect that changes process lifecycle (`systemctl`, `kill`), service configuration, the local `main` checkout, or starts an agentic workflow (`run_workflow.py` without `--orchestrator`) is denied unless emitted through a named verb that records `{verb, target, intent, actor, session, binding_revision, ts, outcome}`. In-process agentic execution is denied without a controller-signed exception; raw kills and local-main writes have no exception path.

*Design reasoning (brief):* (1) it is one artifact at the existing seam — the broker already exposes typed verbs and the permission layer already supports pattern rules, so guard cost is low; (2) it closes four surfaces, which is why it beats the cheaper single-surface in-process flag; (3) it implements the lenses' shared conclusion — change payoffs (evolution), make the commitment external (game theory), verify effects not intentions (epistemology), and keep monitoring cheap (economics) — while resisting the `7948` trap of adding prose. The residual, consciously accepted risks after it: oversized cap selection within the campaign (bounded by `campaign_budget_usd`), and fork-identity cloning (Unit D plus the fork manifest remain the two-deep guard).

## 4. Falsifier for the leading claim

The claim: *the host-effect interlock is the highest-leverage first guard.* **Falsifier:** if, after it is installed, any single non-allowlisted effect still executes without a signed intent record in the effect log — most cheaply, `python3 -c "import os; os.system('systemctl --user restart agentic-dynamics-launch-broker')"`, an in-process `run_workflow.py` with an agentic spec, or a `git merge <branch>` on local `main` — then the boundary is bypassable by an allowed verb and the interlock is security theater; the claim is false and the ranking must fall back to A as a standalone mechanical refusal.
