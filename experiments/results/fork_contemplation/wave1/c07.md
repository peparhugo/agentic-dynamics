## 1. Seven lenses (independent takes, conflicts kept visible)

**Control theory.** The session ran open-loop against a plant model I wrote: the extracted formula. The compaction summary (`mode: compaction`, `summary: true`) was an *unmodeled mode*, so my controller emitted `COMPACT` — a command for a mitigation (native compaction) the plant would not perform there, and later a policy cap that emitted the same signal. The runtime's `he.summary !== true` is the plant guard my controller lacked. *Discriminating test:* model-in-the-loop — drive real plant states and require the controller's verdict to equal the plant's own `isOverflow`; any disagreement is a false model, not a tuning issue.

**Distributed systems.** Acceptance is four code copies at a boundary: CLI, capsule subprocess, consumer container, broker. Submits have durable claims (BLMOVE + processing lane + `_recover_processing`); control actions do not — my restart vanished between claim and compose, leaving no board record. *Discriminating test:* after any control action, require a durable terminal record; absence proves the observability hole. (This is the same class as `6ef9bf9b6ef3b53a`: what rides transport without a durable artifact can be lost. Notably, this delivery respected that finding — the spec was tracked with sha `caf1eb6b` and the goal had no newlines for argv.)

**Measurement epistemology.** "Verified" equivocated between model prediction and instrument reading. Asserting `effective_limit == 968_000` twice tested my port against itself; the 955K-vs-975K discrepancy and the 975K post-compaction reading were *instrument* divergences. The one genuinely epistemic act I added was provenance (`limits_source`, `formula_version`, `runtime_version`) — it makes each number attributable to an instrument. *Discriminating test:* blind export/replay where expected values come only from the runtime; no shared constants.

**Safety engineering.** The gate is an interlock; its signals are safety claims. `FINOPS_SESSION_CTX_LIMIT → COMPACT` was a *mislabeled interlock* claiming a mitigation that cannot occur. The corrupt-DB crash destroyed the "never fabricate OK" property by making the tool unusable rather than degraded. Interlocks are proof-tested with negative controls; my suite had none. *Discriminating test:* fault-injection matrix (corrupt db, missing identity, pending-only, in-flight compaction, oversized override) — every cell must yield a *named* state, never a crash and never a clean OK.

**Organizational economics.** Defect yield per layer this session: independent runtime review **5**, host re-run **1** (the environment gap: no compacted session existed — `time_compacting IS NOT NULL` returned empty), binary suite **0 behavioral** across thousands of assertions. `7948b8ace287e881` says the baseline is cost-minimal and no instruction arm improved *accepted* outcomes; the marginal dollar belongs to the layer with demonstrated yield, not to more instructions. The swallowed restart was a pure observability tax. *Discriminating test:* attribute each escaped defect and its fix cost to a layer; fund max yield-per-dollar.

**Evolutionary dynamics.** My fixture corpus was a low-fitness environment: it selected for code matching my assumptions (my compaction fixture was a small *plain* sample), so the P1 organism survived. `c50f37cfff42523b` supplies the cheap diversity mechanism: fork a seed, warm cache 47%→90%, ~$0.0047; and native `opencode export/import` preserves sessions. Drift (a new OpenCode bumping `OUTPUT_TOKEN_MAX`) is the mutation the oracle must track. *Discriminating test:* mutate the runtime constant and verify the oracle detects the divergence; if it passes unchanged, it isn't coupled to the environment.

**Game theory.** The author writing the oracle is self-grading. The controller's runtime-armed, adversarial review is the credible threat that broke it — but a judge can also cheaply pass everything. `7948b8ace287e881` again: payoff structure (who pays for escaped defects) beats prompt wording. *Discriminating test:* plant a known-bad delivery as a canary; if the judge returns green, its green carries no information.

**Visible conflicts.** (a) *Control theory vs economics*: close the runtime loop on every delivery vs fund only by risk/risk-weighted yield — discriminated by per-layer yield-per-dollar on the rework ledger. (b) *Epistemology vs distributed systems*: one authoritative instrument (runtime) vs four copies that drift — discriminated by a post-version-bump corpus agreement test across CLI/capsule/consumer/broker. (c) *Game theory vs evolutionary dynamics*: adversarial second model vs one model over a wider artifact matrix — discriminated by running both against the pre-fix `bc87e60af`.

## 2. Oracle-by-oracle audit

### A. Binary test suites (pytest, ruff, surfaces)
- **Actually verified:** behavior on *constructed* inputs; repo-wide lint/import invariants; generator drift. It caught the F401 only at CI scope — a real, if shallow, catch (`bc87e60af`).
- **Could pass falsely:** self-referential fixtures; tautological assertions from my own formula; no canary (nothing asserted the resolver *must fail* on a wrong limit); malformed fixtures that fail for the wrong reason (JSONC braces), where "fix the test" can silently bless a broken implementation.
- **Failed to see:** real message shapes (`summary`, `finish`, zero-valued pending), summary-generation usage, cross-file config precedence, corrupt-DB behavior, policy-vs-native semantics, service reload, and anything about acceptance quality. Net: 0 of 5 review defects were in its reach.

### B. Host-side re-runs (real DB, real session)
- **Actually verified:** the active model is the session's (`flash`, not the repo default `pro`); real config/catalog precedence; `172,491 → OK`; the previously-refused session now `OK`; `431,754/968,000`; `limits_source=opencode-cli`.
- **Could pass falsely:** n=1 environment; agreement between my fallback and the CLI on one host doesn't generalize; a re-run confirms reproducibility, not the correctness of the input model.
- **Failed to see:** the compaction path entirely — the exact moment the oracle went blind was `SELECT ... WHERE time_compacting IS NOT NULL` returning empty, so the P1 domain was never sampled.

### C. Arm-blind model reviews (the controller's review)
- **Actually verified:** five behavioral defects with reproductions; the authority critique ("one helper is not one authority if it disagrees with OpenCode"); the 955K/975K arithmetic.
- **Could pass falsely:** diff-only reading; no runtime access; correlated blind spots with the author; coverage is opportunistic (absence of a finding ≠ absence of a defect).
- **Failed to see:** the post-activation service state (the swallowed restart occurred in the same window), downstream run quality, and whether the resume actually fixes the parent failure. Its evidentiary weight came from *runtime access plus adversarial incentive*, not from being "a review" — consistent with `7948b8ace287e881`.

### D. The render gate
- **Actually verified (by design; not yet exercised here):** a preview serves the candidate, light/dark + below-fold renders, evidence bound to a candidate sha.
- **Could pass falsely:** a stale preview serving a different commit; static captures passing while mutating controls are broken; presence checks instead of behavior; and, in this session, the gate hasn't run at all (run still in `p1b`), so its predictive value for *this* delivery is zero so far.
- **Failed to see:** design quality/novelty, accessibility, operator acceptance. The close record's `--candidate/--base` prescription and "mutating controls in an isolated acceptance env" are precisely the anti-false-pass controls.

### E. Ledger checks
- **Actually verified:** the submit is real (`run-0da5271bc0cb` row, parent, leases `bud_afacee0f…`/`con_36ca651b…`), and the transport receipt alone was not accepted ("a queued submit is NOT a running run"). Provenance via decisions `34a57410…`/`77eb2260…` and close `43af2a0c…`.
- **Could pass falsely:** "running" ≠ correct (a row persists through a p1b failure); cost is `estimated`, not metered; **control actions write no ledger row** — the swallowed restart proves the ledger's coverage is partial.

## 3. Synthesis: a stronger delivery oracle

I'm proposing **RADAR** — *Runtime-Anchored Differential Acceptance Review*. Rationale is written as docstrings/comments, per verbose mode.

```python
# RADAR — the delivery acceptance oracle.
# DESIGN PRINCIPLE: the runtime is the authority; our code is a model of it.
# An oracle that agrees with a model cannot adjudicate the model.

def radar(delivery, *, corpus, budget):
    """Validate a delivery against runtime-derived expectations, with canaries.

    WHY (grounding): the controller's P1 repro (completed compaction + pending turn
    → 975K/COMPACT) was invisible to a fixture world where summaries were plain small
    samples. Only driving the runtime (and exporting real sessions) exposes it.
    """
    # LAYER 1 — differential conformance corpus.
    #   Build once, reuse: N≈8-12 native `opencode export` sessions (per
    #   c50f37cfff42523b, export/import preserves sessions where frozen Docker
    #   snapshots lost auxiliary rows) x 3 configs (global / OPENCODE_CONFIG / project,
    #   incl. a partial-override and a trailing-comma JSONC file).
    #   For each fixture, extract the EXPECTED decision from the runtime's own signals
    #   (overflow/compaction events), never from our constants; diff against the helper.
    # BOUNDED COST: warm forks ~90% cache (c50f37cfff42523b); the corpus is a
    #   regression asset amortized across PRs; run it when resolver/gate files change.
    assert_runtime_agreement(corpus)

    # LAYER 2 — canaries (the gate must be able to fail).
    #   Every oracle ships known-bad inputs that MUST be rejected:
    #   pre-fix commit bc87e60af (post-compaction), an oversized override, a corrupt
    #   db, a pending-only session, an in-flight compaction. If a canary passes, the
    #   gate is uncalibrated and RED.
    # WHY: my suite passed the P1 defect because no test encoded its failure mode.
    assert_canaries_rejected(delivery, canaries=[PRE_FIX, OVERSIZE, CORRUPT, PENDING])

    # LAYER 3 — independent reproduction bundle (principal-agent fix).
    #   The author ships <=3 reproductions (command + expected failure mode); the judge
    #   is NOT the author, has runtime access, re-executes the bundle, and records
    #   findings + cost. Generic "review this" prompts are not the asset
    #   (7948b8ace287e881: no instruction arm improved accepted outcomes); runtime
    #   artifacts are. Bound the bundle so review time stays finite.
    assert_judge_reproduces(bundle, judge=not_author)

    # LAYER 4 — boundary telemetry (durability as oracle).
    #   A control action is dispatched only when a durable terminal record exists
    #   (fixes the swallowed `fleet_manager restart`); a run is delivered only when the
    #   render gate runs against the exact candidate sha with a negative control (a
    #   known-bad candidate must FAIL). "Running" is not "accepted".
    assert_durable_terminal(action_log)
    assert_render_gate(candidate_sha=exact, negative_control=True)

    # LAYER 5 — rework/cost ledger (quality signal at bounded cost).
    #   Journal (layer, defect, fix_commit, ci_minutes, tokens, $) per delivery; fund
    #   the max-yield-per-dollar layer. From this session: runtime review 5,
    #   host re-run 1, binary suite 0 behavioral — the allocation signal is already
    #   legible without new process.
    return rework_ledger.attribute(delivery)
```

**Independence is preserved** by construction: author tests remain as cheap regression, but their evidentiary status is downgraded; the acceptance decision rests on layers 1–4, none of which share the author's assumptions. **Bound** comes from reusing the exported-session corpus and warm forks, capping the reproduction bundle, and journaling rather than adding ceremony.
