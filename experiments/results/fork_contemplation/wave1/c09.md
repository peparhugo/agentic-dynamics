## 2. The invisible costs, ranked

1. **The source-to-oracle translation gap (largest).** I had already paid for `/tmp/opencode_strings.txt`. It contained the runtime's run-loop guard `he.summary !== true` — the runtime explicitly *skips its overflow check when the last assistant message is a compaction summary*. My port used the formula but not the guard, so `_measure` read the summary's generation usage (≈975 K) as the new context and refused the first resumed submission. I only grepped `he.summary` when the reviewer pointed at it. The evidence was in hand; the oracle wasn't.
2. **Fixture under-specification (same root, concrete face).** My synthetic DB fixtures had no compaction rows, always carried `tokens.total`, and used one config file. Known finding `c50f37cfff42523b` is exactly this: *frozen real-session snapshots refused to fork in Docker; row-level extraction lost auxiliary rows; a native export/import preserves the session.* My fixtures were row-level extractions — and the auxiliary row (the compaction summary) was the bug. Retrospective honesty, though: when I went looking, `SELECT id, time_compacting FROM session … IS NOT NULL` returned **`compacted sessions: []`** — this host had no real compacted session to snapshot. The cheap instrumentation could not have been “capture a live one”.
3. **Re-proof and repeated diagnostics tax.** Three full suites, two CI cycles, and a two-place proof (main + pristine worktree) for the same 12 environmental failures. That set is stable and known; every session pays it again in wall-clock and carried context.
4. **Control-action acknowledgement gap.** `fleet_manager restart` returned “LPUSHed”, the queues drained, and *nothing happened*. “Queue empty” was read as “effect applied” — an event/state confusion. Same family as known finding `6ef9bf9b6ef3b53a` (what reaches the executor is what the transport declares, not what the sender intended).
5. **Local/CI lint divergence.** Small stakes, trivial fix, but it cost one CI cycle.

## 3. The cheapest instrumentation that would have made (1) visible before payment

**Proposal: a source-to-oracle conformance suite.** Not a new harness — a rule that every runtime semantic extracted during recon becomes one executable assertion, with the minified source expression quoted in the test docstring (this is the “verbose mode” applied to tests, and it is the only durable place the archaeology can live).

```python
# tests/test_session_capacity_conformance.py
def test_overflow_skips_the_compaction_summary():
    """opencode 1.18.15 run loop, /tmp/opencode_strings.txt:

        if (he && he.summary !== !0 && isOverflow({tokens: he.tokens, ...})) { ... }

    `he` is the last assistant message; a summary is explicitly excluded. The ported
    check must therefore never treat a completed compaction summary as the current
    context. Fixture shape is ALSO source-derived: the runtime creates the summary with
    tokens all-zero (summary:!0, mode:"compaction") and the generation call fills them
    with the OLD conversation's usage.
    """
    # fixture: pre-compaction 975K sample -> completed summary (tokens=975K) -> pending turn
    assert measure_verdict(sid, db_path=db)[0] != "COMPACT"   # pre-fix: COMPACT (the bug)
```

Cost: one file, four tests (summary-skip; sum excludes `reasoning`; `reserved = min(20000, maxOutputTokens)`; config order global → `OPENCODE_CONFIG` → project), each built from already-extracted source. No model calls, deterministic, milliseconds — and it directly targets exactly the four findings the human had to reproduce. The fixture is legitimate *without* a live compacted session because it is derived from the runtime's message-creation source, not from a captured row.

**Why this beats the alternatives.** A machine “adversarial reviewer” session would also have found them, but at model-dollar and wall-clock cost. Capturing a real session (the `c50f37cfff42523b` route) is the gold standard but was unavailable here (`compacted sessions: []`). Known finding `7948b8ace287e881` — no instruction arm beat the baseline; the baseline was cost-minimal — warns against building a bigger apparatus: four assertions, not a framework. Separately, the control-action gap wants a one-line **ack record** (`{action, service, returncode, ts}` appended alongside control commands); that is cheap and independent, and would have shown the swallowed restart immediately. The environmental-failure tax wants a checked-in known-failures baseline so “no new failures” is a diff, not a re-proof expedition.

## 4. MoE — seven independent takes, conflicts kept visible

**Control theory.** The interlock was an estimator, not the plant. opencode's `isOverflow` *is* the controller; I built a parallel observer and never fed it the plant's own skip signal (`he.summary !== true`). Discriminating test: a step response — inject a compaction and compare the estimator's verdict to the runtime's boolean. *Conflict:* measurement epistemology notes the plant is only visible through a binary, so “read the plant” is itself costly — but I had already paid that cost.

**Distributed systems.** The submit path is tool → `fleet:commands` → consumer → broker → compose → run. The swallowed restart is a lost acknowledgement: at-most-once effect with at-least-once acceptance. Discriminating test: persist a per-command returncode and replay; the effect must be observable, not inferred. `6ef9bf9b6ef3b53a` is the same lesson at a different hop.

**Measurement epistemology.** Every fixture is theory-laden. Small summary input, presence of `total`, single config file — each encoded an assumption and each hid a finding. The controller's reproduction was the first external referent. Discriminating test: prediction — local number equals runtime number on the same rows. It didn't: 955 K native vs 975 K local. `c50f37cfff42523b` supplies the canonical referent route.

**Safety engineering.** The failure mode was a false trip on an interlock (blocking valid work), not an unsafe pass. False trips erode trust and invite bypass; interlock validation requires injected real failure signals, not model confidence. Discriminating test: every trip must be reproduced against the real sensor — the compacted-session trip is mandatory.

**Organizational economics.** Human attention was the scarcest input and delivered the highest marginal yield (five findings in one pass). The agent should have front-loaded a machine oracle before spending principal time. *Conflict with* the P0 discipline: correctly refusing to self-merge queued the work for the controller — a deliberate principal-agent cost that preserved authority. Discriminating test: run an automated real-data reviewer pre-merge; count residual human findings.

**Evolutionary dynamics.** The test suite is a genotype; CI selects for “passes current environment”; the reviewer is a novel environment. Mutations that only fit the old environment die late and expensively. Diversity of test *environments* (real snapshots) beats diversity of assertions. *Conflict:* `7948b8ace287e881` says richer arms didn't improve accepted outcomes — so add the minimum viable diversity (four source-derived tests), not a simulator.

**Game theory.** The gate is a screening device. My first iteration over-weighted the principal's risk (conservative trip on stale readings), and the agent bore the cost — the refused first resumed submission. Worse, an override that mimicked native `COMPACT` was non-incentive-compatible: it claimed a mechanism that would not fire. Separating policy-CLOSE from native-COMPACT (commit `4c3c6cdf0`) restored signal honesty. Discriminating test: vary the native threshold with the policy cap fixed; `COMPACT` must track the native signal, `CLOSE` the policy signal.

## 5. Divergence, then synthesis

**Where the lenses disagree.** Measurement epistemology wants real-session breadth; evolutionary economics and `7948b8ace287e881` want the minimum. Control theory says hold the port to the plant's exact signal; organizational economics says the plant is expensive to interrogate, so use the source you already extracted. Distributed systems wants durable acks; the P0 boundary says some acknowledgements (the merge) must remain human. None of these can be settled by argument.

**Synthesis.** The four conformance findings share one generator: I treated the runtime as a *specification I could paraphrase* rather than an *oracle I must diff against*. The paraphrase was faithful on the constants and faithless on the control flow (the summary skip), the data shapes (missing `total`, multi-file config), and the failure modes (corrupt DB). The fix is not more prose fidelity; it is at least one executable assertion per extracted semantic, plus one durable ack per control action. Finding #4 (override semantics) is the exception that proves the scope: it was a mechanism-design error, not a conformance error, and no fixture would have caught it — human judgment was genuinely required there.

## 6. One falsifier for the leading claim

**Leading claim:** the largest invisible cost was the source-to-oracle translation gap — runtime semantics already extracted into `/tmp/opencode_strings.txt` were not turned into test oracles, so the human reviewer became the oracle and one full review-plus-rebuild cycle was paid.

**Falsifier:** build the compaction fixture *only* from the source shape I had already extracted (summary created zero-valued with `summary:!0`, `mode:"compaction"`, then filled by the generation call) and run it against the pre-review revision of `_measure`. If that fixture does **not** reproduce the reviewer's `975K / COMPACT` — i.e. if the divergence required auxiliary session rows the source shape did not expose — then a source-derived conformance test could not have made the cost visible before payment, and the claim is false. (A second, broader falsifier: if the majority of the review's cost had come from finding #4-class policy disagreement rather than runtime conformance, instrumentation would not have paid for itself at all.)
