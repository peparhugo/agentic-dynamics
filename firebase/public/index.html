Core Finding

Both implement. Only one pays to explain.

Claude's imitation training explicitly narrates every recovery step — recovery cost 30–50% above baseline. At $10/Mtok vs $0.022/Mtok, explanation is catastrophically expensive.

DeepSeek — Silent Implementation

GRPO-trained policy. Reasoning compressed into latent space. Produces 386 chars of reasoning text — 4× less than Claude. Implements all 7 constraints in code without narrating them. Recovery cost: 0.9× multiplier — perturbation reduces cost. Cost per character: $0.0001.

Claude — Explicit Recovery

Imitation + RLHF policy. Explicit chain-of-thought. Produces 1,639 chars of reasoning text — 4× more than DeepSeek. Verbalizes every constraint and recovery step. Recovery cost: 1.1× multiplier — perturbation increases cost. Cost per character: $0.0007 — 7× more than DeepSeek.

The mechanism: communication strategy × pricing model. Training regime determines whether recovery is narrated (Claude) or silent (DeepSeek). Pricing model determines whether narration costs a rounding error ($0.022/Mtok) or a 30-50% premium ($10/Mtok). Same engineering outcome, two orders of magnitude apart in price.

Reasoning Text Analysis — Not a Proxy, a Direct Measurement

We measured the raw text output of each standardized build session from the opencode database (not heuristics, not proxies). DeepSeek: 386 chars. Claude: 1,639 chars. GPT-5.6: 1,167 chars. GPT-5-nano: 4,797 chars. The pattern is clear — model size and training regime directly predict verbosity. Smaller models (GPT-5-nano) compensate with more words. RL-trained models (DeepSeek) compress reasoning into latent space. Imitation-trained models (Claude) verbalize everything. Cost per character: DeepSeek $0.0001 vs Claude $0.0007 — a 7× gap purely from communication strategy.

Methodology

How the instrument works.

StepWhat happensMeasured
1Perturbation applied to task (10 operators, 2 classes)Operator, class, strength
2Opencode agentic session in isolated git worktreeFiles, tool trace, git diff
3Model builds: writes code, runs pytest, iteratesTool calls, retries, test pass/fail, depth
4Code files scanned for constraint implementation7/7 constraints verified in generated .py files
5Cost from dashboard-verified per-token pricing$/Mtok × observed tokens = session cost
6Recovery cost = perturbed cost − baseline costPerturbation cost multiplier, recovery $

Output-based semantic validation — no embeddings.

We replace embedding analysis with three orthogonal output-based methods: (1) pragmatic marker analysis — counting explanatory/surface/constraint keywords in reasoning text; (2) AST edit distance — comparing code structure changes (logic additions vs surface renames); (3) tool-call latency — measuring exploration (reads/greps) before writing. All methods work on any model's text output. No model internals required. No incompatible vector spaces.

Research Context

Where this fits in the literature.

Liu et al. (2026, arXiv:2605.11733) — "LLM Inference Should Be Evaluated as Energy-to-Token Production." Position paper calling for Joules/token as a first-class metric. Our instrument implements their framework: measuring agentic build cost in dollar and token terms, with energy estimates bounded by disclosed architecture (MoE vs dense) and known hardware (H100 vs H800 TDP).

TokenPowerBench (Niu et al., AAAI 2026) — Empirical J/token measurements across hardware configurations (0.1–2 J/tok). We use their conservative lower bound (0.1 J/tok) for energy estimates. Their finding that MoE architectures show 5–20× lower J/token than dense models directly supports our architectural energy gap analysis.

Zhu & Zhu (2026, arXiv:2603.28949) — "The Planetary Cost of AI Acceleration: A Thermodynamic Outlook." Frames AI scaling as a thermodynamic problem bound by Earth's finite heat capacity. Our finding — that Claude's per-token pricing (455–2,273× DeepSeek) dwarfs any plausible hardware efficiency difference — supports their thesis that the ultimate bottleneck is economic, not physical.

CARL (ACL 2026) — Constraint-Aware RL framework. Rewards constraint focus. Our instrument extends this from training-time to inference-time measurement: how much does it cost to recover a missing constraint at deployment?

TRACED (2026) — Geometric kinematics of reasoning traces. Measures Progress and Stability from hidden states. Our tool-call latency method provides a behavioral proxy for the same concept without requiring model internals.

AST Analysis: Perturbation Does Not Change Code Output

Comparing perturbed (remove_critical_constraint) vs baseline worktrees at the AST level: DeepSeek produces 112.6% of baseline AST nodes — code output is structurally identical. The perturbation's effect is on reasoning strategy, not implementation correctness. Constraint markers spike from 0 → 43.7 under perturbation — even silent models generate more constraint-aware text when forced.

Worktree Inventory — 139 Code Artifacts Across Models

Full pytest execution on all on-disk worktrees: Claude (26 worktrees, 178p/1f), OpenAI (45 worktrees, 209p/1f), DeepSeek (68 worktrees, 298p/168f). DeepSeek's failures are architectural choices (FastAPI instead of Flask, missing async deps) rather than logic errors — tests fail at collection because of import mismatches, not assertion failures. This is the Silent Implementation Principle: DeepSeek implements correctly (all constraints in code) but differently from what the test harness expects.

Honest constraints

Reasoning-time constraint detection requires logit lens or activation patching — unattainable via API. We measure constraint detection through code-file scanning, pragmatic marker analysis, and AST comparison across worktrees. Cross-model embedding analysis is replaced by output-based semantic validation (markers + AST + tool-call latency) because provider embedding spaces are incompatible. These are acknowledged limitations, not hidden gaps.
