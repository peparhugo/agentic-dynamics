How — the instrument

Multi-session builds under controlled degradation.

Most benchmarks ask: can the model solve a clean task? This instrument asks: can it build and maintain a real system across five consecutive sessions — and what does that cost? Each experiment is a story: a greenfield build that progresses through feature work, integration, refactoring, and cross-cutting concerns, with git commits between every session.

Five-session story arc

  • Session 1: greenfield build from spec
  • Session 2: feature addition
  • Session 3: integration (auth, async, persistence)
  • Session 4: refactor (repository pattern, layering)
  • Session 5: cross-cutting (rate limiting, pagination)

Perturbation conditions

  • Clean — unmodified specifications
  • Bad seed — the starting codebase is pre-degraded
  • Early degrade — the first spec is corrupted, cascading through later sessions

Full quality stack

  • AST diffs and convention scoring per commit
  • SonarQube static analysis
  • A second model reviews every commit
  • Test count, edge cases, and test/code ratio measured

221 stories across 3 codebases (CRUD API, static site generator, notification service) and 2 tiers, run against 7 models. Every token, dollar, cache hit, and test is measured and provenance-tagged. The instrument doesn't judge code quality — it measures how cost, verification, and recovery respond to degraded input.

What — the evidence

Four findings from 1,097 instrumented story sessions.

Finding 1

Verification is a vendor behavior, not a price point.

OpenAI spans a 41× price range — Luna at $0.09 and Sol at $3.75 — and both write ~10 tests per story. Claude spans 2.9× — Haiku at $1.59 and Sonnet 5 at $4.58 — and both write ~120. All pass their tests. The 10× verification gap sits between vendors, not between price tiers. You don't buy verification by paying for a pricier sibling model; you buy it by switching vendors.

Finding 2

Cost compounds across the five-session arc.

The Snowball Rule, measured: a story's cost roughly doubles from its greenfield session ($0.16) to its cross-cutting session ($0.34), while tokens grow from 18.7K to 34.9K. Every session grows the codebase, and every new line inflates the cost of the next. Per-session cost understates maintenance work by ~2×.

Finding 3

Cache behavior is a hidden cost lever, not a capability signal.

The cheapest model (Flash) and the most expensive (Sol) both send ~47K tokens per session — Flash at $0.07, Sol at $3.75. Luna hits a 98% cache-hit rate and sends just 6.3K. Token volume, cache policy, and test thoroughness are three independent knobs — none predicts the other two.

Finding 4

Degradation leaks — but models recover.

Corrupting the session-1 spec (early_degrade) drops success to 85% and doubles the cascade rate; a pre-degraded seed (bad_seed) costs the most ($1.48/story) but succeeds 88%. Degradation raises cost and cascades slightly; it does not dominate the outcome.

What — the concept

Correctness is not verification.

A model can pass every test it writes and still leave a system unverified. The gap is measured by test thoroughness:

Tests per story: Luna 7 · Terra 9 · Sol 13 · Flash 34 · Pro 34 · Haiku 117 · Sonnet 122

All seven models pass their own tests at roughly equal rates. But the tests themselves differ by an order of magnitude. Luna ships ~7 tests that confirm the happy path. Sonnet 5 ships ~122 that probe edge cases — duplicate usernames, whitespace titles, missing bearer tokens, idempotent notifications. Both codebases "work." Only one is actually verified.

This is the durable-value gap. Correctness is whether the code passes the tests you have. Verification is whether you have the tests that would catch the failures that matter. An agent can produce working code while silently skimping on the safety net — and that trade-off is a vendor behavior, not something the price tag buys.

What — this means

If you can measure it, you can route on it.

Once cost, verification depth, and cache efficiency are measured together, model routing stops being about vendor price sheets and starts being about earned outcomes. Route cheap models to code that won't be looked at twice. Route expensive models where a missed edge case is expensive failure. The contribution is the verification dimension — nobody else is measuring how much safety net each dollar buys.
