DeepSeek — Silent Inference

GRPO-trained policy. Reasoning compressed into latent space during training. Produces 386 chars of reasoning text — 4× less than Claude. Implements all 7 constraints in code without narrating them. Recovery cost: 0.9× multiplier — perturbation reduces cost. Cost per character: $0.0001.

Claude — Explicit Inference

Imitation + RLHF policy. Explicit chain-of-thought. Produces 1,639 chars of reasoning text — 4× more than DeepSeek. Verbalizes every constraint and recovery step. Recovery cost: 1.1× multiplier — perturbation increases cost. Cost per character: $0.0007 — 7× more than DeepSeek.

Formal Definition — The Silent Inference Principle

A model exhibits Silent Inference when it correctly implements all required constraints in its output artifact (code, plan, action) without generating explicit narration, explanation, or reasoning trace about those constraints. The observer cannot tell from the reasoning text whether a constraint was present — because the model does not narrate it. The principle has three measurable dimensions: (1) Detection — does the model know the constraint is missing? (latent, measured via code scanning); (2) Implementation — does the final artifact handle the constraint? (measured via test pass rate); (3) Narration — does the model say it handled the constraint? (measured via reasoning text analysis). Silent Inference is observed when Implementation=True and Narration=False. The Explanation Tax is the cost delta from Narration=True — paid by explicit inference models, evaded by silent inference models.

Energy Price Multiplier

Token cost is a function of energy price.

The final variable in AI inference economics: token costs are not fixed — they are a function of electricity prices, and electricity prices are a function of AI-driven demand. This creates a feedback loop: AI consumes energy → energy prices rise → token costs rise → economics shift. The Complete Equation — AI FinOps Cost Model

All terms measured from experiment data or sourced from published energy projections.

C₀           = baseline session cost at 2024 energy prices (measured)
EPM(t)       = Energy Price Multiplier at time t
β            = tokens per line of code ≈ 0.001 (context inflation)
v            = velocity (lines per session)
N            = number of sessions
P            = test pass rate (correctness)
K            = desired successful outcomes
A            = architectural multiplier (active params ratio)
ϵ            = explanation tax (natural/forced cost ratio − 1)

Per-session cost:
  c(t) = C₀ × EPM(t) × (1 + β·v·t)

Cumulative cost after N sessions:
  C(N,v) = C₀ × EPM(N) × [N + β·v·N(N−1)/2]

Cost per successful outcome:
  CostPerOutcome(K,v) = C(K/P, v) / K

Decomposing the total cost gap between models:
  Gap = (A × Verbosity × (1+ϵ)) × EPM(N)
  A = Claude active params / DS active params ≈ 13.5×
  Verbosity = Claude code tokens / DS code tokens ≈ 3.5×
  ϵ = DS 24.4%, Claude 52.5%, GPT-5.6 50.1%, GPT-5-mini 119.6%

Honest Constraints

Reasoning-time constraint detection requires logit lens or activation patching — unattainable via API. We measure constraint detection through code-file scanning, pragmatic marker analysis, and AST comparison across worktrees. Cross-model embedding analysis is replaced by output-based semantic validation. These are acknowledged limitations, not hidden gaps.

Methodology

How the instrument works.

StepWhat happensMeasured
1Perturbation applied to task (10 operators, 2 classes)Operator, class, strength
2Opencode agentic session in isolated git worktreeFiles, tool trace, git diff
3Model builds: writes code, runs pytest, iteratesTool calls, retries, test pass/fail, depth
4Code files scanned for constraint implementation7/7 constraints verified in generated .py files
5Cost from dashboard-verified per-token pricing$/Mtok × observed tokens = session cost
6Recovery cost = perturbed cost − baseline costPerturbation cost multiplier, recovery $

Output-based semantic validation — no embeddings.

Three orthogonal output-based methods: (1) pragmatic marker analysis — counting explanatory/surface/constraint keywords in reasoning text; (2) AST edit distance — comparing code structure changes; (3) tool-call latency — measuring exploration before writing. All methods work on any model's text output. No model internals required.
