Cache Strategy

Three-layer caching turns the provider economics in your favor. Each layer compounds on the one below.

Layer 1 · Gateway Exact-Match

Return cached responses for identical prompts within TTL. Zero token cost.

80–95% savings on repeated prompts

Layer 2 · Provider Prefix Cache

Structure prompts so repeated prefixes hit the provider-side disk cache (DeepSeek, Anthropic).

50–90% savings on input tokens

Layer 3 · Semantic Cache

Match semantically similar prompts with a threshold (embedding cosine similarity ≥ 0.97).

20–60% savings on similar-but-not-identical prompts

Critical rule: Static content before dynamic content — one dynamic field in the wrong position invalidates the prefix cache. Place system prompts, tool definitions, and static instructions first. Append user input last.

Cache Strategy: Two-Way Door

Cache writes preserve context but cost $15/Mtok (Anthropic). Cache reads retrieve context at $0.14/Mtok (DeepSeek). Measure your cache hit rate. If under 50%, switch to cache-read mode. If over 80%, cache-write pays for itself. This is a two-way door — toggle it per workstream.

Model Routing

Cascade routing: classify complexity at the edge, route to the cheapest capable model, escalate only on failure.

request → complexity-classifier → cheapest-capable-model → confidence-check → escalate-on-failure

60–80% of requests are simple (classification, formatting, lookup). These should never touch a frontier model.

Tier 1 · Simple

DeepSeek V3 / GPT-4o-mini / Claude Haiku
Classification, extraction, formatting, lookup

~60% of volume

Tier 2 · Moderate

DeepSeek R1 / GPT-4o / Claude Sonnet
Code generation, structured reasoning, analysis

~25% of volume

Tier 3 · Complex

GPT-5.6 / Claude Opus
Multi-step architecture, novel problem solving

~15% of volume

Budget Enforcement

Hard caps prevent runaway costs. These tools enforce limits at the gateway layer.

tokencap

Token-based rate limiting per key, per model, per time window.

tokencap --key sk-xxx \
  --limit 1M --window 1h \
  --model gpt-5.6

token-limiter

Enforce max tokens per request. Reject before the provider sees it.

token-limiter --model gpt-5.6 \
  --max-input 128000 \
  --max-output 16384

agentbudget

Per-agent cost ceilings with automatic escalation to human review.

agentbudget --agent coding-agent \
  --daily-cap $5.00 \
  --on-exceed escalate
