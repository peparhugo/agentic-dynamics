▶ TL;DR — What the evidence shows

Grit = Ground-Truth Integrity. How well does a model maintain correctness when given degraded input? Every LLM defaults to being a chatbot. When we give it degraded instructions — wrong specs, missing requirements, contradictory constraints — some maintain integrity. Most don't. We tested across 227 experiments with 10 stress tests. The Grit Spectrum

Grit = Ground-Truth Integrity. How well does a model maintain correctness when given degraded input? We tested 10 perturbation operators across all models — 4 manifold operators that push the model off its typical linguistic surface, and 6 semantic operators that inject contradictions within the reasoning manifold. Grit is measured by escape rate (how often the model diverges from its default solution) at a given correctness threshold.

Manifold Operators (4)
Push the model off its typical linguistic surface — alien vocabulary injection, framing shifts, causality reversal, forced abandonment. Test search dynamics.
Semantic Operators (6)
Inject contradictions within the reasoning manifold — false premises, inverted constraints, phantom successes, competing goals, removed critical constraints, contradiction insertion. Test truth-seeking policies.
Detector: Recovery Signals (7)
Markers, tool convergence, qualifier patterns, tech stack convergence, output length ratio, reasoning structure overlap. Classify every segment as EXPLORATION or RECOVERY.
Detector: Strategy Archetypes (4)
CONSERVATIVE (low explore, high recover), EXPLORATORY (high escape, low recover), WASTEFUL (high explore, low quality), EFFICIENT (high explore, high quality, low cost).

Our experiments support what Databricks found: On August 7, 2026, Databricks published their playbook for reducing AI coding costs at scale (Wendell et al., Aug 2026). Their four cost levers — shifting to efficient models, dynamic routing, progressive budgeting, and reducing token overhead — map directly to rules in this framework. They call the core concept the "Efficiency Frontier": the set of models with the best price point for a given level of intelligence. We call it Grit. They surveyed companies. We stress-tested models with 10 perturbation operators across 227 experiments.

Grit: The Flail Rate

When the model can't figure out the correct requirement, it flails — producing tokens but zero code. This is the flail rate. Measured per-worktree: what fraction of a model's sessions produced tokens that went to narration instead of code? A session is penalized when output tokens exceed code lines by >20x or when zero code files were produced. Measured Narration Penalty: Claude flails on 11% of sessions (code-free narration) — 36% more often than DeepSeek's 8.4%. When models succeed, DeepSeek carries a negligible narration overhead (0.0% penalty), Claude carries 8.5%.

Key insight: The Explanation Tax isn't theoretical — it's measurable. Claude burns 11% of its sessions on narration with insufficient code output ($1.01/session avg). Nano hits 14% penalty rate. Flail sessions fall into two patterns: models that overthink without acting (producing thousands of reasoning characters but no code), and models that give up immediately (under 5 steps, never write a file). Both are detectable in real-time via tool-call monitoring.

Same Output, Different Cost

Both DeepSeek and Claude generate ~11,000 output+reasoning tokens per session. DeepSeek produces 74 LOC per 1K tokens. Claude produces 55 LOC per 1K tokens. That's 39% more code per token — at 69× less cost. The gap is not about which model is smarter. It's about which tokens you're billed for.

Current Scope & What's Next

This is v0.4 – the first open framework for AI FinOps. Here's what's validated today and what's on the roadmap.

Covered Today
Python/Flask REST APIs, SQLite-backed CRUD apps, JWT auth flows, rate-limited endpoints, paginated responses, audit-logged systems, API versioning, pytest suites, real-time collaboration frontends. TypeScript/Node.js (initial: 3 variants, 21 cross-model runs). 10 prompt-level perturbation operators (4 manifold, 6 semantic). IEA-baseline EPM projection (1.6%/yr). Cost measurement: tokens, dollars, joules.
Planned (v0.4+)
Rust, Go validation. Structural perturbation operators (broken dependencies, AST corruption, production incident simulation). EPM sensitivity analysis (aggressive/optimistic/volatile scenarios). Human maintenance cost modeling. Pull requests welcome – the framework was designed for extensibility from day one.
Not in Scope
The framework does not judge whether narration is wasteful or valuable. It measures the cost. If your team needs auditable reasoning trails for compliance or debugging, the Explanation Tax is insurance – not overhead. The instrument is model-agnostic. DeepSeek was chosen as the anchor case study, not an endorsement.
Test Pass Rate Caveat
Sampled pytest results are environment-sensitive. Approximately 31% of failures resolve with correct dependency installation. The raw pass rate counts everything; the "with correct env" column estimates real code quality. DeepSeek's 69% corrected rate is comparable to Claude and GPT-5.6.
Energy Projection Caveat
The EPM uses a linear IEA-based projection. Real-world energy prices may diverge significantly. v0.4 will add sensitivity analysis with aggressive (2.5%/yr), baseline (1.6%/yr), and optimistic (0.8%/yr) scenarios.
Reproduce This
The instrument is open source. 34 configs, 10 operators, 6 recovery signals. Clone the repo, install the instrument, run a config. View on GitHub. See the methodology.
