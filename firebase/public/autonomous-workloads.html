Autonomous Workloads

When AI works without human supervision — the rules, economics, and operational model

Rules 6–10 for Autonomous Workloads

Rule 6 · The Autonomy Threshold

Define the confidence level at which a model's output proceeds without human review. A model that passes validation 99% of the time can run autonomously. A model at 85% requires human-in-the-loop.

Example: A PR reviewer agent passes 97.3% of validations. Set the autonomy threshold at 95% — it auto-approves 97.3% of PRs and escalates 2.7% to a senior engineer.

Rule 7 · The Escalation Cascade

Don't escalate straight to human. Try a smarter model first. If Flash fails, try Sonnet. If Sonnet fails, try Opus. Only after Opus fails, flag a human. Each tier costs exponentially more — but the vast majority of tasks stop at Tier 1 or 2.

Rule 8 · The Batch SLA Horizon

Batch workloads don't need real-time SLAs. Define completion windows in hours, not seconds. A 72-hour batch window gives you enormous scheduling flexibility — you can fill idle capacity, retry failures, and optimize for cost.

Rule 9 · The WOC Ratio Floor

Work Overhead Cost (WOC) = cost of validation + retries + escalations divided by cost of the primary run. When WOC > 1.0, you're spending more on overhead than on actual work. Autonomy makes sense when WOC < 0.70.

Rule 10 · Workstream Capacity Budgeting

Each autonomous workstream gets a budget envelope: daily spend cap, model tier ceiling, and retry budget. Exceeding any one triggers a human review checkpoint. Budgets compound — 10 workstreams at $5/day = $1,825/yr baseline.

WOC Ratio

The Work Overhead Cost ratio tells you whether autonomy is actually saving money.

WOC = (costvalidation + costretries + costescalations) / costprimary

Healthy

WOC < 0.70

Overhead is manageable. Scaling is safe.

Investigate

WOC < 0.85

Retry or escalation rate rising. Tune thresholds.

Critical

WOC ≥ 0.85

Overhead dominates. Pause autonomy until root cause found.

Measured average: WOC = 0.79 across 248 experiment sessions. This is in the "investigate" range — autonomy is viable but requires active monitoring. The 65× cost gap between Claude and DeepSeek is the dominant factor.

72-Hour Horizon · Batch SLA Management

Batch workloads don't need sub-second response times. A 72-hour window unlocks massive cost savings through scheduling optimization.

Queue Depth

Number of jobs waiting. If queue_depth > 2 × daily throughput, you need more capacity or a longer window.

Slack Buffer

Reserve 20% of the window for retries. At 21.4% retry rate, a 72h window needs ~14.4h of slack.

Completion Time Formula

Tcomplete = Njobs / Rthroughput + Tslack

Guarantees delivery within the SLA window.
