Executive Summary

We discovered a 473× cost gap between models that produce identical constraint-complete Python code. The gap is structural — not situational. DeepSeek v4 Pro uses GRPO-based latent reasoning (Silent Inference); Claude Fable 5 uses SFT imitation chain-of-thought (billed as output tokens). The framework measures the cost. You decide which model fits your context.

Your AI bill is a black box. This framework opens it.

The Five Rules

Rule 1 — The Silent Inference Rule

Default to the cheapest model that passes your test suite. Defaulting to silent models preserves budget runway for tasks that actually need explicit reasoning — database migrations, core architecture, security audits. Two-way door.

Rule 2 — The Explanation Tax Rule

Narration has a measurable cost (24–120%). Whether it's worth paying depends on your verification architecture. If automated tests validate output, route to silent models. If you need auditable reasoning, the tax is insurance.

Rule 3 — The N² Tax Rule

Model cumulative cost before architectural commitments. Context inflation compounds quadratically: C(N,v) = C₀ × EPM(N) × [N + β·v·N(N−1)/2]. A 10% β error produces a 50% overrun after 100 sessions. One-way door.

Rule 4 — The EPM Horizon Rule

Energy costs are the inflation rate of AI compute. Local energy markets determine long-term prices. Find the year your geographic energy costs flip your model selection. EPM(t) = 1.00 + r(t−2024). Hedge before that point.

Rule 5 — The Cost-Per-Pass Rule

Price the outcome, not the prompt. A model at half the cost but half the pass rate costs the same per outcome — with double the latency and retry overhead. CostPerOutcome(K,v) = C(K/P, v) / K.

Decision Framework

Two-Way Doors (C₀ changes): Switch models per task type, toggle silent mode, adjust caching. Reversible. Preserves runway. Experiment freely.

One-Way Doors (β, v, EPM changes): Architecture selection, multi-year contracts, proprietary frameworks. These compound through N². Model cumulative cost over 36 months before committing.

Methodology

The instrument runs 10 calibrated perturbation operators (5 manifold, 5 semantic) across 22 YAML configs. Six recovery detection signals classify model behavior. Four strategy archetypes (Conservative, Exploratory, Wasteful, Efficient) characterize response patterns. Every session recorded in the opencode database.

Research Roadmap (v0.2+)

Pillar 1: Multi-language AST expansion — TypeScript, Go, Rust, Java. Pillar 2: Task archetypes — bug-fixing, refactoring, security. Pillar 3: Model diversity — Gemini, Llama, Mistral. Pillar 4: Structural perturbations — dependency injection, AST corruption. Pillar 5: Maintenance tax — human-in-the-loop studies.

Current Scope & Limitations

Validated on Python/Flask REST APIs, CRUD apps, and real-time collaboration frontends. Not yet validated on TypeScript, Rust, Go, or non-code tasks. EPM uses IEA baseline (1.6%/yr). The framework measures inference cost only — it does not model human maintenance or debugging time. v0.1. Open for contributions.
