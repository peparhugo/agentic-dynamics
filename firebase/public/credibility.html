What's Strong

Transparent methodology

Every operator, every signal, every equation is documented in the open. The source code is the specification. No black-box rankings, no proprietary scoring.

Multi-model

8 variants across 3 architectures (DeepSeek V3/R1, GPT-4o/GPT-5.6, Claude 3.5/4 Sonnet/Opus). Comparisons are calibrated, not cherry-picked.

Replicable

Everything is open source (MIT). Clone the repo, install the package, run your own experiments. Every number in this framework can be independently verified.

What We're Honest About

Sample size limitations

248 sessions is statistically meaningful but not exhaustive. Confidence intervals widen for per-model-per-task breakdowns. We report aggregate numbers where data density supports them.

Single-domain bias

All experiments use coding tasks (Python/Flask REST APIs, CRUD apps, real-time collaboration frontends). Results may not generalize directly to creative writing, legal analysis, or medical reasoning domains.

Static snapshot risk

Model behavior, pricing, and rate limits change. This framework captures a moment in time (Q2–Q3 2025). Provider-side changes (new models, pricing updates, caching improvements) can shift conclusions.

Self-validation risk

We wrote the instrumentation software and we ran the experiments. While the code is open and results are reproducible, independent replication by an unaffiliated team would strengthen confidence.

Rules 6–11 Calibration Status

Transparency on which rules are empirically grounded and which extend conceptually.

Rules 1–5 (Silent Inference, Explanation Tax, Snowball, EPM Horizon, Cost-Per-Pass) are fully calibrated against the 248-experiment dataset. All five have measured numeric constants from the instrument pipeline.

Rules 6–11 (Autonomy Threshold, Escalation Cascade, Batch SLA Horizon, WOC Ratio Floor, Workstream Capacity Budgeting, Provider Selection) extend the framework conceptually from industry best practices. They have been calibrated using the 248-experiment dataset where possible — r, Eₘ, and WOC are measured. Full validation against autonomous workload scenarios is in the roadmap.

Call to Reproduce

Science depends on replication. Here's how to verify the numbers yourself.

git clone https://github.com/peparhugo/ai-finops-framework.git
cd ai-finops-framework
pip install -e .

# Run a single experiment
python scripts/run.py --config experiments/configs/task_manager.yaml

# Run a full silent-mode sweep
python scripts/sweep_silent_mode.py

# Inspect the inventory
python scripts/inventory.py list
python scripts/inventory.py stats
python scripts/inventory.py report

# Validate a worktree
python scripts/validate_session.py /tmp/exp_xyz

Challenge: Run the same experiment configs on your own models, your own hardware, your own tasks. If you find different numbers, open an issue with your data. The framework gets stronger with every independent replication — including ones that disagree.
