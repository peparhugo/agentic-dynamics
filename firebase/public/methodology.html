The Measurement Instrument

A calibrated apparatus that perturbs the agent's task and environment, measures how it recovers, adapts, flails, and compounds cost, and turns those behaviors into numbers a business can act on. This page describes the instrument; the Evidence page reports what it measured.

Perturbation Operators

Change is the lever, because behavior under change is the object of study. Ten operators act on a coding-task prompt at controlled strength ∈ [0,1], each seeded and deterministic for a given cell. They fall into three classes, each targeting a different failure mode:

Specification corruption ×4
Degrade the information, keep the ground truth
inject_false_premise — a plausible but incorrect assumption · insert_contradiction — two mutually exclusive requirements · remove_critical_constraint — silently drop a defining requirement · inject_phantom_success — assert an intermediate step already passed. Tests whether the agent detects that the problem changed.
Objective mutation ×2
Change the requested target
invert_constraint — flip a requirement to its opposite · inject_competing_goal — add a conflicting objective. Tests whether the agent complies blindly or recognizes the absurdity.
Process perturbation ×4
Shift the search process, not the substance
inject_alien_vocab — unfamiliar terminology · shift_framing — reframe build-X as disprove-X · reverse_causality — present solution before problem · force_abandonment — generate and discard. Tests whether the agent recognizes the same problem wearing different words.
Why the split is load-bearing: specification corruption and objective mutation change content (error detection); process perturbation changes surface (recognition under re-framing). They expose different failure modes and separate models in sharply different ways.

Four Signal Families

No single scalar "quality" is admitted. Four families are computed post-hoc by static and test analysis of the produced code, each mapped to the business outcome it feeds.

Correctness
The generated test suite is executed by an independent runner (pytest / vitest / go test / cargo test / tsc) and constraints met are counted. test_executed_success is the source of truth — not the model's self-report. [M]
Basin escape
Structural divergence (AST architecture + structure, not text similarity) of the perturbed solution from the baseline. escape ∈ [0,1]; high means the agent left its default solution topology. [H]
Efficiency
Tokens (input/output/reasoning/cache read/write), dollars (per-model pricing), and joules (per-token energy estimates), plus derived ratios. The answer/explanation token split decomposes reasoning cost. [M]
Strategy classification
Each cell is labeled CONSERVATIVE, EXPLORATORY, EFFICIENT, or WASTEFUL from exploration-to-recovery token ratios weighted by escape and quality. [H]

The Instrumented Ledger

Measurement rules read an append-only ledger of attempts. Four fields that were previously absent — and that gated the policy arms that depend on them — are now measured, not missing:

FieldMeaningConsumed byProvenance
confidencePer-attempt confidence signal emitted by the agent runmodel_cascade / dynamics arms[H]
perturbation_strengthControlled magnitude s ∈ [0,1] of the applied operatorgrit (the strength axis)[M]
test_executed_successIndependent pass/fail from the test runnergrit (verified success)[M]
answer / explanationOutput-token split: tokens that become the deliverable vs tokens that only narrateoutput-decomposition (reasoning cost)[M]

Alongside these sit the attempt/timestamp fields (queued, leased, started, first-token, ended) and the full token/cost accounting. Together they give a control rule everything it needs to read an outcome — and nothing it must assume.

The Measure-Before-Policy Gate

The load-bearing rule, enforced by a compiler rather than by author discipline: a control policy may consume only information that a measurement rule has already produced.

A measurement rule reads raw ledger events and produces information (first_pass_quality, grit, recovery_premium). A control rule consumes information and emits a decision (route, retry, escalate, budget). The compiler resolves the dependency graph and refuses any control rule whose requires are unmet:

ERROR: policy arm "dynamics" requires [confidence, first_pass, deadline_slack]
       — not produced by the ledger or any rule in this spec. Instrument these first.

The refusal is the architecture doing its job: it computes the next measurement target. Before the four fields above were instrumented, the grit and model_cascade arms were correctly refused. Now that the fields are measured, those arms are admissible — and the compiler's error list is the research program.

The Queue Pipeline

The corpus is produced by a Redis queue drained by parallel workers, with analysis and review auto-triggered per worktree:

1
Enqueue
scripts/enqueue.py fills the queue (story × tier × quality × condition × model), skipping already-completed cells.
2
Execute
scripts/worker.py (BRPOP) drains the queue, running each cell as a five-session story with git commits between sessions.
3
Analyze
AST + SonarQube static analysis and solution evaluation per worktree, auto-triggered after execution.
4
Review
DeepSeek flash reviews each commit and story for architectural fit, conventions, and failure modes.
5
Regenerate
Aggregated results feed data.js; the site is rebuilt from provenance-tagged measurements.
Provider-agnostic by design: every regime goes through the same backend seam. anthropic/* models run through the Claude CLI (subscription-safe); other providers run through opencode. Both emit the same event schema, so downstream analysis is identical regardless of provider.

The CLI Tools

The instrument runs in two regimes over the same backend, observed through a live control plane.

Single-session
Perturbation experiments
scripts/run.py <task>.yaml. One task, one (perturbed) prompt, one isolated worktree. Produces a game report and feeds _results_summary.json — the 144-cell single-task corpus.
Multi-session
Story pipeline
scripts/enqueue.py fills the queue; scripts/worker.py drains it — each cell a five-session story: greenfield → feature → integration → refactor → cross-cutting.
Orchestration
YAML pipeline
scripts/pipeline.py --plan <ci|deploy|full_matrix|feature|ship_features>. Phase DAGs (lint → test → build; matrix → analyze → review → deploy).
Control plane
Live telemetry
admin/server.py serves the Control Room: live experiment matrix, per-cell event streams, supervisor flags — observe-only, reading the same Redis state the workers write.

Measurement Provenance

Every metric carries a provenance tag, making clear what was measured, what was computed, and what is estimated — and avoiding the overclaim that "every term is measured."

[M]
Measured
API tokens & costs, test results, LOC, cache tokens, session duration, confidence, perturbation_strength — directly from the openCode DB or filesystem.
[C]
Computed
Thinking ratio, cost ratios, snowball factor, first-pass quality — derived directly from measured values with no estimation.
[H]
Heuristic
Escape scores, code quality, strategy classification — algorithmic analysis with author-chosen thresholds.
[X]
External
Energy estimates from TokenPowerBench (Niu et al., AAAI 2026); EPM projections from IEA World Energy Outlook 2024. β and EPM are external, not measured.
[P]
Policy / prior
The field definition, the requires/produces gate, and design thresholds — not experimental results.

Reproduce This

The instrument is open source. Every experiment is a YAML config. Every run is seeded for reproducibility.

1. Clone & Install
git clone https://github.com/peparhugo/agentic-dynamics
cd agentic-dynamics
pip install -e .
2. Run a Config
python scripts/run.py experiments/configs/task_manager.yaml --model deepseek/deepseek-v4-pro
Choose from 35 configs in experiments/configs/.
3. Run a Story
python scripts/run_story.py task_manager_api --model anthropic/claude-sonnet-5 --backend claude_cli
Five-session stories; scale with scripts/enqueue.py + scripts/worker.py.
4. Watch It Live
python admin/server.py
Control Room: matrix, event streams, supervisor flags. Or scripts/monitor.py for a terminal dashboard.

Limitations

The corpus is statistically meaningful but not exhaustive — confidence intervals widen for per-model-per-task breakdowns. Validated on Python/Flask REST APIs and TypeScript/Node.js; not yet on Go, Rust, Java, or non-code tasks. Provider pricing and model behavior change — this is a Q3 2026 snapshot. The instrument is open source; independent replication is welcome. EPM projections use IEA baseline (1.6%/yr); real energy markets may diverge. Energy estimates are modeled scenarios; dollar costs and token counts are the measured quantities. The single-task and story corpora are distinct experiment families and are reported separately, never summed into a false total.
